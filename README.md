MarkPilot 是一款 AI 原生的 Markdown 编辑器：你在写上一句的时候，它已经在替你想下一句；你排版的一撇一捺之间，藏着一套正经的中文排版引擎。同一套编辑内核，两种工作形态——既能作为 Windows 桌面应用开箱即用，也能作为插件装进 VS Code、Trae 等 AI IDE。

![MarkPilot：中西文混排与公式编辑](https://raw.githubusercontent.com/ltmroberthk915/markpilot/main/docs/screenshots/hero-light-serif.png)

*窄窗口、密集换行、中西文混排与实时公式——宋体-朙主题，中西文之间自动留白。*

## 和 Typora 比，快多少？（实测）

同一台电脑、同一个窗口大小、同一份「中文 + 公式」素材，两边都按最大化窗口打开；每一项都跑多次取中位值，并且用**两套互相独立的测法**交叉验证过，结论一致。

| 场景 | 实测 |
| --- | --- |
| 打开小文档（1.7 KB） | MarkPilot **快约 0.2 秒**（0.51 秒 vs 0.71 秒） |
| 打开中文档（67 KB） | MarkPilot **快约 0.14 秒**（0.61 秒 vs 0.75 秒） |
| 打开大文档（240 KB） | 几乎一样快（0.91 秒 vs 0.90 秒） |
| 双击文件后窗口弹出来的速度 | MarkPilot **更快**（0.29 秒 vs 0.33 秒） |
| 在大文档末尾点开一个公式、直接进源码编辑 | MarkPilot **快 6.5 倍**（0.024 秒 vs 0.156 秒） |

对照对象是同期最新版 Typora（1.14.10），MarkPilot 用的 Windows 桌面版 2.0.18。数字是 2026-09-10 在这台机器上的实测：换机器、换文档绝对值都会变，"打开文档不落后、点公式编辑快一个量级"这个结论在同一台机器上是稳定的。

## 六个 Typora 给不了的重磅能力

### ✦ AI 行内补全

真正的行内续写：它知道你正在写哪个章节、前后文是什么、是不是在公式环境里，光标后面直接浮现灰色预览，Tab 采纳。双引擎设计——大模型续写（DeepSeek / 智谱 GLM，填自己的 Key 即用）加本地规则补全（公式、模板、路径），断网或没配 Key 也照样补。你的 API Key 只存在本机加密存储，不上传、不打进安装包。

### ✦ 数学公式的精准映射

编辑体验沿用 Typora 的路子：平时看到的是渲染好的公式，光标走近就亮出局部源码，即改即预览。MarkPilot 在这层交互之上，把渲染结果与源码挂了钩——**点击公式上的任意符号，光标就精准落在生成它的那段源码处**；反过来，源码里动一个字符，对应元素立刻刷新。公式嵌在表格单元格里、或层层嵌套，这层映射都不丢；原地点开编辑、精确撤销重做。写数学文档时，公式不再是"渲染完就碰不得的图片"，而是可编辑、可回退的活内容。

### ✦ 插件化：编辑器进驻 AI IDE

整个编辑内核打包成标准扩展：在 VS Code 或 Trae 里装上（现在**直接在扩展商店搜 MarkPilot 即可**，见「下载」），活动栏立刻多出一个 Markdown 工作台——完整编辑器、文档大纲树、AI 补全，全部在 IDE 里原生运行。在 AI IDE 里写文档，不用再切出去。

### ✦ 大文件不卡顿

分片后台渲染加源码缓存复用：打开大文档先建缓存，之后输入、撤销、大纲跳转都保持流畅，公式再多的长文也不会滚不动。内部基准测试中，正文编辑的 CPU 开销下降 57%–87%。

### ✦ 印刷级中文排版

这是 2.0 系列打磨最狠的一块，也是中文名「万可百律」里那个「律」字的来历——排版的韵律：

- **中西文混排自动间距**：中文与西文、数字之间自动留出呼吸空隙，公式与代码内部的像素布局不受干扰；
- **宋体系衬线双主题**（宋体-朙 / 宋体-暗）：正文中文宋体、西文 Georgia 双衬线，细笔画描边、暗色表格不再陷成黑条纹，中文斜体以楷体呈现——把屏幕当"纸"来排；
- **1280px 阅读版心**：宽屏不再一行读到脖子断；
- **导出采用 TeX 同源的 Knuth–Plass 整段最优断行**：不是逐行贪心塞满，而是整段代价最优——TeX 排了四十年的数学论文，用的就是它。

### ✦ 界面透明度可调

每一个弹窗、右键菜单与工具栏默认都是半透明的，而且**可以自己调**：设置里的「界面透明度」给弹窗与工具栏各一个 10%–100% 的滑块（70% 是个不错的起点）。是"可调"而不是"写死"——想看得清就调实，想要玻璃感就调透；正文从半透明的菜单后面透出来，但不会糊成一片。

## v2.1.5 更新

### ✦ 清空整篇之后接着打字，不再变成公式

`Ctrl+A` 全选 + 一次退格把文档清空之后，接着打的第一句话以前会**变成公式**：当文档最后一块是块公式时，
光标会停在那个被清空的 `$$` 里，你打的字直接进了公式源码——屏幕上出现的是一段按公式排版的斜体字
（打 `abc`，文档里就变成 `$$\nabc\n$$`）。

现在清空之后是一个普通的空段落，接着打字进的是正文。

## 修复（v2.1.5）

- **清空整篇之后接着打字会被当成公式**：`Ctrl+A` 全选 + 一次退格之后，如果文档最后一块是块公式，光标会停在
  那个空 `$$` 的源码里，之后输入的字符全被写成 TeX（打 `abc` 就得到 `$$\nabc\n$$`）。现在这种"清空后只剩
  一个空块公式"的形状会归位成空段落，打字进正文；清空后按**一次** `Ctrl+Z` 依旧逐字节把整篇文档还原。

## v2.1.4 更新

### ✦ 公式旁边按「按词删」不再毁公式

`Ctrl+Backspace` / `Ctrl+Delete`（按词删）以前会绕过公式的贴边保护：光标停在一条块公式前面按下去，
整条 `$$…$$` 会被并进上一段，公式当场散成一行文字。现在带 `Ctrl`/`Cmd` 的退格与删除也走同一套保护，
这两组键的其余行为一个字都没改。

### ✦ 点公式上下的那几像素空白，不再吃掉公式源码

折叠的块公式上方或下方几像素的空白，以前点下去会落到隐藏的公式源码里，紧跟着按一下退格就删掉了公式里的
一个字符。现在这类点击按几何位置落到公式**之前/之后**，永远不会落进源码。

### ✦ 大文档里移动光标更省

每移动一次光标都要跑一遍的公式状态同步里，有一句"找当前展开的公式"是最贵的一步——在一份 49 万字、
5634 条公式的文档上，它一项就占掉整趟的九成。换成更省的查法之后，这一趟从 **0.289 ms 降到 0.099 ms**（约 3 倍）。

## 修复（v2.1.4）

- **按词删（`Ctrl+Backspace` / `Ctrl+Delete`）会绕过贴边保护、把整条块公式并进上一段**：在真实文档上实测，
  `> (1)` 那一行会当场变成 `> (1)\neg\,\exists x\in A, P(x)\;\Leftrightarrow…`（公式散成引用块里的文字）。
  现在这类按键也走同一段贴边保护，保护之外的行为不变。
- **点"公式块上方那几像素的页边距"再按退格，会吃掉公式源码的最后一个字符**：现在贴着折叠公式的空白留白
  按几何归位到公式之前/之后。

## v2.1.3 更新

### ✦ 点在公式周围的空白上，光标不会再掉进隐藏的源码里

块公式折叠时，它的源码是一个 `0×0` 的壳。在公式下方那片看起来是"空行"的地方点一下，浏览器会把点击解析成
源码文本里的某个位置——同一片留白，靠左拿到源码末尾、中间拿到开头，取决于你点在哪。于是"点一下再按退格"
删掉的是公式里的一个字符（`x+y=1` → `x+y=`）。现在点公式周围的空白，光标落在公式**之前/之后**；
点渲染出来的公式本体，照旧展开源码、进源码编辑。

### ✦ 现在的手感

- **点公式块周围的空白留白**：光标落到公式之前/之后，公式不展开、也不会落进隐藏源码里；点公式本体照旧展开源码。
- **点 `$$` 围栏**：光标**就停在 `$$` 上**——第一个 `$` 前、两个 `$` 中间、最后一个 `$` 后，按你点在哪决定。
- **在围栏上或紧贴公式块按退格**：文档**一个字节都不改**，并弹一句说明。
- **在围栏上打字 / 粘贴 / 输入法**：字符落进公式源码的对应一端，围栏和 Markdown 都不会被写坏。
- **只增不减**：前几版的修复全部保留。

### ✦ 为什么在渲染视图里删不掉单独一个 `$`

块公式的 `$$`、行内公式的 `$` 都是渲染器每次重排时重新生成的标记，编辑内核里并不存在"删掉一个 `$`"这个动作
（改标记文本不参与保存，会被丢掉）。所以这里的选择是"围栏上可以停光标、但退格不改文档，并且当场说明原因"，
而不是假装删掉一个 `$`、把公式变成半截文本。要逐字符改围栏，用工具栏的「切换源码视图」，那里围栏就是普通文字；
要删整条公式，整条选中按一次 `Backspace`/`Delete` 即可。

## 修复（v2.1.3）

- **跨引用块的段落贴边没被拦住**：`> $$ … $$` 后面跟一行不带 `>` 的空行、再跟 `> (2)` 时，两行分处不同的引用块，
  这一下退格会把整段引用块的 `>` 前缀削掉（`> (2)` → `(2)`），看起来就像公式被删了。现在贴边判定会往上层节点走。
- **点 `$$` 会被塞进源码里（所见非所得）**：点开围栏＝光标到源码开头，点闭围栏＝光标到源码末尾，接着打字就落在你点的那一侧。
- **行内公式源码第 0 个位置退格会整条消失**：现在同样纳入边界拦截。

## v2.1.2 更新

### ✦ 贴着公式按退格，公式一个字节都不会变

在公式块的边上按退格，以前会把 `$$…$$` 整块散进上一段文字里；上一版改成"第一下选中整条、第二下整条删除"，
连按两次公式照样会消失。现在这一下**只把光标挪到公式外面最近的文字上**，文档不动；再按一下删掉的是公式外的普通文字。

### ✦ `$$` 围栏点在哪就在哪落光标

展开后点前 `$$`，光标落在源码**开头**；点后 `$$`，落在源码**末尾**；接着打字，字符真的落在你点的那一侧
（以前停在围栏上打字，字符会悄悄跑到源码末尾）。

### ✦ 行尾公式的预渲染框从机制上不可能再停留

只要光标不在公式的源码/预览里，展开样式立刻撤掉——不再依赖"再跑一遍"去追渲染时序，所以不会再出现
"同一处点击有时收得回、有时收不回"。

## 修复（v2.1.2）

- **光标落在公式"本体"上（元素级位置）时，边界判断不认**：这一下退格会让整块 `$$…$$` 散进上一段。现在这类位置也纳入边界判定。
- **贴边退格不再"先选中整条公式"**：改为把光标挪到公式外最近的文字位置，文档零改动。
- **展开态（预渲染框）改为强制收回**：光标不在公式源码/预览里就撤掉展开样式，消除时序竞争。
- **`$$` 围栏点击语义明确**：点开围栏＝光标到源码开头，点闭围栏＝光标到源码末尾（以前点尾 `$$` 光标会掉进下一段）。
- **行内公式源码第 0 个位置退格会整条消失**（v2.0.4 那个形状对行内仍会漏）：现在同样被拦住。
- **只增不减**：上一版的其余修复全部保留（整条选中删除不留残渣、公式源码里 `Ctrl+B/I/U` 与回车不再改坏 TeX 等）。

## v2.1.1 更新

### ✦ 公式「贴边」的编辑手感对齐直觉

这几处都是真实文档里报出来的：

- **一行最后是公式时，光标停在行尾不再自己弹出预渲染框**。以前光标一落到行尾（在行尾点一下、或按 End），
  最后一个公式的浮层就冒出来挡住下文；现在**只有点公式本身**才会展开源码来编辑，停在公式前/后都只是普通光标位置，
  接着打字就落在公式之后。
- **`$$ … $$` 前后那两个 `$$` 现在可以落光标**。以前块公式展开后，不管点哪儿光标都只能停在源码的第一个位置；
  那两个 `$$` 现在是真的文本，点它、选它、按字符改它都成立。
- **贴着公式按退格不再毁公式**。以前在公式块的边上（块首、块尾，或紧邻段落的首尾）按一下退格，`$$…$$` 会整块
  散成一行纯文本，或者悄悄吃掉源码里的字符；现在这类位置的第一下只**把整条公式选中**（文档一个字都不动），
  再按一下才把它作为一个整体删掉——想整块删掉公式仍然两下就够。

### ✦ 顺手修掉巡检中发现的三处同类问题

- 公式源码里按 **Ctrl+B / Ctrl+I / Ctrl+U** 不再把 `****`、`**`、`<u></u>` 插进 TeX 源码（以前公式当场就坏）。
  剪贴板、撤销重做、全选不受影响。
- 公式源码里按**回车**不再把 TeX 拆断（以前会得到 `$a$a+1+1$` 这种垃圾）。行内公式里这一下只把光标移到公式之后；
  块公式是多行源码，回车照旧换行。
- 删除整条公式（无论是你自己选中的、还是上面那一步选中的）不再留下 `<span>` 之类的残渣文本。

## 修复（v2.1.1）

- **光标停在行尾、而这一行以公式的 `$` 结尾时，最后一个公式被自动展开**并浮出预渲染框：贴边的光标现在不算在编辑公式，
  并且会把自动挂上的展开态收回。
- **点 `$$` 以前不管点哪都只能落到源码开头**（那两个 `$$` 是画出来的、不参与点击命中）：展开后改用真实的 `$$` 文本，
  点哪落哪，折叠态照旧只显示渲染结果。
- **光标作为节点的首/尾子位置时，退格会吃掉末尾的 `$`**，把公式变成一行字面文本：这类贴边位置改为先把整条公式选中。
- **块公式源码开头退格会把 `$$` 围栏拆掉**（`$$…$$` 整块散成一行文本）、**行内公式源码末尾删除会整条消失**：
  朝围栏方向的删除改为先选中整条公式；**向内**的正常改字（源码末尾退格、源码开头删除）保持原样。
- **光标停在块公式紧邻的段落首/尾按删除，会把公式块并进段落文本**：现在改为先选中整条公式。
- **公式源码里的 `Ctrl+B` / `Ctrl+I` / `Ctrl+U`** 不再把 Markdown 记号插进 TeX 源码。
- **行内公式源码里按回车**把 TeX 拆断并复制出半截公式：现在只把光标移到公式之后，不改文档。

## v2.1.0 更新

### ✦ 一次开好几份稿子：一个文件一个独立窗口

以前打开第二个文件会**顶掉**已经打开的那一份——这是产品最要紧的缺陷之一。这版改成：**每个文件一个独立窗口**，各自可以拖动、缩放、最大化，互不影响；关掉一个不影响其它；只有关窗口或退出应用时才问你要不要保存，而且是**逐个**确认，点「取消」就中止整个退出（已经确认过的窗口内容不会丢）。

顺手一起做好的：

- **同一个文件只开一个窗口**：再次打开已在别处的文件，直接把那个窗口带到前面，不会弄出两份互相覆盖。
- **记住你上次开着哪些窗口**：每个窗口的文件、工作区、位置和大小都记下来，下次打开原样回来。
- **每个窗口一套文件夹树**：不同窗口可以开在不同目录，互不牵动；同一个目录只监听一次，不会开几个窗口就重复监听几遍。
- **拖入或一次选中多个文件**：每个文件各开一个窗口；当前窗口若还停在欢迎页，就先填进当前窗口，不浪费一个空窗口。

### ✦ 窗口很小的时候，工具栏会自己让位

窗口压得很矮时（那种小窄窗），工具栏换行后会占掉一大块高度，正文几乎没地方。现在只要工具栏占到可视高度的 35% 以上，它就**自动收上去**；鼠标移到窗口顶边它滑出来，鼠标离开再收回去，正文始终是满的。窗口拉回正常高度后一切照旧。（实测极端小窗里这一档占到了 116%。）

窗口本身也不会再被压到比工具栏还矮了：**最小高度按「换行之后实测的工具栏高度」来定**（让工具栏最多占可视高度的 80%）。所以窗口越窄、工具栏换行越高，能缩到的最小高度就跟着变高；再拉宽，最小高度又跟着降回去——它盯的是实际排版结果，不是一个写死的数字。

### ✦ 在 IDE 里也不再「只能开一份」

- 默认把标签页**钉住**：以前单击文件会用同一个标签顶掉上一份（IDE 的「预览标签」行为），现在默认新开标签，多份稿子可以同时开着。
- 新增右键菜单「**用 MarkPilot 打开（新标签页）**」，任何设置组合下都强制新开标签。
- 切回某个标签时，编辑区会和最新内容对齐一次（长时间在后台的标签不会再显示旧内容）。

## 修复（v2.1.0）

- **超小窗口里工具栏占掉半个屏幕**：见上，35% 以上自动收纳，贴顶弹出、离开收回。
- **标签页切回来可能显示旧内容**：IDE 里隐藏的标签页不保证收到更新推送，现在切回来按最新内容对齐一次（内容没变就不动，不会白丢撤销历史）。
- **个别弹窗关掉后还留在页面上，导致再也打不开**：窗口被别的窗口完全遮住时，「关于」「快捷键设置」这类弹窗的关闭事件可能不派发，节点留在 DOM 里、判重逻辑就把后续的打开请求挡掉了。现在关闭动作自己收尾，关一次干净一次。
- **退出应用时的偶发报错框**：多窗口退出时窗口正在销毁，焦点回调读到已销毁的窗口会弹错误框并卡住退出流程；现在这类回调一律跳过销毁中的窗口。
- **一次打开多个文件却只剩一个窗口**：一次拖入/多选多个文件时，第二个文件会被误判成「填进刚建好的那个空窗口」，几个文件挤进同一个窗口——它正是「开一个顶掉一个」的另一种形态，已修正。
- **两个窗口之间复制复杂表格，单元格里的格式会丢**：复制带粗体/行内代码的单元格时，记号会被悄悄吃掉（粘过去就只剩纯文字）。现在按 Markdown 逐格还原，粗体、公式、行内代码、图片、转义竖线都能原样过去，粘到另一个窗口后重新变成真节点。
- **两个窗口之间剪切表格会粘成一串**：剪切选中的表格格子后，剪贴板里得到的是一串连在一起的文字（还会顺带弄坏表形），粘到另一个窗口只剩一格。现在剪切和复制是同一套矩形语义，并且只清空选中格、不动表形。
- **两个窗口之间剪切图片会指向原文档的文件夹**：剪走的图片粘到另一个文档后引用的是**原来那个文件所在目录**，换个文档就断链。现在剪切图片也按"图片"进剪贴板，粘到哪份文档就跟着哪份文档走。

## v2.0.20 更新

### ✦ 导出终于会问你把文件放哪了

导出从工具栏「更多」里的一个小图标，改成**一眼可见的独立按钮**：点开就是 PDF / Word / HTML / 便携 Markdown 四选一，**先弹保存对话框让你选好位置、点了确认才开始导出**；导出完成后会自动打开资源管理器并选中刚生成的文件，不用再猜它去哪了。按钮本身不带文字，用的是各平台通用的「方框 + 箭头出框」图标——中英文使用者都认得；四种格式和"先选保存位置"写在鼠标悬停的提示里。

### ✦ 工具栏清爽了：不再有装样子不干活的按钮

去掉了几个看着像功能、点了却没反应甚至帮倒忙的按钮（详见下面「修复」）。工具栏上留下的每一项都真的能用。

## 修复（v2.0.20）

- **导出 PDF 之后不知道文件去哪了**：工具栏「更多」里原先同时有两个「导出」，一个是我们自己的（只有一个没文字的图标），另一个是编辑器内核自带的（写着「导出」，而且只有它里面有 PDF）。点后者导 PDF，屏幕会提示"生成中"，但文件从来没有被创建过——它只是把内容塞进一个零高度的隐藏框去调系统的打印命令；导 Markdown / HTML 则会不声不响地下载进系统下载目录。现在那个会骗人的入口已经移除，「导出」提升为一级图标按钮，导出成功后会直接帮你定位文件。**编辑器自己的导出引擎一直是好的**（PDF / Word / HTML / 便携 Markdown 四种格式逐字节校验通过），坏的是入口。
- **鼠标侧键会让整个编辑区消失**：用带前进/后退侧键的鼠标时，按「后退」编辑区会整片消失，再按「前进」才拉回来。原因是编辑器把每份文档都装进内部框架，每开一个文档都会往浏览历史里压一条记录，「后退」就把它退回了上一个文档甚至空白页。现在前进/后退侧键（以及常被鼠标驱动映射成的 Alt+←/→）都会被拦下，编辑区不会再被翻走；中键、右键一切照旧。
- **录音按钮是个坑，已移除**：它看起来能录音，实际点下去会占用麦克风，录完却把音频当图片处理、弹一句「不支持的图片格式」，文件不会保存到任何地方；更麻烦的是它会让正文的编辑区变成只读，连点两次之后正文就打不了字了。这个功能从来没有真正接好，这版直接拿掉。
- **「关于」里讲的是别人的项目**：以前点「关于」看到的是编辑器内核那个开源库的介绍，还带着它的官网和论坛链接；「帮助」跳的也是它的文档站。现在「关于」显示 MarkPilot 自己的版本号和仓库地址，「帮助」指向我们的 GitHub 仓库。

## 修复（v2.0.18）
