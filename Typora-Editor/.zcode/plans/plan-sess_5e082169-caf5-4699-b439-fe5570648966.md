# 把 Typora-Editor 插件变成个人版单文件 EXE（含目录浏览/文件管理）

## 目标与硬约束
- 在 **D:\BuyKey\Typora-Editor-App**（与 Typora-Editor 平行的新目录）新建 Electron 项目，产出**单文件便携 EXE**（portable，约 200MB）。
- 侧边栏带**完整文件管理**：目录树浏览、打开、新建 .md/文件夹、重命名、删除（回收站）、资源管理器定位、复制路径。
- **绝不修改 D:\BuyKey\Typora-Editor 下任何文件**（只读取）。开工前先对全目录做 SHA-256 清单，结束前复测对比，作为零改动证明。

## 调研结论（可行性依据）
- 编辑器前端（`extension-src/render/`，魔改 Vditor 3.11.1 + KaTeX 源码定位补丁，全部资源本地化 22MB）与 VS Code 耦合极低：`js/vscode.js` 对 `acquireVsCodeApi` 判空降级，初始化只等宿主回一条 `open` 消息；`test/` 目录已在纯浏览器验证可跑。
- 扩展宿主侧只有 245 行，职责就是：模板替换 + 消息中转 + 读写文件 + 图片落盘 + 滚动持久化。全部可在 Electron 主进程复刻。

## 核心架构：零改动复用（所有新代码在新目录）
1. **同步脚本** `scripts/sync-renderer.mjs`：只读复制 `D:\BuyKey\Typora-Editor\extension-src\render` → `app/renderer`（校验文件数/字节数一致）。副本永不手改，编辑器页面字节级等于 GPT 版本。
2. **内建 HTTP 服务**（主进程，沿用 test/serve.py 思路，解决 ES module 与图片相对路径）：
   - `GET /render/*` → 提供 `app/renderer` 下文件（正确 MIME，模块可加载）
   - `GET /doc/<urlencoded-md绝对路径>` → 读 renderer 的 index.html 动态改写：`{{baseUrl}}`→`/ws/<md所在目录encoded>`，页内相对 `src/href` 重写为 `/render/...`（等价扩展的 buildPath）
   - `GET /ws/<urlencoded-绝对路径>` → 提供 md 同目录资源（图片等）
   - `rootPath` 消息字段传 `/render`，Vditor 懒加载资源即从本地副本读取
3. **preload 假 webview API**：`contextBridge.exposeInMainWorld('acquireVsCodeApi', ...)`，postMessage→`ipcRenderer.send`；主进程消息→`window` MessageEvent（`vscode.js` 的 receive 原样可用）。`nodeIntegrationInSubFrames: true` + `sandbox: true` 让 preload 进入 iframe。
4. **外壳** `app/shell/shell.html`：左侧边栏（新代码）+ 右侧 iframe 加载 `/doc/...`（GPT 的编辑器页）。
5. **消息协议复刻**（主进程 doc.js）：
   | renderer→main | 处理 |
   |---|---|
   | `init` | 回 `open{title, language:'zh-cn', scrollTop(持久化恢复), rootPath:'/render', content}` |
   | `change` | 更新内存文本 + 脏标记（标题栏 •） |
   | `img` | 写 `images/<md名>/<时间戳>.png` 到 md 同目录，回 `insertValue` |
   | `openLink` | `/ws/` 内链 .md→应用内打开；http→系统浏览器；相对文本→按 md 目录 resolve 后 shell 打开 |
   | `scroll` | 按文件绝对路径持久化到 userData JSON |
   | `reload` | 重读磁盘回 `setValue` |
   | `editInVSCode` | `shell.openPath` 用系统默认程序打开 |
   | `developerTool`(F12) | `webContents.openDevTools({mode:'detach'})` |
   - Ctrl+S（菜单加速键）→ 写盘；`fs.watch` 监听 md，磁盘内容 ≠ 内存文本且 ≠ 自己刚写的 → 发 `setValue`（复刻 onDidSaveTextDocument 逻辑）；关闭窗口有未保存改动 → 保存/放弃/取消对话框。

## 侧边栏文件树（新功能）
- 目录树：文件夹折叠/展开（记住展开状态），.md 单击在当前窗口打开，非 .md 双击用系统程序打开；顶部工具条：新建 .md、新建文件夹、刷新、展开/收起全部、只看 Markdown 开关。
- 右键菜单：新建 Markdown 文件 / 新建文件夹 / 重命名 / 删除（`shell.trashItem` 进回收站，带确认）/ 在资源管理器中显示 / 复制路径。
- `fs.watch` 递归监听工作区根（Windows 原生支持递归）→ 防抖刷新并保留展开状态。
- 欢迎页（未打开文件夹时）：打开文件夹/打开文件/最近列表 + 全窗拖放文件/文件夹。
- 记忆：窗口位置大小、上次文件夹与文件、各文件滚动位置、侧边栏宽度与展开状态。
- 其他：单实例锁（二次启动带文件参数→聚焦并打开）、`TyporaEditor.exe D:\x\a.md` 命令行直接打开、自动保存默认关（与插件一致，手动 Ctrl+S）。
