# 章节上下文补全对照：100 个真实缺口，200 次生成

2026-09-07，北京时间 01:31–01:35 执行 API 实验。

**本轮开启章节上下文的直接可用率为 77%，关闭为 71%；有改善信号，但尚不足以证明稳定提升。** 同时，把“小改后可用”也计入时，两组只有 83% 对 81%。建议保留现有章节开关和上下文上限，下一步优先验证文内符号定义与插入边界约束，不凭本轮结果继续扩大提示词。

本次只新增实验、审计与报告文件。正式补全代码、默认配置、EXE/VSIX 版本均未改动。

## 如何比较

- 文档：`D:/Users/Ming/Desktop/动态规划教材（渲染修复副本）.md`，178,107 个 UTF-16 字符、261,933 字节。
- 固定沿用上一轮的 100 个真实编辑缺口：70 数学、30 文字。两组都重新生成，不把旧响应当作关闭组。
- 每处关闭/开启章节上下文各生成一次，共 **200 次调用**，全部指定 `deepseek-v4-flash-vision-exp`；199 个完整响应的模型字段也都是该模型。
- 缺口顺序打乱；数学中 OFF/ON 各先执行 35 次，文字各 15 次；并发为 1。
- 同一生产版 `requestAI`、局部上下文、清理逻辑和参数。数学 temperature=0.2、输出上限 256 token；文字不指定 temperature、输出上限 160 token；关闭 thinking，不使用流式输出。
- 唯一请求差异：开启组注入生产版 `StructureCache` 生成的章节信息及其配套指令。对每组请求删除这两处后，逐项验证与关闭组完全一致。
- 参考缺口先从完整文档移除，再建立章节索引。参考答案和测试标签不作为额外字段发送。若相同公式本来就在相邻笔记中重复出现，则保留这种真实上下文。
- 单次超时 15 秒。第 51 次（M51/ON）收到了 HTTP 200 响应头，但未在期限内完成响应读取，计 D，不重抽。初始运行器因此暂停；恢复时只执行尚未尝试的 149 个预定请求，没有更换提示词、覆盖失败结果或增加抽取次数。
- 先用随机 X/Y 隐藏开关组别，由本助手逐项阅读缺口、上下文与输出评分；100 项评分写入并锁定 SHA256 后，才揭盲统计。没有另调模型作预检或评分。这是**单一助手评审，不是独立人工接纳率**。

## 质量结果

评分：A=语义正确且能直接插入；B=小幅修改后可用；C=含义/记号错误或插入边界失效；D=无可用输出。数学等价式可以得 A，不要求逐字还原原文。文字中准确、能衔接的其他表述也可以得 A；明显重复、悬空标点和格式问题计 B。

| 类别 | 关闭：A / B / C / D | 开启：A / B / C / D | 直接可用率变化 |
| --- | --- | --- | --- |
| 数学，70 处 | 52 / 2 / 16 / 0 | 55 / 1 / 13 / 1 | 74.3% → 78.6%，+4.3 个百分点 |
| 文字，30 处 | 19 / 8 / 3 / 0 | 22 / 5 / 3 / 0 | 63.3% → 73.3%，+10.0 个百分点 |
| 合计，100 处 | 71 / 10 / 19 / 0 | 77 / 6 / 16 / 1 | 71% → 77%，+6 个百分点 |

配对看，有 **15 处从非 A 变为 A，9 处从 A 变为非 A**，净增加 6 处。按 A/B/C/D 等级比较，16 处改善、12 处变差、72 处等级不变。

按数学/文字比例分层，对缺口做 20,000 次配对 bootstrap，直接可用率差的探索性 95% 区间为 **−3 至 +16 个百分点**；精确 McNemar 双侧 p=0.307。区间跨过零，不能据此宣称“稳定提高 6%”。若将 A+B 一并视作可用，结果是 **81% → 83%**，说明本轮部分优势来自减少小修，并非全部来自解决数学硬错误。

### 改善与退步都存在

| 缺口 | 关闭 | 开启 | 判定 |
| --- | --- | --- | --- |
| M28，另一状态的流入率 | `\eta_i\mu_j(a)` | `\eta_j\mu_j(a)` | C→A，流入率下标正确 |
| M32，一般历史可行约束 | `\Gamma_t(x_t)` | `\Gamma_t(u_{S:t-1},x_t)` | C→A，保留前序控制依赖 |
| M69，Pareto 指数 | `2\bar g/\bar\sigma^2-1` | `1-2\bar g/\bar\sigma^2` | C→A，与左侧指数匹配 |
| M45，多维扩散 | `\sigma\sigma^\top` 的迹项 | `\sigma^2` 的迹项 | A→C，矩阵协方差退成标量平方 |
| M70，平稳分布 | `A^\top\mu=0` 的等价写法 | 改用未定义的 `p` | A→C，破坏文内记号 |
| P6，粗体内的短缺口 | 正确方向，但多一个逗号 | 复制后文定义，以冒号结束 | B→C，无法接上已有“转化为” |
| M51，累积效用 | 正确积分 | 15 秒超时，无输出 | A→D，保留本次真实失败 |

这些是本次成对输出的差异，不代表已证明“某个标题导致该处改善或退步”。每组只抽一次，存在模型随机性。

## 速度和成本

时延从调用开始计到完整响应及生产清理结束，**不含编辑器触发防抖、灰字显示、用户接受时间**。中位数及 P95 使用线性插值分位数。

| 类别 | 关闭，中位数 / P95 | 开启，中位数 / P95 |
| --- | --- | --- |
| 数学 | 825 / 1,436 ms | 812 / 1,486 ms |
| 文字 | 909 / 1,570 ms | 1,074 / 1,348 ms |
| 合计，含失败耗时 | 846 / 1,470 ms | 900 / 1,479 ms |

开启组那次 15,006 ms 超时仍计入总体。P95 本身不会展示全部极端值。只看双方都成功的 99 对，逐对“开启减关闭”的时延差中位数为 **+14 ms**，与两组各自中位数之差不是同一统计量。

**两组缓存条件并不相等。新生成不等于冷缓存，交错顺序也不能清除供应商已有缓存。** 在双方都成功的 99 对中，关闭组输入缓存读取占比为 **94.4%**，开启组为 **15.3%**。旧提示前缀曾用于早先实验；当前章节块又位于局部正文之前。缓存差异的具体来源没有单独做实验。因此，上表是本次运行观测，不能把速度差全部归因于章节上下文。

按兼容响应的 `input_tokens + cache_read_input_tokens + cache_creation_input_tokens` 统计总输入；这里 `input_tokens` 只代表未缓存输入，不能单独当成总 token 数。该口径来自 [Anthropic 缓存字段说明](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)，接口兼容约定见 [DeepSeek 官方说明](https://api-docs.deepseek.com/guides/anthropic_api/)。

| 相同的 99 对成功请求 | 关闭 | 开启 |
| --- | ---: | ---: |
| 总输入 token | 110,863 | 125,504 |
| 其中缓存读取 token | 104,704 | 19,200 |
| 输出 token | 1,610 | 1,536 |

**章节信息平均增加约 148 个输入 token/次，+13.2%。** 这是配对后的总输入差，比直接相减 100 次成功与 99 次成功更可比。本轮章节文本为 153–321 字符，中位数 228；没有把整篇笔记发给 API。离线准备时，每个缺口重新构建本地标题索引的中位数为 0.73 ms、P95 为 1.40 ms；这不是应用启动或编辑时延测量。

本次时间处于官方非高峰段。按输入未命中 $0.22/M、缓存命中 $0.007/M、输出 $0.66/M 估算，全部已返回 usage 的请求合计约 **$0.0277**：关闭约 $0.00318，开启约 $0.02454。该巨大比例主要伴随不等的缓存命中，**不能理解为日常开启章节功能就会贵 7.7 倍**。超时请求没有 usage，可能产生的费用不在此估算内；这里也不是账单实扣金额。价格与时段依据 [DeepSeek 官方价格表](https://api-docs.deepseek.com/quick_start/pricing/)。

若对相同 99 对进行纯算术估算，两组都按完全未命中缓存收费，则为 $0.02545 → $0.02862，约 +12.5%；都假定 90% 命中，则约 +8.7%。这些只是同等缓存条件的成本情景，不是追加实测。

## 下一步优先验证什么

1. **补进当前章节的符号定义，控制总长度。** 两组都没解决 M19 的终值函数 Phi/g、M25 的最优漂移 g*/b、M31 的状态维数 k/n 等问题。标题能提示主题，却不能替代具体符号约定。候选方案是本地提取少量相关定义片段，优先同公式、同段、同章节，并用它替换低价值的相邻标题信息；不增加一次“检查用”的模型请求。文档原本的记号不一致也应作为压力测试保留。
2. **加强光标两侧的衔接。** M65 另起 `Q*_t=` 后撞上已有 `\equiv`，M66 重复后面的概率流定义；文字还有重复前缀、句号前的悬空“即”、粗体内部不合适的结尾。应比较短缺口约束与边界清理，而非单纯增加输出长度。不能自动改写数学符号或见到等式就截断。
3. **重新控制缓存再谈加速。** 将等量预热与正式计分分开记录，对两组采用相同处理；提示块重排若要改变，也作为独立变量做对照。当前结果不支持宣称已经加速。

这些是由失败样本导出的候选方向，本轮没有把未经验证的新规则塞进正式版本。现有章节开关与 1,200 字符上限保留，便于继续选择。

## 结论的适用范围

- 同一份笔记、之前测试过的缺口，不是新的留出集。不同缺口还可能共享段落或公式，存在相关性；上述区间和 p 值只能作探索参考。
- 每个开关在每处只抽一次，不能估计同一提示多次生成的稳定性；这轮也不比较 GLM 或 DeepSeek Pro。
- 评分由单一助手完成，B 与 A 的边界存在主观判断。全部 X/Y 输出及理由已保存，便于用户复核；评分文件揭盲后没有改动。
- 比较使用此前捕获的真实编辑器局部上下文，在主机侧重放当前请求。并未重新测 VS Code、Trae 或桌面端的输入、显示延迟。
- 本次唯一不可用响应是超时；并未再次模拟 401/429/断网的 UI 行为。正式请求、凭据与离线降级代码未变，先前回归结果不能当成本轮新测试。
