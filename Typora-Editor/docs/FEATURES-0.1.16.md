# 0.1.16-local：数学优先的上下文补全

按数学笔记约 70%、正文约 30% 的使用场景设计。比例代表功能优先级，不是随机分配模型调用次数。仅更新 VS Code / Trae 的 VSIX。

## 触发与响应

| 场景 | 默认等待 | 行为 |
| --- | --- | --- |
| 输入公式命令或模板 | 120 ms | 本地匹配候选，无 API 调用 |
| 数学编辑停顿 | 500 ms | 结合公式左右两侧、附近定义和标题，直接请求一条补写建议 |
| 正文输入停顿 | 750 ms | 生成一两句以内的续写 |
| 进入公式或移动光标 | 数学 900 ms，正文 1200 ms | 本地判断空参数、未完成右式或插入空隙，再直接请求补写；无须先输入字符 |

保留用户原有等待设置，表中数值基于默认基础等待 650 ms。只阅读完整句子或在代码区移动光标不会自动调用 AI。中文 IME 组词期间暂停，滚轮浏览、切换窗口和 Esc 会关闭建议。自动行为受 **补全 ▾ → 自动 AI 补全** 控制；**光标停顿时建议** 可单独关闭。

这些等待时间不包含服务商的网络与模型生成耗时。继续使用用户配置的 `glm-5.3-flash`；没有新增模型、账号或依赖。

## 一次调用直接生成

插件的 JavaScript 在本地识别公式区域、光标位置、简单结构和停顿，不使用 LLM 分类，不消耗补全 API token。唯一的模型调用直接请求插入文本，同时处理上下文和补写目的。没有“检查一次，再生成一次”的两轮调用，也不并发调用多个模型评审。

请求携带：光标前最多 4000、后最多 1000 个字符；当前公式前后片段；最近标题；少量附近定义或说明。所有文档字段合计上限 10000 字符（不是 token），通常远低于上限。附近正文会排除已完整包含在左右上下文中的块。准备过程有节点数和字符预算，不做全文索引或遍历全部 KaTeX 预览。

数学提示要求沿用已有变量、下标、记号和假设，优先补一个表达式、公式参数或一步推导；正文请求限制为较短续写。数学最多输出 256 tokens，正文最多 160 tokens。一次请求的输入上下文和实际输出仍受服务商的 token / 套餐规则约束；不能把“没有输出”或“客户端取消”理解为必然不计费。

## 利用已生成的结果

- 同一文档面板内，相同模型、地址和上下文的结果保存在内存中最多两分钟，最多 24 条；密钥、模型或配置变更时清空。
- 用户自己输入了建议开头时，如果前后文、标题和附近说明仍匹配，就继续显示剩余部分，无须再次调用 API。
- 同一光标位置的手动请求尚未结束时，再按快捷键不会重复发起请求。
- 只移动光标时，已发出的 AI 请求可以完成并进入缓存；结果不会插到新位置，回到原上下文后可复用。修改正文或关闭面板会取消旧请求。
- 本地候选先出现；AI 返回后加入可选建议。已有本地候选不会挡住 AI，宿主空响应也不会清掉灰字。用户已用方向键选定的候选会保留选择。
- 没有可靠插入内容时允许空结果，短暂缓存，避免为了产生输出而编造等式。空闲时没有轮询。

公式中途补命令会保留右侧参数，例如 `\fr|ac{x}{y}` 补成 `\frac{x}{y}`。AI 建议仍只在按 Tab / Enter 接受时写入正文，支持撤销，未修改的公式缓存保持复用。

## 与 VS Code 的关系

参考 VS Code 的补全提供器设计：区分手动和自动触发、候选与灰字、取消过期请求，并保留标准 CompletionItemProvider 桥接。当前编辑器主体是 Vditor Webview，补全交互由插件承接，未声称接入 Copilot 或 Trae CUE 私有模型。

参考：[InlineCompletionItemProvider](https://code.visualstudio.com/api/references/vscode-api#InlineCompletionItemProvider)、[IntelliSense](https://code.visualstudio.com/docs/editing/intellisense)、[智谱 token 说明](https://docs.bigmodel.cn/cn/guide/start/concept-param)。

模型仍可能给出不正确的数学建议；本次使用隔离测试文档与本机模拟 API 验证传入的上下文、调用次数、显示和编辑行为，不等同于真实 GLM 数学质量评测。
