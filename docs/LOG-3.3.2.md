# MarkPilot 3.3.2 验证记录

## 三个确认的笔记入口缺陷

安装态 3.3.1 上分别确认：分屏源码非主键 mousedown 在上下文菜单捕获前把 master 选区折叠；原生查找框整段 input 尚未提交到 SearchQuery，首次 Enter 命中旧查询；全局 contextmenu 缺少编辑表面的边界，在查找 input 中右键也能执行正文格式命令。

修复限定在入口意图与路由：分屏非主键保留既有默认抑制并提前返回；查找和替换框以 input/compositionend 同步已有 SearchQuery，跳过未提交的 composition；正文上下文菜单只接受 master/source 编辑区域与当前连接的 cell 输入节点。各项继续使用同一 CM6 文档、选区、编辑会话和历史，不新增另一份源码或历史。

常规输入先检查目标 tag/name；没有给正文输入增加 DOM 祖先扫描或全量解析。右键表面检查在命中计算和几何读取之前执行。当前图片、公式、代码、Mermaid 的编辑归属与增量生命周期保持既有协议。

## 已完成的定向证据

- 标准公开探针新增 `tools/quality/note-entry-workflows.cjs`，9 个独立场景；同源私有探针在隔离的实际用户设置副本上 9/9 通过，键盘、鼠标、组合键、鼠标加键盘、拖拽五通道都有真实 Chromium 输入记录。
- 三份独立的自有 ASAR 负对照分别只移除一个入口修复，三个对应场景均重现缺陷；编译控制与未变更载荷逐字节一致。未改动产品源码、候选或正常安装。
- 行测含图笔记和动态规划公式笔记从原件各做稳定副本。图片/公式激活后立即输入、远处正文再输入、两次逆序撤销与重做、保存前磁盘不变、Ctrl+S 精确保存、关闭窗口再以新会话重开、另一窗口保留文档与历史，两个流程均通过。原件与图片资产逐字节不变。
- 保存比较按真实源字节、BOM 和 CRLF/LF 进行；CM6 的 LF 归一化与磁盘编码分开验证。新会话以页面和文档 UUID 判定，不把不同窗口的本地 epoch 值当作跨窗口唯一标识。
- 独立视觉代理实际查看了 28 张全图/局部图并核对收据；Root 已全文读取报告、复核关键图像。它没有自行接管 GUI，五通道结论来自真实输入收据及图像交叉核验。

相邻的加粗操作和立即输入沿用 CM6 的既有撤销分组：安装态 3.3.1 控制实验确认一次 Undo 会同时撤销二者。曾使用“两次撤销”的错误探针判据已纠正，原失败证据保留，未修改产品历史来迎合探针。真实笔记中的两处远隔编辑则按严格两次逆序撤销验证。表格列插入使用真实 rewriteTable 的填充格式，不能用简单字符串拼接作为字节判据。查找源语法中的反斜杠沿用已有 SearchQuery 的转义契约。
