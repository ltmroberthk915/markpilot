# 3.6.8 · 复制后 Ctrl+点击产生双光标/双改的修复

## 复现（安装版 3.6.7，隔离 profile）

夹具：

```md
有的 $A$ 是 $P$: 翻译 $\exists A\land P$ 语法糖：$\exists A\to P$
规则：
1. 有的 $A$ 是 $P$,  $\leftrightarrow$ 有的 $P$ 是 $A$
2. 有的 $A$ 是 $P$,
```

步骤：

1. 选中第一行的 `有的 $A$ 是 $P$`；
2. 按下 Ctrl 不放，按 C 复制；
3. Ctrl 仍按住，点击第四行要粘贴的位置；
4. 松开 Ctrl，Ctrl+V，再输入一个字符。

测得的 CM 选区：

- 普通点击后粘贴：1 个光标，只有第四行变化；
- Ctrl 仍按住时点击：2 个选区（第一行选中的原文 + 第四行空光标）；
- 随后粘贴：两处都写入；再输入一个字符，两行同时出现新字符。

## 根因

这不是公式/IME 投影问题。CM6 在 Windows 上的默认交互是 **Ctrl+点击添加选区**；
复制后用户常常还没松开 Ctrl 就点目标行，于是第一行的原选区没有收起，第二行又加了一个
空光标。MarkPilot 的多光标粘贴路径（`extras.js` 的 `allRanges.length > 1` 分支）和
CM6 原生粘贴都会按多选区填入两处；输入也合法地作用到两行。控制臂证明：

- 普通点击（无 Ctrl）→ 单光标、单行粘贴；
- 复制后释放 Ctrl、再按 Ctrl 点击 → 仍是双光标，这是文档中明确的多光标手势，不应误伤。

## 修复

在 `main.js` 增加一个复制手势守卫：

- 跟踪修饰键按下状态和最近一次 `copy` 事件；
- 若 `copy` 时 Ctrl/Cmd 仍按着，则**同一按压期间的第一下 Ctrl/Cmd+点击**按普通点击处理，
  不添加选区；点击抬起后清除守卫；
- 松开再按 Ctrl/Cmd 后点击，或未复制时 Ctrl/Cmd+点击，仍按原多光标行为；
- Windows/Linux 用 Ctrl，macOS 用 Cmd，与 CM6 默认修饰键一致。
