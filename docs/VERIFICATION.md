# 验证手册（怎么确认"真的改对了"）

这个项目改一行都可能踩坑，所以每处行为都有**可复跑的判据**。这份文档说明这套验证怎么跑，
以及**哪些取证方式不可信**（这部分比"怎么跑"更值钱）。

---

## 一、测试挂点（产品内置，不用另外打补丁）

应用支持几个环境变量与启动参数，专为自动化取证准备：

| 名称 | 作用 |
|---|---|
| `--remote-debugging-port=<端口>` | 开 CDP，探针用 Playwright 连上去做真实键鼠输入 |
| `--user-data-dir=<目录>` | 独立配置目录：**并行跑多个实例**、互不干扰（务必每次都换新目录） |
| `MP_DEBUG=1` | 把壳层 trace 写到 `userData/main-debug.log`（保存/窗口/会话等一手事实） |
| `MP_TEST_NO_DIALOG=1` | 关掉原生对话框（**不设它，遇到保存框会把探针挂死**） |
| `MP_TEST_SAVE_AS=<路径>` | 预先指定"另存为"的目标，等价于用户在弹框里选好 |
| `MP_TEST_PICK_IMAGES=<路径>` | 同上，用于插入图片 |
| `MP_EXPORT_PDF=<路径>` | 预先指定 PDF 导出目标 |
| `MP_KEEP_STAGING=1` | 导出后保留临时 staging 目录（排查导出问题时看它） |

引擎侧另有一批**只读取证口**（`window.mpEngine.*`），例如：

| 取数口 | 回答的问题 |
|---|---|
| `_view()` | 拿 CodeMirror 的 `EditorView`（选区、文档、行盒坐标…） |
| `__inlineMarks()` | 行内标记清单（含 `hides` 隐藏区间、`uInner` 等；排"某类标记没投影"） |
| `__mermaid()` | 图表块清单 ＋ 三层缓存的规模/命中（排"图没渲染/改了没更新/变慢"） |
| `imgCopyDiag()` / `cellCopyDiag()` | 复制路径的分支与次数（排"复制没带上图/表格"） |
| `prefs()` / `setPref()` / `applyPrefs()` | 外观偏好的读写（改设置后的观感回归） |

> **加取数口的纪律**：只读、不改状态；名字以 `__` 开头；并在同一次改动里把"用它排障的判据"写上。

## 二、探针怎么跑

`tools/probes/` 下是手写探针。**顶层那批开箱即用**（已做冒烟普查：124 支里 109 支在公开仓里
就能跑出结果 ✓）；`tools/probes/dev-only/` 里那 15 支需要开发期的夹具/输入文件
（内部工作区 `.mp-verify/` 未随源码公开），**照抄思路可以、直接跑会缺文件** —— 该目录里有清单写明各缺什么。

典型形态：

```bash
node tools/probes/probe-u-accept.cjs "path/to/MarkPilot.exe"
```

约定：

1. **第一个参数＝被测产物路径**（默认指向打包出来的 exe）。探针会在开头打一张**尺子卡**
   （产物 sha16、文档 sha、node 版本）—— 换产物之后读数不可比，这条卡就是证据。
2. 探针自己起应用、连 CDP、结束后 `taskkill` 收摊；**不需要**你先手动开应用。
3. 输入一律走真实通道（CDP 的 `Input.dispatchKeyEvent` / `dispatchMouseEvent` / `insertText`），
   **不允许**用 JS 造 DOM 事件代替 —— 合成事件测不出 keymap/layout 这类真问题。
4. 读数落到探针自己的目录（`result.json` 或日志），按**实际字段名**取，不要凭猜写过滤条件。

两个外部依赖（路径按你的机器改）：

- **Playwright-core**：探针里 `require('C:/Windows/System32/node_modules/playwright-core')`
  之类写法是为了在无 `node_modules` 的目录里也能跑；换成你本地安装位置即可。
- **Chromium**：用应用自带的 Electron，无需另装浏览器。

## 三、取证纪律（这一节是踩出来的，不是抄的）

### 1. 任何尺子先做体检

拿一个**已知答案**的输入走同一条通路，确认尺子读得出已知答案。
**实测教训**：我们曾用自写的 PNG 解码器和本机 `pdftoppm` 去判"导出的 PDF 是不是白纸"，
两者都报"整页全黑" —— 拿一份已知白底的 PDF 一测，它们**同样报黑**，才知道是尺子坏了。
结论：**自写的解码/解析器默认不可信**；外部工具也会坏；至少两条独立口径一致才落账。

### 2. "读数一字未变" ＝ 这段没执行

改完代码后如果读数与上一版**逐字相同**，第一嫌疑是**新分支根本没进去**（守卫条件恒假、
或者被上游 `return` 挡死），而不是参数不对。做法：在分支入口埋一行自证
（`window.__xx = (window.__xx || 0) + 1`），复验时**先读它**再读行为。

### 3. 结果比对只适合"我是唯一写入者"

同族模块共用同一个键时（表格、列表、代码块都处理 Tab），用"文档有没有变"判"我的处理器有没有生效"
**必然误判**。要**分层**：先判"谁接管了"（自证计数），再判"接管者做得对不对"（用户可见性质）。

### 4. 判据文本不许内嵌期望值的字面量

写"把 62 写进了所有项"这种判据，一旦数值规则变了，判据还在说 62，
读报告的人会得出**相反**的结论。判据应由数据生成（"实测 X ∈ [min,max]"）。

### 5. 突变验证

"修好了"的结论，除了同一支探针复验，还要**把修复注掉再复跑**：判据必须转红；
注掉不变红 ⇒ 要么探针没鉴别力，要么你修的不是那个地方。
突变脚本要有**双向幂等**开关（`on|off`），验完立刻还原并复跑，最后用 `git status` 确认工作树干净。

### 6. 夹具要与判据同源

- 光标**必须**放在"不触发源码态"的行上 —— 否则会把产品**既有契约**（光标在标记区间内就显示源码）
  读成"没渲染"；
- 文档形态一变，**所有坐标算式都要重算**；
- 每臂开头**同时复位文档与光标**，并把复位结果打出来（上一臂的脏数据会连造几处假红）。

### 7. 不要用"看起来像"当判据

搜"像哈希的 16 进制串"去替换，会命中源码里的占位符；
在打包产物里搜中文字面量永远 0 命中（构建会把非 ASCII 转义掉）；
正则里 `.` 不匹配换行这件事，会让"挖 HTML 容器"只挖到开头。
**判"某段文本长什么样"就先把它打印出来看**。

## 四、各族报告（`docs/verification/`）

这些是历次改动的验收报告：判据怎么写的、实测读数是多少、哪些臂没有鉴别力。
按文件名找族即可，常见几类：

| 前缀 | 覆盖 |
|---|---|
| `long-doc-navigation` / `outline-modes` | 大文档导航、大纲面板 |
| `table-daily-*` | 表格：按键、粘贴、选区、剪贴板 |
| `math-daily-*` | 公式：点击定位、浮框、块公式折叠 |
| `code-fence-*` | 代码围栏：行类、粘贴、剪贴板通道 |
| `settings-truth-*` / `corrupt-config-*` | 设置的真源与脏数据 |
| `path-edge-*` / `file-ops-*` | 文件路径边界、另存为、外部改名 |
| `control-chars-*` / `rich-paste-*` | 控制字符嗅探、富文本粘贴 |
| `theme-switch-*` / `reading-split-*` | 主题切换、阅读/分栏模式 |

`docs/DEBUG-DB.md` 是开发期的**总台账**：每处改动的原因、判据、实测读数、
以及走错的路（那部分通常比结论更有用）。

---

## 五、这份文档本身的来源

它整理自开发期的内部工作区（保存了每处改动的判据、读数、以及**踩过的坑**）。
与源码一起公开，是为了让别人**不用重走一遍**：想做二次开发的话，
把上面的取证纪律当成默认习惯，能省掉相当多的来回。
