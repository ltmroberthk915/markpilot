# LOG 1.7.5 · 保存后自事件与真实外部修改的边界

## 背景

1.7.3 为消除“保存后误报冲突”引入了 1.2 秒时间窗：保存刚结束时的文件监听事件直接忽略。误报没了，但留下一个盲区——这 1.2 秒内的真实外部修改也会被忽略。

1.7.5 去掉“按时间盲目忽略”，改成**按正文判定**。

## 最终行为

### 保存中到达的文件事件

直接返回，不弹冲突；由保存后的 stat 对账决定：

- 磁盘正文 == 刚保存文本 → 采纳版本，不冲突；
- 正文不同 → 保留冲突/重载逻辑。

### 保存后 1.2 秒内、编辑器仍为脏时到达的文件事件

延迟 60ms 读一次磁盘（`api("open", live:false)`），按正文判定：

- 磁盘正文 == 编辑器当前正文 → 同文，采纳版本，不冲突；
- 磁盘正文 == 最近一次保存文本 → 是自己的保存，采纳版本，保持脏标；
- 其他 → 真实外部修改，显示冲突。

### 保存后 1.2 秒内、编辑器干净时

走原 `onExternalEvent` 路径：版本变化则静默 `loadFromDisk`；不吞外部内容，也不弹假冲突。

### 宽限期外

保持原逻辑，不依赖时间窗。

## 辅助函数

- `shouldVerifyExternalEvent(state, now)`：是否需要在宽限期内做正文核验（仅脏缓冲）。
- `externalDiskVerdict(diskText, currentText, lastSavedText)`：
  - `same`：磁盘与当前正文一致；
  - `own-save`：磁盘与最近保存文本一致；
  - `conflict`：真实不同。
- `lastSavedText` 在保存成功和 `commitApplied` 时写入。

## 测试

```text
npm test
tests 447, pass 446, fail 0, skipped 1
```

客户端测试覆盖：

- `same` / `own-save` / `conflict` 三分支；
- 保存中不核验、脏缓冲 + 宽限期内核验、干净缓冲不核验、超时不核验；
- BOM/CRLF 正文归一；
- 保存后 stat 版本变化仍先按正文采纳。

## 真机验证

外部脚本监听 README，保存后立刻 touch mtime，强制制造版本变化：

- 1.7.1/1.7.2：仍出现冲突横幅；
- 1.7.3：不再出现，但存在 1.2 秒时间盲区；
- 1.7.4/1.7.5：不再出现误报，且同一条事件路径改为正文核验（`externalDiskVerdict` 单测覆盖真实不同 ⇒ `conflict`）。
