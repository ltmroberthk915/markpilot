# 3.3.5：取消组字后的自动保存活性

旧 GLM 报告的函数模型在当前 3.3.4 宿主仍复现定时器耗尽。实际装机版、教材及当前设置的隔离副本：先原生输入 R、普通自动保存与 Undo 对照准确写盘，再 R 后 CDP 组字跨两个保存间隔，官方空串取消；单元格源码仍含 R，磁盘未含 R，dirty=true、capture 已恢复、没有保存定时器。正文对照会产生 change 而恢复，并未宣称相同故障。

Input.imeSetComposition 空串取消来自官方 CDP Input 协议。实际 compositionstart/update/beforeinput/input 为 trusted，取消 input.data 为 null，compositionend 为 untrusted。严格记录 Chromium CDP 范围，不宣称物理键盘或操作系统 IME。初版判据期待空 input.data，误报入口未确认；原收据保留，独立旁证修正，没有生成替代历史绿灯。

host.js 的 doSave 在 capture 暂拒时仅为非 force、当前 automatic 调用现有 scheduleSave，然后返回。取源码、保存正文、写入回执协议不变。复用已有配置间隔和策略/代际/错误/路径门禁；不增加逐键或滚动监听。持续组字最多一个定时器、每配置间隔一次常数检查，保存成功后干净停表。
