# 3.5.6 — 本机 PDF 导出阻塞隔离

## 目标与边界

本批处理大文档导出 PDF 时编辑器主进程被打印阻塞的问题。实际素材为本机《北交所博士后笔试-优化版.md》的只读副本：173,036 字节、78,056 UTF-16 字符、1,869 行，原件 SHA-256 为 `69d0c9adaba478d7c6e0e5107d462fbc0d5ba1cd5b312b10c0c5d50a660ab7a9`。真实硬件为 Intel Core Ultra 5 125H、24 GB RAM；全程在本机运行安装产物，独立 profile 与文档副本用于输入验证。

范围限定为桌面 PDF 生命周期、最终文件发布和对应原生辅助程序。CM6 引擎、字体、描边、KP 排版和 `export-pdf.js` 均保持原样。此前编辑器交互收尾项不因本批完成而视为关闭。

## 复现与判断

3.5.5 正常导出可以约 15 秒完成，不能只凭单次成功认定缺陷不存在。同一份 578,731 字节、SHA-256 `00f6b505a0675e90d12411cea72ade3fa15702fcc2ec1395ce05493001a6cfcf` 的打印 HTML，在 `warm-unicode-r1` 自然复现约 95 秒未返回的 `printToPDF`：主进程 CPU 约 91.84 秒，主进程 inspector 亦超时；系统仍有约 8.6 GB 可用 RAM，未触发测试内存限制。

KP 关闭、outline 关闭、额外 CSS 注入关闭，以及有限的字体就绪等待均未给出可靠因果修复。去除描边的诊断反而可触发阻塞，故没有用改变字体或页面外观换取通过。尚不能把底层问题断言为某个特定 Chromium 字体缺陷；本次交付的是独立 OS 进程隔离、可靠终止和事务发布。

## 实现

- `main.js` 在正常启动逻辑之前识别私有 PDF worker 模式；编辑器只收发阶段、取消和结果，打印不再共享编辑器主进程。
- `shell/pdf-process.js` 管理私有 staging、随机凭据、进度与结果认证、实际退出码和 Job 清空；流式核对 PDF 头尾、页数及摘要，再交现有 SafeFile 原子发布。worker 不接收最终输出目标。
- `shell/pdf-worker.js` 使用原有 `export-pdf.js`，独立 userData，原有排版与打印参数。
- `native/PdfWorkerGuard.cs` 在工作进程第一条指令执行前分配 Windows Job；硬限制 3 GiB，private 阈值 2.5 GiB，可用物理内存下限 3 GiB，打印期限 290 秒。取消、超时、内存阈值、父进程退出均结束本任务 Job，并确认没有残留 PID。保留真实父进程生命周期句柄，避免 PID 重用误判。
- 输出目标在短暂提交期间保留锁，核对已打开文档、进行中的 open/adopt、外部修改及取消时机。提交已经获准后报告 publishing；此前取消不会发布 PDF。
- 退出等待任务结束；Windows 临时目录短暂占用采用最多 5 次、每次 80ms 的有界清理重试。
- 原生辅助程序沿用短路径验证和 ACL/可信所有者/重解析点检查。LocalAppData 不合格时只尝试已存在且通过同一检查的 profile 路径，不修改系统 DACL。

## 验证

私有证据根：`.mp-verify/pdf-local-freeze-r1/`。该目录含文档/profile 私有副本，不进入 Git 或 Release。

1. 相关原生/文件发布测试及完整单元回归 270/270 通过。新增六条测试覆盖流式发布、末块取消、提交获准后的取消、外部目标修改、长叶名和 PDF 页数边界。真实源码突变退出 1，精确恢复后退出 0；`counter-nc.json` 记录源文件恢复摘要。
2. 最终候选同窗口连续三次导出 19.137 / 18.370 / 18.414 秒，每次 83 页、16,155,426 字节，主进程 heartbeat 最大 174ms。
3. 最终取消臂使用真实键盘、鼠标、组合键、键鼠配合和多步拖拽；标题原生选区 14 字。取消约 1,489ms，主进程 heartbeat 最大 203ms。原文、历史和最终目标均保持，Job 清空且 staging 删除。
4. 实际超时终止、模拟低可用内存的创建前拒绝、打印期间目标被打开而拒绝发布均通过。低内存臂没有消耗真实大量内存。
5. 20 秒同步阻塞只注入私有 ASAR 夹具：关闭隔离时真实输入超过 3 秒判红；精确恢复后同臂取消约 1,430ms、heartbeat 最大 198ms。原生 Alt+F4 关窗约 639ms 清空任务；另一个进程实际结束父进程后 guard 约 111ms 清空工作 Job。夹具从未进入交付包。
6. 全新的 DeepSeek 视觉会话 `session-42507165-26c8-4609-95a5-bb61b8172d0f` 实际调用五次 `read_image` 查看三页 PDF、打印中选区及取消状态；独立报告无新增视觉阻断。`ds-final-image-proof.json` 保留实际工具调用，不把静态截图当作性能证据。
7. 最终生产安装产物重新导出 18.432 秒，83 页、16,155,426 字节。逐 83 页 72dpi 光栅比较无差异，提取文字完全相同，文字摘要为 `6fb7c5410f73400438af19172610925575dc480d20a2bd9497afadf1f1d80863`。提取层的既有描边重复保留，不能把提取字符数当作源文字符数。

无效/失败的准备臂也保留：首次取消暴露 Windows EBUSY 后补充有界重试并同臂通过；首次 owner-close 探针持有 inspector 导致退出等待，脱离 inspector 后同臂通过；首个追加保存探针未验证末尾光标，文本预期差一个字符，没有用于通过结论，改为先断言实际位置 0 的前缀输入、精确 Ctrl+S、撤销与再次保存。此项不构成已证明的引擎修复，后续编辑队列应按实际末尾光标重新定位。
