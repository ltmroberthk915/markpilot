# 3.2.9 文档与连续编辑工作流记录

本批修复三个独立根因：打开另一文档时的历史污染、混合 HTML 多表粘贴丢失／错序、引用公式的点击源码坐标。源码候选、负控、交付边界使用合成文件及隔离 profile；正式安装状态以 [实装记录](verification/quality-3.2.9/installed.json) 为准。未推送、未发布。

## 产品行为

| 场景 | 问题与结果 | 实现边界 |
| --- | --- | --- |
| A 编辑后打开同内容 B；新建空稿；重新打开同路径 | B 曾继承 A 的 Undo/Redo，撤销会改写并自动保存 B。新文档现在从独立原生历史开始 | host 明确区分 replace 与 reload；replace 使用原生 EditorState，并保留当前配置、扩展及分屏。仅同文档刷新继续最小 diff 和原历史 |
| HTML 中的段落、两张表及包装节点混排 | 第一张表之外的内容曾丢失或移到错误位置。现在按 DOM 子节点顺序转换并整次撤销 | 一次 DOM 解析、共享行内转换；嵌套／合并等不支持的表整体保留纯文本，不返回部分表内容 |
| 点击引用、多层引用、多行公式字形及编辑浮层 | 去掉引用前缀后仍用连续偏移，点击可能进入错误源码行／字符。现在落在对应源码端点 | 每行稀疏 UTF-16 源码映射；正文与浮层使用同一映射，浮层失去当前 span 时不写选区 |

## 性能与限制

七档输入各 5 次预热、30 个有效样本，稳态 P95 为 19–24ms（含 CDP 传输与帧调度），满足本轮 50ms 预算。没有 Typora 对照，不由这些数据宣称行业领先。

55 万字符文档的 pending 引用回车内容正确，但首击约 308ms、稳态 P95 约 253ms；这是保留的性能问题，不能把套件语义通过当作流畅性通过。

操作系统输入法候选窗口、真实文件选择框和全部 Markdown 方言仍未穷举。Shift+点击公式字形、表格逐字 pipe 后的继续输入与格内历史属于下一批定向场景，不在本批成功结论内。

## 交付边界

正常 Setup、portable、唯一测试 appId 的 Setup 实际载荷均核对完整 ASAR、内层 EXE 和核心文件。隔离安装在含空格路径进行，卸载后核对原有两个安装项；正式升级前另备份当前程序、两个配置目录、四项注册信息及快捷方式。实际升级及主目标复验完成后生成公开实装记录，不能由“已打包”推成“已安装”。

重新执行时使用 [公开工具说明](../tools/quality/README.md) 中的命令，输出指向空的私有目录；完整安装器、profile、原剪贴板及机器备份不进入公开证据。
