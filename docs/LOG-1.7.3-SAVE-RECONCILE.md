# LOG 1.7.3 · 保存后“文件已在磁盘上更新”误报

## 症状

真机键盘输入后 Ctrl+S：

- 左侧显示“已保存”；
- 随即出现冲突横幅“文件已在磁盘上更新；点「重载磁盘版本」…”；
- 磁盘内容实际正确；
- 普通操作偶尔出现，第二次不一定复现。

## 定位过程

1. **保存后 stat 对账**：`runSave` 成功后用 `api("stat")` 比较 `version`；版本串含 `ctimeNs/mtimeNs`，元数据时序变化会与 `doc.lastVersion` 不同。旧代码只比版本，直接进入 `externalStale`。
2. 第一次修复（1.7.1）：版本不一致时读磁盘正文，正文相同才采纳版本。但实测仍失败——因为 **SSE 文件监听事件**先到，走另一条 `onExternalEvent` 路径，在保存中/刚保存后直接把 dirty 状态显示成冲突。
3. 第二次修复（1.7.2）：放宽文本比较，不再要求 stat 版本等于打开版本；仍失败，确认问题在监听事件路径。
4. 最终修复（1.7.3）：新增 `savedAt` 和 `SAVE_RECONCILE_GRACE_MS=1200`；保存中或保存成功后 1.2 秒内到达的文件监听事件直接忽略，交给保存后对账；对账再比较正文，只有正文不同才冲突。

## 最终行为

- 自己保存触发的 mtime/ctime 监听事件不会弹冲突。
- 保存后 stat 版本变化时，读磁盘正文；正文与刚保存文本一致（去 BOM/CRLF）→ 采纳新版本、清除冲突。
- 正文真的不同 → 原有冲突/静默重载逻辑不变。
- 保存期间到达的真实外部修改仍由保存 CAS / 正文对账兜底。
