# 3.3.6 PDF 导出生命周期

原始问题在正常安装的 3.3.5 上实测：HTML 已开始分块写入、finish 尚未开始时，真实点击取消，PDF 返回 ENOTEMPTY；再次清理记录 EPERM。原收据保留于 notes-save-liveness-3.3.4/export-two-frontier-first，未将失败改写成成功。

统一方案经不同代理只读对抗：PDF 会话保留唯一写流引用，独立于 finish 提前删除的 IPC Map；写入、完成、取消都按实际 open/close 收敛；取消先阻止新生产者再关闭并删除。本次补上非取消异常的 closing 入场保护，诊断保留文件仅影响删除，仍关闭生产者。

宿主把 make-html 的 PDF 会话编号传到引擎 pick/assets/begin。主进程同时验证编号、窗口归属和实际临时目录，拒绝旧任务借用下一次目录。图片复制停止领取取消任务，已开始的复制完成后再删除目录。HTML 的 head/body/tail 每次发送都检查实际回执，失败立即结束并 abort。

十项新增单元使用真实文件系统和写流；实际全量单元为 204/204 通过。pending write/finish 用例证明 API Promise 收敛，不宣称观察到特定内核写入阶段。

新增两个定向工作流：C2 原生取消、原生编辑/撤销/拖拽/Shift 扩选及同窗口重新导出；C3 双窗口 busy、归属拒绝、旧会话拒绝、另窗文件夹隔离、取消保留已有 PDF、另窗恢复导出与原窗历史。HTML 失败的诊断通知单独标明，真实渲染侧的迟到回复及写流均须完成后再检查目录消失。只读仪表返回原函数的实际值和同一 Promise，不引入延时或虚构业务成功。

首次 C3 的 More 入口被忙碌错误提示覆盖；保留失败记录，改为真人点击关闭提示后再进入 More。此处是探针入口修正，没有改变产品布局或强行穿透点击。

完整当前源码、探针、夹具、全部运行文件及 ASAR 成员由私有 fresh runner 绑定。最终回归、负控、载荷、安装及发布收据存于 pdf-cancel-lifecycle-3.3.6；未完成的阶段由原收据状态区分，不以本日志推定成功。

冻结程序的最终 39 组、481 项工作流已全部新鲜串行通过，原有 50ms 性能门槛保持通过；源文件、探针、运行文件和 ASAR 全成员在回归前后保持同一身份。新增真实写流测试连同现有单元共 204 项通过。

负控仅移除清理前等待真实写流关闭的一处 await，实际取消臂返回 ENOTEMPTY 并留下清理错误；精确恢复后，同一取消臂及双窗口臂均通过。取消时 writeEntered=11、finishEntered=0、pending=0，证明 HTML append 链内取消，不声称内核写入在途。独立视觉复核的五次图片读取均核验了成功图像回执，Root 实际看图并裁定报告，保留诊断光标和故障注入的解释边界。
