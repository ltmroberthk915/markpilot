## 三、没反应 / 行为不符预期的项

### ① 打字延迟随**总行数**近似线性增长（本族唯一"不能用"级现象）
100,000 行文档里**每敲一个字符卡 0.6–0.8 秒**：

- 逐键明细（30 键）：`454,455,456,457,458,460,472,…,572,588,592` ms（另一轮 `631.6 … 766.3`）——**不是首键慢，是每一键都慢**；P50≈P95（727 / 766）说明代价是**确定性**的，不是偶发。
- 归因：**事务落地延迟 P50 = 728.1 ms ≈ DOM 变更延迟 727.1 ms**（两条独立采样差 1 ms）⇒ 卡在**按键处理本身**，不是"字进了模型但没画出来"。
- 浏览器自报长任务：**45 条 / 30 键，最长 769 ms，合计 27.7 s**。
- 位置梯度（同一个 10 万行文档）：行 5 → **727.1 ms**；行 50,000 → **580.3 ms**；行 99,990 → **492.8 ms**（越靠后越轻，但都 ≥0.49 s）。
- 行数扫描（同一行格式，排除体积混淆）：1 万 49.4 / 2.5 万 168.8 / 5 万 339.0 / 10 万 727.1 ms ⇒ 约 **6.7 µs/行/键**。
- 用户可感：10 万行下 ≈ **1.4 字/秒**（5 万行 3 字/秒、2.5 万行 6 字/秒、1 万行 20 字/秒）；对照 500 行文档 3.5–5.0 ms/键。
- 该轮 30 键仍 30/30 真落字、逐键 `docΔ=+1`，画面最后与键盘输入完全一致（见 2 倍截图：第 5 行 `L000005 quabcdefghijklmnopqrstuvwxyz0123ick brown fox …`）——**是慢，不是错**。

### ② `Ctrl+Home` 回到顶部时有一次主线程长任务（≥2.5 万行才出现）
| 文档 | 长任务 | rAF 帧缝 |
|---|---|---|
| 500 行 / 1 万行 | 0 | 16.8 / 16.9 ms |
| 2.5 万行 | **96 ms** | 66.7 ms |
| 5 万行 | **203 ms** | 183.5 ms |
| 10 万行 | **282 ms** | 267 ms |

长任务与帧缝**同量级成对出现** ⇒ 回顶瞬间约 0.07–0.28 s 界面完全不动（滚轮、按键都会排队；同轮探针的 evaluate 往返在同一时刻被堵到 248–290 ms）。

### ③ 单行 50 万字符：每键仍有 0.06–0.07 s 级阻塞
P50 59.9 ms，浏览器自报 **36 条长任务（最长 73 ms）**；比同量级多行文档轻（1MB/7597 行 = 18.8 ms 且 0 长任务），但每条按键都掉 3–4 帧。

### ④ 尺子缺陷（非产品缺陷）：`PerformanceObserver('event')` 对这类代价没有鉴别力
同一批 30 个按键，`processingEnd − startTime` 读数恒为 **0.1–0.4 ms**（P50 0.3 ms），而真实代价是 **492–769 ms**。
⇒ 该尺子只覆盖事件监听器的派发窗口，**不含**事务与 DOM 更新；第二波 typing-perf-daily 用它当第二把尺子，在小文档上恰好与真实值同量级，**在大文档上会给出"打字很快"的假绿灯**。

## 五、明确为"好"的项（带读数）

1. **打开耗时与文档规模基本无关**：3.5 MB / 10 万行 → 1037–1224 ms 就绪（其中 Electron 启动到 CDP 可连 376–507 ms、磁盘读 36–45 ms）；500 行对照 578–649 ms。极值差 < 0.7 s。
2. **滚轮滚动全程不卡**：9 个夹具 **16 轮有效读数**，rAF p50 **16.7 ms**、max ≤ **17.2 ms**、**长任务 0 条**；每格位移精确 120 px（3 格逐格验证 120/120/120，另有连发段页内事件计数 20/20）。2.5 万行的文档滚动高度 630,457 px、3.5 MB 文档 2,514,399 px，均未见掉帧。
3. **`Ctrl+End` 一跳到底不卡**：10 万行（scrollHeight 2,514,399 px）0 长任务、帧缝 16.8 ms、`atBottom=true`。
4. **内存不失控**：单实例基线 **460.7–522.6 MB**（4 进程：main 133–143 / renderer 145–193 / gpu 150–178 / utility 87–89）；滚到底+回顶+30 键后 **491.7–672 MB**（最大增幅出现在 10 万行：+143 MB，renderer WS 峰值 289 MB，JS 堆仅 30 MB）；无 OOM、无进程被杀、无持续增长迹象。
5. 1000 张图 / 500 个表 / 单行 50 万字符三个极限形态**都能正常打开与编辑**（打字 6.5–59.9 ms），无一崩溃。

## 六、未验证项（不许当通过）

1. **每键代价的成因**未验证：只测到"随总行数近似线性"与"随光标位置越靠后越轻"两条相关，**未读码、未做 CPU profile**，不给出机制结论。
2. **`Ctrl+Home` 落在 `scrollTop = 6–9`（不是 0）**：9 个夹具（含 500 行对照）完全一致 ⇒ 与文档大小无关；是"到不了 0"还是"顶部本身留 6–9 px"**未验证**（要再发一次"到顶后再滚一格"的定向实验）。
3. **长期稳定性**未验证：每夹具只跑 1–2 次；分钟级连续打字、长时间驻留后的劣化未测。
4. **真实物理键盘 / IME**未验证：本机为 CDP 合成键（中文 IME 候选窗路径不在本族范围）。
5. **内存口径**只测 WorkingSet（进程树合计），未测提交内存/私有字节；未做小时级长驻。
6. **本机负载混杂**：运行期间有 16–44 个别族 MarkPilot 进程，绝对毫秒数含这部分争用；同一轮内的相对比较（同一尺子、同一夹具、同一顺序）仍成立。
