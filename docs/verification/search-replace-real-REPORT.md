## 一、没反应 / 行为不符预期（6 条）

### 1. ★ 表格里的查找命中：没有高亮，跳过去也看不到选区（用户零反馈）
- 读数（词 `命中`，9 处）：引擎命中 9、DOM 高亮**只有 5 个**；落在表格里的 2 处 `isReplaced=true`、`domHighlighted=false`。
- 逐跳 10 次（回车）：第 4、5 跳（表格 `表格命中四`/`表格命中五`）`selMarks=0`、`domHighlighted=false`、光标坐标 **x=994**（正文列范围 148–1018，即被画在正文列最右缘，不在表格里）；第 6/7 跳（行内公式 / 块公式）**选区高亮=1**（跳转后源码露出，可见）；第 8 跳（代码块）、第 1–3/9 跳（正文）高亮=1。
- 专查表格词 `表格命中四`：引擎 1 命中、选区确实变成 `表格命中四`（from 68–73），但 `marks=0`、`selMarks=0` —— **文档位置对了，屏幕上什么都没变**（唯一可见变化是表格浮动条出现）。
- 证据：`shots\find2-b2-table-full.png`（查找框里是"表格命中四"，表里那格没有任何高亮）、`shots\find2-b0-all.png`（9 处命中只有 5 处有琥珀色高亮：正文 3 + 代码块 1 + 正文 1）。
- 成因（读产品代码，只读）：表格行是 `Decoration.replace({widget, block:true})` 整行替换（`src-cm6/main.js:2062`），注释写明"行源码永不露出"，且该装饰 `compute(["selection", …])` **不随选区露出源码** ⇒ 搜索用的 mark 装饰落在被替换区间里画不出来；公式/代码块/正文不受影响。

### 2. ★ 面板的查询只认 keyup：字段里有字，引擎却没提交（无高亮、无命中数）
- 通道校准读数（词都在输入框里显示）：
  | 通道 | 输入框 | 引擎查询 | 命中数 | 事件 |
  |---|---|---|---|---|
  | Playwright `keyboard.type('命')` | `命` | `""`（valid=false） | null | 只有 `beforeinput`/`input`，**无 keydown/keyup** |
  | CDP IME 组字 + keyUp | `命中` | `命中` | 9 | composition*×4 + `keyup: ` |
  | 上一条之后补按一次 ArrowLeft | `命中` | `命中` | 9 | 补出 `keyup:ArrowLeft` |
  | 组字提交、**不发 keyUp** | `命` | `""`（valid=false） | null | 只有 composition*，无 keyup |
  | 之后随便按一个键（Esc） | — | `中` | 11 | 补出 keyup 才提交 |
- 判据（用户可见）：输入框里有字，正文里**一处高亮都没有**、回车也不跳；再按任意一个键才"突然"全部生效。
- 真实中文输入（IME 组字 + 空格/回车上屏）有 keyup ⇒ 正常；**"鼠标点候选词上屏"是否产生 keyup 取决于输入法，未验证**（见六）。
- 这一条同时是**尺子结论**：本族第一版探针用 `page.keyboard.type` 打中文，读出来"引擎命中 null、回车不跳"，差点写成产品缺陷（见五·尺子修正）。

### 3. ★ 替换全部后，在查找框 / 替换框 / 按钮上按 Ctrl+Z 撤销不了文档（上一轮 P2-9 仍复现）
- 全部替换后 docHash = `-303233011`（9 处 `命中`→`锁定`，逐字等于期望，磁盘 == 内存）。
- 焦点在 `replace all` 按钮上按 Ctrl+Z：docHash `-303233011` **不变**。
- 点进**查找框**按 Ctrl+Z：docHash 仍 `-303233011` **不变**（另一次运行：`880662123` 不变）；点进**替换框**按 Ctrl+Z 同样不变。
- 点回正文按 Ctrl+Z：**一步整体回退**到替换前（docHash 回到 `-38044074`），再按一次 Ctrl+Y 又能整体重做 ⇒ 历史项粒度是对的，只是面板内的 Ctrl+Z 到不了文档。

### 4. 第一次点「replace」不改文档，只把选区放到命中上（与 Typora 习惯不同）
- 读数：查找 `命中一`、替换词 `锁定`，文档 195 B；**第一次**点 replace：文档 195 B 不变、选区变成 `命中一`（rank 0）；**第二次**点：195→194 B，`命中一`→`锁定`（3 字换 2 字）。
- 判据：输入查找词后点一次「replace」，用户的直觉是"替换掉了"，实际只是跳过去；要再点一次才真替换（CM6 原生 `replaceNext` 语义）。

### 5. 在替换框里按回车不替换，只跳到匹配
- 读数：查找 `命中二`、替换词 `锁定二`，焦点在替换框（`isReplaceField=true`），按回车前后 docHash 都是 `-38044074`（**文档没变**），但选区从空变成 `[27,30]`=`命中二`。
- 判据：在替换框里输好替换词按回车 —— 文档没动（Typora 用户会以为替换了当前项）。

### 6. 顺带观察（归属未深究，不计入本族缺陷）：公式源码露出时，渲染的公式浮层压住代码块
- 查找 `命中七` 回车后，块公式源码 `$$ \frac{命中七}{2} $$` 露出且命中高亮可见（正常），但同一屏里渲染件（`.mp-inline-float`）落在源码下方、与代码块 `const tag = "命中八";` 区域重叠。
- 证据：`shots\find2-b3-mathblock-full.png`。是否属于"露出态布局"缺陷需公式族判定。

## 五、尺子修正（避免把自己的测量误差当产品缺陷）

1. **中文不能用 `page.keyboard.type` 打**：Playwright 对无键位映射的字符只发 `Input.insertText`（无 keyup），而面板查询是 keyup 提交 ⇒ 第一版 `search-replace-real-find.cjs` 读出"引擎命中 null / 回车不跳 / 表格词 0 命中"三处假红。已改走 IME 通道（`imeSetComposition` + `insertText` + `keyUp`），并加 29 条"字段=引擎=目标词"自证；第一版读数全部作废（保留文件与 JSON 以便对照）。
2. **同长度替换不能用 docLen 判撤销**：`命中八`→`锁定八` 长度不变，`docLen` 恒定 194 ⇒ 第一版判"A6b 撤销无效"。改用 `docHash` 后读数正确（撤销前 `-691675858` → 撤销后 `1779684407` = A4 之后）。
3. **期望值手写错 1 处**：A1 已把替换词设成 `锁定`，替换一次的结果是 `命中一`→`锁定`（不是 `锁定一`）。已按夹具字符串重算。
4. **无鉴别力的用例要标出来**：phase B 的 B8（正则 `$1`）因前一步 Ctrl+Y 重做把文档恢复成"全部锁定"，前置命中数 = **0**，替换是空操作，"逐字等于期望"是平凡真。真判据改到 phase C 的 C1（**前置断言命中数 = 3**）。
5. **跨实例串台防护**：端口是全局共享资源，本波次别的族在用 9633/9792/9974/17612。加了 `launchVerified()`：连上 CDP 后必须断言"装载的文档逐字等于我的夹具"，否则换端口重来（读数里 `verify[].ok=true` 可查）。第一轮曾有 1 次 phase B 页面被外部杀掉（shell trace 停在启动后 0.3 s，`main-debug.log` 无任何退出记录 ⇒ 判定为外部 `taskkill`，非产品崩溃）。

## 六、未验证项

1. **真实物理输入法的"鼠标点候选词上屏"**：CDP 模拟的"组字提交无 keyup"路径确实读成"引擎不提交"（见一·2 第 4 行），但真实输入法该路径是否产生 keyup **未验证**（本机锁屏、无物理 IME 通道）。
2. **突变验证未做**：本族是普查、且任务书禁止改产品代码 ⇒ 对"已修项"（P1-1/P1-3）只做了最终状态复验，没有"注掉修复看是否转红"的突变证据。
3. **表格内命中的高亮**只在本夹具的 2 列表格上取证（居中表格、宽度 ~800 px）；不同列数/窄窗口下的光标 x 坐标未穷举。
4. **剪贴板**：本族无跨系统剪贴板用例（锁屏态不影响本族任何判据）。
