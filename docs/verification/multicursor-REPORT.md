### ⚠️ 一处待复测的疑点：**Ctrl+C 多选区复制，`clipboardData` 里只有第一段**

### 多光标粘贴多行（**逐行分发**）

四步齐全（装弹 → 独立进程回读 → 按键 → 再回读），两组独立回读**都等于本载荷**：

| 光标数 | 载荷行数 | 载荷 | 文档前几行 | 判定 |
|---|---|---|---|---|
| 2 | 1 | `A1` | `A1AAA… / A1BBB…` | 逐行分发 ✓ |
| 2 | 2 | `B1\nB2` | `B1… / B2…` | 逐行分发 ✓ |
| 2 | 3 | `C1\nC2\nC3` | `C1 / C2 / C3…` | 逐行分发 ✓ |
| 3 | 2 | `D1\nD2` | `D1 / D2…` | 逐行分发 ✓ |
| 3 | 3 | `F1\nF2\nF3` | `F1 / F2 / F3…` | 逐行分发 ✓ |
| 3 | 4 | `G1..G4` | `G1 / G2 / G3 / G4…` | 逐行分发 ✓ |
| 4 | 4 | `J1..J4` | `J1 / J2 / J3 / J4…` | 逐行分发 ✓ |
| 1（对照） | 3 | `U1\nU2\nU3` | 整块贴到单光标处 | 正确 ✓ |

**规律（定向枚举得出）**：`粘贴行数 == 光标数` ⇒ 一光标一行；
`行数 ≠ 光标数` ⇒ **整块载荷贴到每个光标**。两条都不是"没反应"，与 CM6 上游语义一致。

## 3 探针自身的错误（本轮最重要的一条，必须留档）

**v1 的 `multicursor-paste-enum.cjs` 用空尾行做落点，导致 `Ctrl+Alt+↓` 根本没落光标**，
七格全部在**单光标**上量出来，却打印成"整块贴到每个光标"。
自证：那七格的 `粘贴前选区数` **恒为 1**（本该是 2/3/4）。
这一条同时**回溯解释**了 `multicursor-clip.cjs` 的 C7 异常读数（"4 光标粘贴 4 行 ⇒ 整块"）。

**v2 的对策**（已落地）：落点改用**有字的段落行**；每加一次光标都断言选区数真的涨了
（staircase 自证）；判据只在"光标数 == 目标"时才成立。
v2 的 `E1 staircase 自证`：二光标 `[1,2]`、三光标 `[1,2,3]`、四光标 `[1,2,3,4]`，全部 ok。
v2 七格全部 **四步 ok、尝试 1 次、抢占 0 次**。

**其它探针错误**：
1. `MP_EXPECT_EXE` 必须**小写**（`assertExe` 大小写敏感），大写会 exit(9) 拒绝出数。
2. 截图叠加标记必须乘 **DPR=1.75**（PNG 是设备像素、引擎坐标是 CSS 像素），
   否则红线画偏约 30 设备像素（v1 就偏了；v2 修正后每光标红线像素数恒定 116）。
3. `clip.diag()` 在剪贴板被别的族抢占时会误报 `available:false` —— 它是**环境争用探测器**，
   不是产品判据，报告里不能拿它当"剪贴板不可用"。

## 4 剪贴板争用（错-13 实战）

本机**同时有别的族在跑并抢系统剪贴板**（实测读回 `MPCC-SENTINEL-ASCII-0123456789`、
`MPCC-A\x1bB\x07C-END`、`中文·哨兵·单行`、`姓名\t数量\n甲\t1\n乙\t2`、`MP-WC-SENT-13144-1-9n67`、
`MPCC2-NUL[`、`👨‍👩‍👧`）。同类实例：`print-daily`、`drag-move-text`、`control`、`rich-pa*`。

- 第一轮 B6/B7/B8 的 ④ 回读不符 ⇒ **判被抢占、读数作废**（已在 `multicursor-clip-retry.cjs` 重跑通过）
- 重跑时把抢占做成**硬条件 + 自动重试**：C6 尝试 2 次（换手被抢 1 次）、C7 尝试 4 次（被抢 3 次），
  最终两组回读都等于本载荷，才采信
- C1（多选区复制）即使重试也拿到外部载荷 ⇒ 按纪律**不采信**，见 §1 疑点
