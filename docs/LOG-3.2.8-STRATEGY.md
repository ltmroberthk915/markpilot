# 3.2.8：修复时效复盘与后续执行规则

## 已测到的时间与主要损失

本次最终七套源码回归 179 项耗时 4.32 分钟，最终图片专项 42 项耗时 3.71 分钟，13 类真实突变对照耗时 6.24 分钟，便携、隔离安装与正式安装的交付边界复查共耗时 3.98 分钟。原始起止时间及计算来源见 [iteration-timing.json](verification/quality-3.2.8/iteration-timing.json)。这些是套件执行时间，不能用它们推算编码、分析、模型审阅、打包及安装恢复各自占比，也不能把未计量的时间全部叫作浪费。

主要策略损失有五项：

1. **最有代表性的场景验证过晚。** 短合成文档已经出图后，才在 9 MB 文档副本及快速 Ctrl+End→Ctrl+V 中发现图片高度变化导致视口只露出约 31px。前面图片专项变绿，仍未回答真实操作是否可用。这一场景应进入第一次复现及每次定向复验。
2. **较小修改反复触发大范围验证。** 修改图片格式、文档身份及插入事务期间，多次启动整套图片用例；随后又加入视口修复，改变已经审阅的引擎。部分重验因产物确实改变而必要，但冻结太晚使这些成本连成关键路径。修改中先跑失败臂及依赖边界，冻结后再做一次最终回归。
3. **探针自身的隔离和判据问题发现过晚。** 复用编辑器的 `setValue` 保留了旧撤销历史，待写图片取消用例曾只断言“没有图片”，遗漏前一夹具的文本回流。独立历史、准确的终态及动作确实发生的证据，应先于大批 GUI 测试。
4. **安装器前提没有提前验证。** 正常 Setup 与已有安装共用身份，含空格的 `/D` 参数还被再次解析。错误安装后恢复两套程序增加了交付时间和操作风险。唯一 appId、含空格的真实安装/卸载及原注册项核对，必须先于正式升级。
5. **范围、报告和协作未围绕一次交付收敛。** 测试逐步增加后，报告与审阅随之扩展，核心问题达到可验证状态后仍没有清楚的冻结点。新发现应先判断是否阻断主目标；队友交付应以裁定、反例、证据路径和修改建议为主，避免反复全文解释。

缩短时间的重点是提高第一次复现的代表性、提早验证交付前提，以及减少重复启动和重新审阅。真实输入、保存安全、图片字节、可见结果和能检出缺陷的失败对照继续保留。

## 每批修复如何推进

每批先写一张简短任务卡：一个用户可见的主目标、精确复现动作、成功判据、涉及的依赖边界、必跑用例和暂不纳入的相邻问题。相邻问题只有会导致数据丢失、主目标仍不可用或当前修法必然破坏既有行为时，才并入本批；其余记录为下一批。不能把一个仍有阻断缺陷的主目标标为完成。

| 阶段 | 工作与退出条件 |
| --- | --- |
| 复现 | 当前实际安装产物、真实操作、文档和 profile 的隔离副本；先测实际文档长度、目录和操作位置。保留基线画面、真实输入和最终状态。 |
| 定位与对抗 | 主控定位修改边界；按现有六步流程获取方案及独立反例。一次提交明确的问题、源码片段和少量关键帧，争论围绕可复现反例。 |
| 快速循环 | 先跑相关单元/实际函数模型，再跑失败 GUI 臂、成功对照及紧邻边界。失败时先停下本套件分析；独立检查仍可继续。 |
| 判据核验 | 新探针先证明动作生效、状态隔离；每个独立修复根因至少一条真实突变红→精确恢复→同臂绿。一个根因的等价形态可共用代表性负控，不同根因须分别验证。 |
| 冻结与最终检查 | 冻结源码、夹具、探针及构建产物。按下表选回归；交互修改保留五通道和视觉复核。当前完整七套回归只需约 4.3 分钟，涉及共享核心时直接完整跑一次。 |
| 打包与交付 | 构建一次、核对三种实际载荷，先验证独立身份及含空格安装路径，再备份正式环境、升级并做针对安装边界的真实复查。 |

“冻结”后出现确证阻断问题，重新打开对应修改边界，并使受影响证据失效。纯报告、版本说明及路径整理不引发无关产品重测；产品代码、资源、运行条件或探针变化则按依赖重新选测。

小修以 15～30 分钟获得可信定向结果、30～60 分钟完成一批交付为调度目标。它们是检查点，不能靠删判据或掩盖失败实现。10 分钟仍不能稳定复现，先修观测手段；30 分钟仍在扩展范围，主控必须重新收敛主线；超出交付目标时报告具体阻断事实及下一个能排除它的动作，继续推进。

## 如何选择测试

| 修改边界 | 本批必须覆盖 | 何时扩大 |
| --- | --- | --- |
| 局部图片扫描、投影或菜单 | 原始故障、起止边界与源码内部、第二张图、实际大小变化；键盘/鼠标/组合键/键鼠配合/拖拽；关键帧和相关负控 | 影响共享装饰、选择、文档变更映射时，加入编辑和 Worker 集成回归 |
| 异步插入或文档身份 | 继续输入、撤销、重载、切文档、并发请求顺序；真实最终文本及宿主归属；实际函数时序模型 | 涉及启动、保存回执或共享会话协议时，增加完整 data-safety 与 critical |
| 文件、图片源或编码 | 实际落盘字节、不可写回退、同名不覆盖、所属文档目录、复制/另存独立回读 | 涉及通用写入或编码边界时，完整数据安全与编码回归 |
| Parser、共享编辑命令或热路径 | 编辑方言、Worker 集成、错误降级和相应性能指标 | 影响多种编辑操作时，完整七套回归；结构命令单独量时，不能用普通字母延迟替代 |
| 打包、安装或运行时 | 实际 EXE/ASAR/资源身份、启动、真实目标路径、保存/重开、主目标复查、既有安装保护 | 运行时、依赖或资源改变时，重新选取功能和性能回归 |
| 文档、流程或测试工具 | 文档链接/保留规则；工具行为改变时跑针对性工具自测 | 工具改变判据或夹具时，相关产品证据重新验证 |

默认正常操作先用真实时序。图片快速粘贴显式使用 `--image-delay-ms 0`；人为五秒延迟只用于需要稳定制造竞争的定向用例。当前 `images.cjs` 整套仍默认五秒，不能把整套改成零延迟而让取消/顺序竞争用例失去鉴别力。后续按用例配置延迟时须保留这些负控。

## 证据复用与协作规则

- 证据复用至少核对完整应用及资源 ASAR、运行时、探针和夹具、关键环境条件（profile 前提、窗口/缩放、输入方式）。七个核心文件 SHA 或版本号相同，单独都不足以证明可复用。失败、过期或条件不明的结果不能复用。
- 包装元信息或安装位置变化有明确证明时，复用已经冻结的功能证据，同时补做相应交付边界；不宣称不同 EXE 完全相同。改变渲染资源后，即使 JavaScript 相同也要重测相关视觉性质。
- 当前报告还没有统一记录探针/夹具/全部环境的复用键，暂不能自动判定旧结果有效。先按上述条件人工核对并写明依据；若实现复用工具，必须验证“输入变化会使旧结果失效”。
- 频繁定位优先用实际函数模型，真正的输入、宿主和可见结果仍由 GUI 判据负责。已核验的运行时及一次性副本可复用；最终包装与正式安装验收保留。避免每次诊断都复制整个 Electron 或生成三个安装器。
- 无 GUI 的源码分析、模型及准备可并行；GUI 和性能测量期间不混入构建或重 CPU 校验。主控是唯一键鼠、剪贴板和安装操作方；助手负责只读反例和证据审阅。
- 视觉助手先给裁定和确证反例，再附关键帧。通常先提供 6～12 张覆盖被改性质的关键图；遗漏的性质需补图，不能为满足张数省掉必需证据。每次操作的取证帧仍保留，已核验的相同图和不变行为不反复撰写长报告。
- 每轮结束保留交付物、小型证据和必要恢复备份；清除自己的临时进程、profile 和无用大文件。清理只能触及已确认归属且位于私有工作目录的目标，不能为省时跨过路径和归属检查。

## CM6 与旧技能的适用范围

v3 的引擎事实源是 `dsh-markpilot/src-cm6/`，桌面壳是 `MarkPilot-CM6/`，当前受控构建入口是 `build-from-source.cjs`。先确认实际 Git checkout、package 版本、运行时及入口；旧技能里的 Vditor IR、双仓同步、VSIX 打包及旧 IDE 套件只在对应 v2/扩展任务适用，不能直接作为 v3 的全量流程。真实输入、独立反例、视觉核验、哈希链和用户内容保护继续适用。

本次策略落地修改项目约定和说明，新增由既有公开结果计算的时间清单；没有借此扩展编辑器改动或重新打包。后续先观察每批“首次复现→定向通过→冻结→实装”的耗时和重验原因，再决定是否新增调度工具。
