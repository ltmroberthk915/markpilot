# MarkPilot v3 设计宪法（2026-10-06 立法）

> 两条根本法，一切 v3 设计决策的裁决依据。与 3.0宪法.md（零补丁原则详版）互为总分关系：
> 本文是法条，彼文是判例集。

## 第一条（架构级避免补丁）

**任何缺陷的修复与任何能力的实现，必须以系统级架构容纳；禁止在架构之上打点状补丁。**

裁决规则：
1. **补丁的判定**：一段代码若只对「某个症状的某个触发形态」生效、而同类根因的其他形态仍会复发，
   它就是补丁——无论写了多少行。判例：2.x 的 23 条 A 挂账里，绝大多数的根治方案都是 S1/S2/S4
   架构件（影子锚层/输入事务/展开态单源），而不是更多 if。
2. **架构的判定**：一段代码若让「整族问题在结构上不可能发生」（而非「被正确处理」），它才是架构。
   判例：iframe 整装让「插件与宿主 DSH 的键鼠/焦点/崩溃冲突」整族消失，不是被处理掉。
3. **落地门（强制）**：v3 起每个修复/特性在方案评审时必须回答两问——
   - 这个修法让哪些**未报告的同族形态**同时不可能？（答不出＝补丁）
   - 这个修法在 [根因树]（rct-input-compact.json）里落在哪棵树、哪个架构件上？（答不出＝没想清楚）
4. **既有补丁的处置**：v3 的自研引擎核（CM6 基座，C1 路）不迁移任何 2.x 补丁——只迁移**判例**
   （根因树、DNA、场景门）。2.x 补丁清单是需求清单，不是代码清单。

## 第二条（性能效率全面超越 Typora）

**插件的每一项性能指标必须全面超越 Typora 桌面版；不允许任何单项「持平即可」的豁免。**

裁决规则：
1. **测量面（九轴）**：启动至可打字、大文档（≥20万字符）滚动帧稳定性、键入到渲染延迟、
   IME 组字延迟、全文档搜索、大段粘贴、撤销栈深度与延迟、常驻内存、文件保存 RTT。
   DSH 形态再加三轴：**tab 首开延迟、守卫保存往返、Agent 改动回推可见延迟**（agentic 原生特有）。
2. **对标纪律**：九轴每一轴都要有 Typora 同机实测数与本产品实测数，成对入表；没有 Typora 数
   的轴不允许宣称超越。Typora 以 `--remote-debugging-port` 起 CDP 用同一套探针测。
3. **预算制**：每轴定预算（超 Typora 的量化幅度），探针固化进验收场景；回归即红。
   大文档轴的预算参考既有事实基线（2.x 场景 60：181 帧 p50 16.7ms 零掉帧；fast-type-gate 4ms；
   cvFirst 20万字符首屏）——这些是 2.x 已兑现的底，v3 只许更好。
4. **效率的含义包含「不浪费」**：轮询频率、内存驻留、无效渲染都计入。判例：v0.1 的 1.5s 轮询
   是权宜，v3 必须换成事件推（架构级：宿主 fs watch → 客户端事件 → 面板），这是第一条与第二条
   的交汇点——事件推是架构，轮询是补丁。
