# 踩坑编年史（v2.0.1 交付 session 全记录）

> 收录标准：**所有让交付变慢的点**——bug 根因、验收误报、工具链死路、流程绕弯，每条附「代价」与「本应」。
> 阅读方式：当同类问题再出现时，先在这里找对照，避免二次付费。

## 一、问题受理与定位

### 1. 大纲功能验收误报（本 session 最贵的一课）
- **现象**：用户截图证明 Trae 里大纲根本没生成，而此前结论是"验收成功"。
- **根因**：冒烟断言只走命令/状态桥（executeCommand + webview 状态查询），从未断言真实 workbench DOM。命令能执行 ≠ 面板真的渲染。
- **代价**：用户信任受损；后续所有验收都要补"真实 DOM + 真实输入"税；重新设计断言 + 重跑全部 IDE 任务。
- **本应**：第一天就用真实 DOM 断言——比返工 + 重建信任便宜一个数量级。

### 2. Trae 不渲染 explorer 容器的树视图
- **现象**：同一 VSIX，VS Code 有大纲、Trae 完全没有。
- **根因**：Trae（字节分叉）不渲染 `views.explorer` 树视图贡献，静默无报错。
- **代价**：先按 VS Code 行为调试了一轮，才想起分叉差异要用目标 IDE 实测。
- **本应**：目标 IDE 兼容性问题，第一步就在目标 IDE 上复现（fresh dev-mode 隔离实例对比一次即定位）。

### 3. 清单键名拼错被静默忽略
- **现象**：`viewContainers`（少个 s）不报错，VS Code 静默回退 Explorer，只留一行扩展宿主日志警告。
- **代价**：差点把"落在 Explorer"当成"新容器生效"，二次误判。
- **本应**：清单类改动，断言"效果落在预期容器"，而不是"有东西渲染出来就行"。正确键名 `viewsContainers.activitybar`。

### 4. 弹窗卡工具栏根因
- **现象**：补全锚点滚到可视区上方时弹窗停在工具栏；滚到下方正常。
- **根因**：v10 `position()` 的 `Math.max(8,…)` 顶部钳位不区分"光标离屏"与"光标在视口内但靠上"。
- **定位方法**：桌面测试新增几何用例（60 段长文 + 驱动滚动 + 断言弹窗/工具栏 rect 关系），一次跑出因果。

### 5. 滚动容器认知错误（测试侧）
- **现象**：CDP wheel 滚不动；`querySelector('.vditor-reset')` 的 scrollTop 永远 0。
- **根因**：DOM 有多个 `.vditor-reset`（隐藏副本）；IR 模式根 `editor.ir.element` 本身就是 `pre.vditor-reset`（滚动器+contenteditable 二合一），`.vditor-ir` 下没有它的后代。
- **代价**：多轮"换元素试滚动"的盲试。
- **本应**：先在桌面探针里打印实际 DOM 结构（`.vditor-ir` sh==ch、pre sh 2487>ch 616 一眼定位），再写用例；滚动后必须断言 scrollTop 变化。

## 二、修复方案迭代

### 6. 三个"更彻底"的重写方案全部打破嵌套公式测试
- **现象**：画布∩视口全面夹取、rAF 合帧滚动重定位、"视口内钉住不跟随"，逐个让嵌套公式套件失败。
- **根因**：360px 弹窗在滚动后于新位置展开，盖住公式 1 点击点 (576,411)，弹窗按钮吞掉点击（诊断：`popupAtClick` 覆盖点击点、`popupAfter:null`；负载高时还有 `popupAtClick:null visible:[]` 的时序变体）。
- **代价**：每轮方案一整套测试周期 ×3，是本 session 最大的时间黑洞之一。
- **本应**：先二分证明因果（2.0.1 + v10 completion.js 单变量对照），再收敛最小 diff（历史翻转语义逐字节保留 + 硬边界 + 离屏随行）+ CSS z-index 硬保险。对敏感几何代码，"改得少"就是"改得对"。

### 7. webview 里 console.log 不可见
- **现象**：想看 position() 实时值，日志完全打不出来；`window.__posdiag` 方案也失败。
- **根因**：webview 的 console 不进扩展宿主输出。
- **本应**：直接测试侧插桩——让 `nestedPoint` 返回点击瞬间的弹窗 rect，一次跑完拿全因果链。

### 8. 用户架构建议的落地翻译
- **现象**：用户建议"弹窗放文本层、工具栏放上一层"，字面执行不可行。
- **根因**：滚动器就是 contenteditable，注入弹窗节点会被 DOM→Markdown 序列化损坏。
- **本应**（也是最终做法）：把用户直觉翻译成宿主约束内的等价物——画布夹取 + 离屏随行 + `.vditor-toolbar{z-index:1001}`。不要字面照搬，也不要直接说"做不到"。

## 三、验收测试编写

### 9. 树行单击/双击语义
- **现象**：单击只产生选中态（aria-selected:true），reveal 不触发；连续两对普通 click 也不生效。
- **根因**：树条目命令绑定在双击/激活上；CDP 合成双击必须第二对 mousePressed/Released 带 `clickCount:2`。
- **本应**：记住工作序列：`mouseMoved → click(1) → click(2 with clickCount:2)`。

### 10. CDP 上下文掩蔽（假阴性）
- **现象**：扩展侧命令日志打了 `[reveal-cmd]`，测试读 webview 标记却恒为 null。
- **根因**：`inWebviewTagged` 取"第一个不抛异常的上下文"——那是旁观上下文，自然没有标记，真正的编辑器 webview 被掩蔽。
- **代价**：长链路排查（一度怀疑产品代码）。
- **本应**：多上下文环境从第一天就"遍历全部上下文 + 时间戳最大值为基线"（即 `anyReveal()` 模式）。

### 11. 产品侧 reveal 守卫被防抖刷新打破
- **现象**：偶发点击无效。
- **根因**：守卫用对象同一性 `flat[node.index] === node`，250ms 防抖刷新会在渲染与点击之间替换节点对象。
- **本应**：防抖数据结构上的身份判断一律用语义键（行+文本）。

## 四、版本与打包

### 12. 版本号混乱（用户点名）
- **现象**：历史交付版本号不递增、多处漂移。
- **对策**：第三位递增政策（本轮 2.0.1 → 2.0.2…）；版本贯穿两仓 package.json、VSIX 清单、文件名、dist 目录、验收断言，全部单一来源（package.json）。
- **坑**：verify 脚本硬编码 2.0.0 直接断言失败——硬编码版本号迟早咬人。

### 13. VSIX 清单字节级一致性
- **坑**：`<Identity Version>` 手工同步会漏；写回时 CRLF→LF 改变字节，导致 VSIX 内字节与清单文件对不上。
- **对策**：pack.py 自动同步版本并以 `newline=""` 写回保持 CRLF；verify 用「桌面源码 = app.asar = VSIX」三方逐文件哈希断言。

### 14. Trae 命令行装扩展会转发给真实实例
- **风险**：Trae 运行中 `--install-extension` 转发给用户正在用的实例，等于动用户环境。
- **本应**：永不使用；测试走 `--extensionDevelopmentPath` + 隔离 profile；指导用户从命令面板"扩展：从 VSIX 安装"。

## 五、全量验收执行

### 15. 并行负载毁掉 GUI 轮次
- **现象**：GUI 驱动跑着的同时并行后台 Node 套件，CDP 打字丢字（`null !== '事件🙂集合'`）。
- **代价**：整轮 GUI 任务重跑（每轮分钟级）。
- **本应**：GUI 验收期间零并行负载是铁律；无 GUI 校验批量先跑。

### 16. 三类已知抖动（复跑即过，必须披露）
- profile UI 2.5s 等待超时；Trae 遥测噪声（volo/icube 超时）+ 一次 `visible:[]`；workflow-gaps 的 SV undo 时序（历史已知）。
- **本应**：抖动分类记录在案，复跑通过后写进报告披露，不静默吞掉。

### 17. 遗留测试实例引起用户误会
- **现象**：用户看到屏幕上出现大纲面板，以为新功能已就绪——实际是遗留的测试实例窗口。
- **本应**：测试实例用完即关；屏幕上任何不该存在的窗口都会消耗用户的注意力甚至误导判断。

## 六、会话崩溃与恢复

### 18. 远程图片分析链路是单点故障（崩溃直接原因）
- **现象**：截图分析依赖"上传 CDN → 远程模型读 URL"两跳。路径带反斜杠被拼坏 → 400「图片输入格式/解析错误」；最终一次 DNS 解析失败（temporary DNS server 8.8.8.8 exceeded retries）把会话卡死崩溃。
- **代价**：整个会话尾部 + 恢复对账成本。
- **本应**：图像验证先备本地退路（curl 下载、像素统计）；远程分析只当加速器。判断"内容是什么"可用，反推坐标不可用（见 19）。

### 19. 图标坐标用图像分析反推——反复漂移
- **现象**：按截图比例估算活动栏图标坐标，连错数次，每次都是"点击+等待+截图+分析"一整轮；命令面板兜底又发现 `<id>.focus` 自动命令不显示。
- **本应**：坐标一律从 CDP DOM `getBoundingClientRect` 拿（vscode-smoke 的 rowTarget 就是范例）。

### 20. 恢复时不信叙述、只信哈希
- **现象**：恢复后磁盘上的 completion.js 与会话摘要描述的"最终版本"不一致（摘要说最小 diff，磁盘是混合版）。
- **根因**：叙述性总结天然滞后于最后几次编辑。
- **本应**：恢复第一步重建哈希链——extension-src、App 仓、VSIX 提取物三处哈希 + verify 把 app.asar 拉进三方断言，闭环"源码=产物=被验收的版本"。

### 21. "本地看图"在本环境不存在 + 本地视觉分析连环死路
- Read 打开本地图片也只回 CDN URL；随后依次尝试并全部失败：
  - PowerShell WinRT OCR：`GetFileAsync` MethodNotFound（静态投影失败）、`IStorageFileStatics` 类型找不到；
  - UIA 遍历：Chromium 无障碍未开，树全空；
  - `SPI_SETSCREENREADER` 唤醒：无效，且**系统标志必须当场恢复 off**（已恢复）。
- **代价**：约 6 次工具调用全部沉没。
- **本应**：这些死路已记入 SKILL.md「本机死路」，直接绕开；像素类验证一律退到 CDP DOM 状态。

### 22. 手动复验 CDP 已断言的行为（收尾阶段最大的弯路）
- **现象**：为"最终手动抽查"在孤立 Trae 上反复折腾：图标坐标猜测（19）→ 远程分析崩溃（18）→ 本地视觉死路（21）→ 截屏发现前台被用户占用，中止。
- **本质**：CDP 冒烟已经用真实 DOM + 真实输入事件断言了同一行为，人工点击不增加证据强度，只增加风险（误点用户窗口）与成本。
- **本应**：验收标准 = CDP 断言；人工只看脚本测不了的（视觉/手感），一遍过；动手前先确认前台归属。

### 23. 截屏捕获用户前台（隐私 + 安全 + 打扰三重坑）
- **现象**：截屏发现前台是用户正在使用的窗口，测试窗被完全盖住。
- **处置**：立即中止手动抽查；含用户桌面的截图当场删除；测试实例 `CloseMainWindow` 优雅关闭；报告如实披露"手动抽查未执行及原因"。
- **本应**：GUI 自动化动手前先截屏确认前台归属；截到用户内容一律即删、不入档。

### 24. 脚本默认参数指向旧版本
- **现象**：恢复后复跑 verify 只传了 release 目录，第二参默认 `marcopilot-1.0.0.vsix`，断言 `'1.0.0' !== '2.0.1'` 失败，还误以为产物有问题。
- **本应**：带版本号默认值的脚本永远显式传全参（本 skill 的 acceptance.md 固化了完整命令）。

### 25. 证据文件路径/schema 现场猜
- live-AI 结果在 `.perf/release100-live-ai-201/`（不是无后缀目录）；后台套件 results.json 没有 pass/total 字段，判定看 `testExitCode===0` 和 `tests[].path/sha256`；verify 的结论文件叫 `coherence.json` 不叫 report.json。
- `node -e` require 一个含 GBK 错误文本的"json"只会报 SyntaxError——先看原始文件再解析。
- **本应**：证据索引固化在 acceptance.md，交付时按表取数。

### 26. Git Bash / 路径小坑（高频复发）
- PowerShell 单行里的 `$_` 被 Git Bash 展开 → 写 `\$_`。
- `/tmp` 是 MSYS 虚拟路径，交给 Windows 程序（PowerShell、Read）前 `cygpath -w`。
- `node` 的 require 不认 `/d/...` MSYS 路径 → 用 `D:/...`（本 session 又踩一次）。

### 27. 渲染补丁"看起来没装"——先怀疑 TDZ，再怀疑时序（2.2.1 踩到）
- 症状：探针里补丁的所有守卫逐条复算都通过，但 Selection API 代理/时间线里**看不到我们的调用**，
  页面又没有任何异常上报（`w.__acc.errors` 为空是因为探针没装 SHIM——那是**假的绿色**）。
- 真凶是自己刚加的代码：把 `forward ? ... : ...` 提到 `const forward = ...` 之前 → 暂时性死区
  `ReferenceError`，异常被外层吞掉，表现成"整段补丁静默失效"。
- 定位套路（下次直接照做，省两轮 GUI）：① 逐条复算守卫（确认不是守卫拦的）→ ② 在 handler 里插
  分阶段打点（`window.__x.push({stage:...})`，每处 `return` 前一个）→ ③ 用 try/catch 把异常连同
  `error.message/stack` 打进同一个数组。三轮以内能钉到行。
- 另一条同类教训：**"补丁没生效"和"补丁生效但被 Vditor 覆盖"要分开**——Vditor 的 `c ← B`
  （`removeAllRanges`+`addRange`）在每次选区变化后都会重设选区，代理里看到它在我们的调用之后跑，
  说明我们生效了、只是被规范化（那属于可接受行为）。

### 28. 改口径必须同时改旧断言，并且**理由要写在断言旁边**（2.2.1）
- 用户要求把"围栏当普通字符"之后，场景 74/75 里 8 条"文档一个字节都不改"的旧断言必然变红。
- 做法：新断言换成**更强的**用户可见判据（源码少一个字符 / 围栏成对 / 块公式还在 / 磁盘独立读），
  并在断言上面写清"口径变更 + 证据探针名"，绝不出现"为了让红灯变绿而放宽"。
- 顺带：`--only` 是**子串**匹配（`--only=74` 会连 74x 一起跑、`--only=10` 会跑到 109）；
  临时插桩过产品代码之后，必须 `sha256sum -c` 逐字节校验还原、并 `grep -c` 确认
  `TEMP-INSTRUMENT`/`ABLATED`/`__dbg` 残留为 0——本轮两次插桩都按这条走的。

## 慢在哪里——一句话总结

**时间不是花在修 bug 上，而是花在四类绕路上**：
1. **证据强度不够的验收**（误报 → 返工 → 全程补真实 DOM 税）；
2. **用更脆弱的手段验证已被更强手段覆盖的事情**（远程图像分析/手动点击 vs CDP 断言）；
3. **方案先行的重写**（3 轮几何重写 vs 二分 + 最小 diff）；
4. **环境与流程的隐形税**（并行负载毁轮次、默认参数/硬编码版本、路径与引用转义、遗留实例）。

### 29. 改了代码但读数**逐字不变** —— 先怀疑自己的探针（2026-09-18）
- 症状：连续三个不同实现的纵向补丁，全篇随机行走的输出**逐字相同**（同一下/上键次数、同一批列偏离）。
- 真凶不是"代码没生效"（版本标记 `window.__vertBuild` 证明新代码在跑），而是**探针的记账**：
  隐形落点的 y=0 被当成"上一次读数"，下一段循环 `now.y >= top.y - 1` 立刻成立 → 直接 break →
  永远报"↑0 次"。**改代码不影响判据的输入通道，读数自然不动。**
- 规矩：读数与上一版**逐字相同**时，先证明"这一版真的改了行为"（打一个版本标记 + 一次最小手势），
  再怀疑产品代码。判据要能区分"没动"与"动了但隐形"。

### 30. 谁先拿到方向键：window 捕获 vs 元素捕获（2026-09-18）
- Vditor 在编辑器初始化时就注册了 keydown（**元素**捕获），我们的补丁注册在它之后 →
  每次方向键都是"Vditor 先算一次落点（它只看行、不看列）→ 我们再去校正"，列被它带跑。
- 改到 **window 捕获**（`root.ownerDocument.defaultView.addEventListener('keydown', h, true)`）
  就抢在它前面：能算准就 `preventDefault + stopImmediatePropagation` 接管，算不准就整个放行
  （放行时 Vditor 仍会动选区——边界上它会给出 0×0 的位置，所以"到顶/到底"也要拦下来、什么都不做）。
- 同理：`caretRangeFromPoint` 在**折叠态公式源码**上给不出有高度的矩形（源码是 display:none），
  用它当"可用性"判据会把整行误判成不可落点；几何要用**公式节点自己的盒子**兜底
  （`boxOf`：先用自己的 rect，空就退到 owner 的 rect）。

## 31. 【2026-09-19】"光标看不见"分两种：一种该救，一种**救不得**（口径冲突，别再自动"顺手修"）

实测（`probe-real-ops --section=navdetail`，doc A 的 `**非整数解**…` 那段，5 个采样点里 2 个）：

| 落点 | 容器 | 画得出来吗 | 该不该挪光标 |
| --- | --- | --- | --- |
| 段落内的**元素级边界**（`P` 的第 N 个子节点之间，如 `{容器: "P.", 偏移: 11, 容器是文本: false, 高: 0}`） | 元素 | 否（0×0） | **不该**——见下 |
| 块里的**空白/零宽哨兵文本**（长度 1 的 `\n`/ZWSP，`{容器: "P.", 容器是文本: true, 文本长: 1}`） | 文本 | 否 | **不该** |
| 折叠态**公式源码**（`code[data-type=math-inline]`） | 文本 | 否 | **不该**（这是"围栏当普通字符 + 光标可进源码"允许的位置） |
| 标题标记 `span[data-type=heading-marker]` | 标记 | 是 | **该**（落进去之后 ← 不动，用户卡住） |

为什么前三种"救不得"：**把那一次落点挪到"最近画得出来的位置"，等于悄悄改了插入点**——
用户点段落末尾（外侧）时，Vditor 给的就是"段落末尾那个元素级位置"，落字就该落在段落末尾
（场景 107 ②③ 钉着这条，断言的是**磁盘里那个字出现在公式外面**）；一旦按"就近挪到可见位置"，
字会跑进公式源码里，用户看到的是"我点末尾打出来的字跑公式里去了"。
实测把这条放宽（隐形就救）时：107 由 15/15 掉到 13/15、101 由 32/32 掉到 30/32。

**结论（判据）**：能救的只有"**落点可绘但位置非法**"（标题标记、公式预览里）；
"**落点合法但画不出来**"是浏览器的绘制限制，**不许用挪光标的办法消掉**——
要根治只能从 DOM 层做（在该位置保证有一个能承载 caret 的文本节点），那是另一件事。
