## 一 性能：归因探针先把钱花在哪量出来

新探针 `scripts/math-edit-perf-probe.cjs`（只观测、不改产品代码；素材先复制、结束删副本），一次运行里做四件事：

1. **微基准**：展开节点查询（`querySelectorAll` vs `getElementsByClassName`）、`ownMath` 的 `:scope` 选择器 vs 手写遍历、段落贴边 `Range+toString` vs 一条等价快路径；每项都带**等价性自检**（两种实现必须在同一批节点上返回同一个答案，否则报 mismatch）。
2. **真事件成本拆分**：在 window / document / root 三级捕获各打一个时间点，把"事件派发 / document 捕获 / **我们自己的 root 捕获处理器** / Vditor 的冒泡处理器 + 浏览器默认"四段分开。
3. **`boundaryNode` 的逐行等价副本**：把 `math-edit.js` 里 `formulaEdge / neighbour / nearBlockOf / boundaryNode` 抄一份页内直接计时，用来判断"捕获段里那 0.9ms 是不是我们的代码花的"。
4. **打字连发时观察器负载**：装一个和 `enforce` 同配置的 MutationObserver，真 `insertText` 连打 24 个字，数它收到多少条 class 记录。

关键数字（49 万字符 / 348K markdown / 5634 条公式 / 45,082 个元素）：

| 项 | 实测 |
|---|---|
| `querySelectorAll('.vditor-ir__node--expand')` | **0.213–0.228 ms** |
| `getElementsByClassName('vditor-ir__node--expand')` | **0.0013–0.002 ms**（快照成数组 0.00033 ms） |
| 整趟 `refreshMathEditing` | **0.217–0.299 ms**（九成是上面那句查询） |
| 改后同一趟 | **0.099 ms** |
| `ownMath`：`:scope` / 手写 | 0.00010 ms / 0.00017–0.00022 ms（**手写更慢**） |
| 段落贴边探针 `Range+toString` | 0.0004–0.0005 ms（快路径 0.00007 ms） |
| `boundaryNode` 等价副本整体 | **0.0012 ms** |
| 退格 keydown 拆分 | 派发 0.023 / document 捕获 0.047 / **我们 0.868–0.935** / Vditor+browser 5.4–6.0（单位 ms） |
| 打字 keydown 拆分 | 派发 0.023 / document 0.052 / **我们 0.038** / rest 5.6 |
| 观察器负载 | **0.9 条 class 记录/字**（落在公式节点上 0） |
| WYSIWYG 全篇归一化循环 | **2.42 ms/次**（5148 条行内公式） |

### 一个必须说清楚的归因结论

"退格时我们这一段的 0.9ms"**不是我们的代码**：逐行等价副本在同一光标位置上只要 **0.0012 ms**，差三个数量级；而且同一位置打一个普通字符时我们的处理器只要 0.038 ms（两者都要跑 `activeCode`/`activeEmpty`）。那 0.9ms 落在"root 捕获阶段、注册在探针监听之前的所有监听"里，也就是 **Vditor 自己的捕获相位 Backspace 处理**（块合并那类活）。这个结论直接影响决策：**贴边判定没有可优化的空间**（它已经是微秒级），所以那条"紧前字符快路径"不做。

### 五条候选的最终处置

- **A（改）** 展开节点查询 → `getElementsByClassName`。源码改动一行 + 遍历前 `Array.from` 快照（活集合会随移除 EXPAND 而变）。
- **B（不改）** `ownMath` 手写遍历更慢。
- **C（不改）** 贴边判定整体 0.0012ms，快路径省 0.0003ms = 一次退格事件的 0.005%。
- **D（不改）** 观察器每字 0.9 条记录。
- **E（不改，记账）** WYSIWYG 归一化 2.42ms/次：非默认模式；且没有可靠判据区分"用户刚建的空公式节点"与"已归一化的节点"，改成 O(1) 会让 `setValue` 后全篇源码外露（2.1.3 已经在这条分支上自造过一次回归，不再冒同类风险）。

## 二 只测没测过的手势：新场景 75（48 条断言 / 82 证人 / 每检查都截图）

覆盖的形状：文档最开头就是块公式、文档最末尾是块公式、两条块公式只隔一个空行、两条相邻行内公式、块公式后紧跟标题、紧跟列表、列表项里的行内公式、`Ctrl+A` 全选加一次删除再撤销、`Ctrl+Backspace`/`Ctrl+Delete`、展开后连按 8 次左方向键、双击行内公式、三击段落、查找命中公式源码、源码视图切过去再切回来；并在两份受保护真实素材上跑"全选→退格→撤销（逐字节回原文）""双击公式""贴块公式按 Ctrl+Backspace""Ctrl+End 后 Delete"。

### 2.1 它抓到的两个真缺陷

**缺陷 1：`Ctrl+Backspace` 绕过全部贴边保护。** 保护逻辑原本对任何带 Ctrl/Cmd/Alt 的按键直接 `return`（那是为了不干扰格式化快捷键）。于是按词删走浏览器默认删除：光标停在块公式之前时，整条公式被并进上一段。在**用户真实素材**上实测到的字节：

```
before: > (1)
after : > (1)\neg\,\exists x\in A, P(x)\;\Leftrightarrow\;\forall x\
```

修法：`wordDelete = (ctrl||meta) && !alt && (Backspace|Delete)`，这一类按键**继续往下走**那一段贴边保护；判完（无论有没有命中）立刻 `return`，保护之外的行为一个字都不改。Alt 不碰——Windows 上 Alt+Backspace 是系统的撤销。

**缺陷 2：点"文档首块公式上方 4px 的页边距"再按退格，吃掉公式源码最后一个字符。** 场景里加了 `CARET_STATE` 转储，取证到的按下前状态是：

```json
{"startKind":"text","offset":7,"textTail":"a0+b0=1","path":"",
 "ownerClass":"vditor-ir__node vditor-ir__node--expand","ownerType":"math-block",
 "ownerExpanded":true,"visibleSource":true}
```

也就是说：**不是**"光标困在隐藏源码里"，而是点击被 Chromium 映射进了源码末尾，然后**我们自己的刷新把这条公式展开**，让它看起来像"用户正在编辑公式尾巴"——于是按"源码末尾退格"（那条**故意放行**的常规手势）把最后一个字符删了。2.1.3 的几何归位只覆盖"落在公式盒子**里面**"的留白，盒子外面 1px 就漏。

修法：新增 `blankLanding(x, y)`。落点不在任何公式里时，按 clientY 在顶层块上**二分定位**（沿用 `math-scheduler` 里那套"顶层块按纵向排列"的假设，避免在几千个块上逐个量几何），若该块（或它的首/末子节点）是一条**折叠的**块公式、且点在它上下 10px 之内、横向在编辑面里，就按几何翻译成公式之前/之后。文档序里"公式之前的留白"就等于这个插入点，所以语义与"点上一段末尾"一致。

### 2.2 测试自身的三处误判（也如实记着）

1. `Ctrl+A` 的判据拿 markdown 字符数（211）比 `getSelection().toString()`（118）——后者不给 `display:none` 的隐藏源码。改成**结构判据**：选区从第 0 块跨到最后一块。另：Chromium 里连按两次 `Ctrl+A` 会继续往外升级（第二次选到了外壳页的 7 个字符），只需要按一次。
2. 真实素材上的键盘操作前**必须先点进编辑器**（快捷键由编辑器自己处理，焦点在外壳页上按键到不了）——第一版因此把"什么都没发生"读成"全选+退格无效"。
3. 判据里拿 `owner.textContent`（含渲染器生成的 `$$` 围栏）去 markdown 里 `includes`，永远找不到；应取 `code[data-type="math-block"]` 的 `textContent`。

### 2.3 两条如实记账、本轮不修

- `Ctrl+A` + 一次退格之后正文与所有公式源码都删净了，**只剩一个空的 `$$` 壳**（实测剩 8 个字符）。Vditor 的删块归一化行为；产品本身支持"空 `$$` 对"（素材里就有），没有可靠判据把"用户故意留的空公式对"和"删块剩下的壳"分开。
- 连按左方向键穿越围栏时 **1/8 步**光标落在标题的 `##` 标记里、0 绘制矩形（与公式无关的 Vditor 标记）。场景里如实记账 + 单独 `ctx.log`，没有算作公式失败。
