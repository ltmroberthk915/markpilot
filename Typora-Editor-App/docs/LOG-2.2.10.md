本轮两件，都带测量口径与回归数字。第二件（VSIX 里的"双重光标"）**未能在桌面端复现**，如实记在 §三。

## 一 点已渲染的行内公式：展开之后，光标要落在你点的那一个字

**来历**：此前**没有**这条设计。代码里只有 2.2.5 的 `patchClickIntoFormulaSource`——它把"点进源码
之后光标隐形"救出来，不管落点精不精确。

**实测病象**（`scripts/acceptance/probe-repro-dupcaret.cjs`，doc A 的 `$33-1=32，33+8-1=40$`）：
点公式盒子里，Vditor **确实会展开源码**，但落点是 `code[data-type="math-inline"]` 的**元素级**位置——
矩形 0×0、偏移恒为 0 或源码长度，**与点击横坐标无关**：

| 点击位置 | 改前落点 | 改后落点 |
| --- | --- | --- |
| 公式左缘内 2px（x=631） | `code@0`，矩形 0×0 | 源码文本 offset 0，可见 |
| 公式正中（x=738 → 公式盒 629..847） | `code@14`（源码长 17），矩形 0×0 | 源码文本 offset 4 附近，可见 |
| 网格 x=666（用户那种"点在字上"） | `code@0`，矩形 0×0 | 源码文本 **offset 4**，矩形 `[669,154,0,13]` |

**改法**：新增 `patchInlineMathClickPosition`（事后校正，与其余点击补丁同形）——
单次左键、无修饰键、按下抬起基本没动，点在某条**行内公式盒子里**时：
① 先按点击点重新命中一次（展开后源码是真实文本，浏览器命中测试很准）；
② 解不到就逐字符扫源码的行盒，取离点击横坐标最近的字符边界；
③ 若 Vditor 没展开（用户图二那种"点了还是渲染态"），先替它展开（挂它自己的 `vditor-ir__node--expand` 类）再落点。
点公式盒子**之外**、或光标本来就在源码文本里，一律不碰。

## 五 追加：展开编辑态下"点公式后面出现高频闪烁"（2.2.11）

用户 2026-09-21 报：`$33-1=32，33+8-1=40$` **展开编辑（源码 + 上方浮出预渲染框）**时，点它后面"总长度"
附近出现高频闪烁（截图里浮框在源码上方）。

**复现尝试（dev 树，与 2.2.10 实装同一份 render 代码）** ——`probe-repro-flicker.cjs`：

| 动作 | 结果 |
| --- | --- |
| 点公式正中 → 展开（我们的新补丁生效，落点源码 offset 8） | 展开 ✓、浮框翻到上方 ✓、**无抖** |
| 点公式右侧 -30 / -10 / -2 / +2 / +6 / +12 / +30 / +60 px | 每处连拍 10 帧：不同帧 1–3 张（2 张 = 光标自身在闪） |
| 悬停在浮框上 / 在"总长度"处按下不放 / 从公式缓慢移到"总长度" | 14 帧里 1–2 张不同（同上） |
| 展开态静止 2.4 秒，每 200ms 采一次 DOM 变更条数 | `[0,0,0,0,0,0,3,0,0,0,0,0]` = 基本不动 |
| 藏掉我们的合成线再连拍 | 与有线时同样 2 张不同（排除"我们的线在闪"） |

⇒ **dev 树复现不出来**（这份代码与实装 2.2.10 逐字节相同）。所以本轮**没有**改任何"症状正确"的行为，
只做了一道**结构性防抖**：

**浮框翻转不再"摘类再量"。** 原实现每次都 `classList.remove(UP)` → 量 → 再 `toggle`，也就是**每次运行写两次 DOM**、
浮动盒当场跳一次；连续几拍里跑就会表现为高频闪烁。改为**算术重建"默认（下方）"那一版的框**——
翻不翻只改 top（默认 = 源码下沿 + 4，翻上去 = 源码上沿 − 4，与场景 92 的断言口径一致），
宽度/高度/左边直接取当前这一版；**只有需要翻时才写类**（同值不会产生 DOM 变更）。

**验证**：场景 92 **44/44**（浮框几何口径未破）+ 101 32/32、107 15/15、75 50/50；
闪烁探针在展开态依旧"连拍同帧、DOM 零变更"。

**仍需用户侧一条信息**：这个闪烁是在**桌面版**还是 **VSIX（webview）**里看到的、发生时鼠标是否在动。
（上一轮"双重光标"就是 VSIX 侧的现象，桌面端同样复现不出来。）
