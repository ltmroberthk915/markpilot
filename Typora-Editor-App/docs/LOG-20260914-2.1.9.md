# 2.1.9 取证与实施日志（2026-09-14）

需求：**含数学公式的段落要能"按住鼠标拖拽整体选中"，底纹要像普通文本一样盖住公式，复制不能是空白**
（用户要求照 Typora）。下面是这一轮从"复现"到"装上"的全部取证。

## 二 代码改动

| 文件 | 改动 | 为什么 |
| --- | --- | --- |
| `extension-src/render/js/math-select-reveal.js` | 新增：按下落在折叠行内公式的渲染结果上 → 挂 `.typora-ir-selected` + 临时摘该预览的 `contenteditable`；松手还原；`settleEndpoints()` 把边界那几条翻成源码并把端点吸到整条公式；`sync()` 只在"选区端点落在某条公式上"时保持翻开 | ①③ 两个坏点；并且按 Typora 的时序（拖拽中不翻源码、落手才翻） |
| `extension-src/render/js/math-source-map.js` | 折叠公式 `mousedown` 去掉 `preventDefault`；`click` 兜底（落点→源码偏移，折叠态也走）；拖拽收尾的 `click` 吃掉 | ①：preventDefault 让 Chromium 不给这次按下起选区；兜底保证"点公式本体 = 展开 + 光标进源码"这条老路不回退；吃掉收尾 click 是因为 Vditor 与 `refreshMathEditing` 会按它把刚建好的选区收掉（实测：拖拽全程 `collapsed:false`，一到 click 变 `collapsed:true`） |
| `extension-src/render/index.css` | `.typora-ir-selected` 的三条规则（marker 显示 / 源码 inline 可选中 / 预览收起）；折叠态隐藏 marker 那条加上 `:not(.typora-ir-selected)` | ③：源码得看得见、能选中、`$` 围栏要在选区里 |
| `extension-src/render/js/typora-patches.js` | 安装 + 销毁新模块 | —— |

**只对行内公式生效**（`data-type="inline-node"`）；块公式（`$$…$$`）的点击/退格语义一个字没动。

## 三 走错的路（都留了数字，避免下次再走）

1. **把渲染结果改成 `user-select:text`**（配置 S）：手感对，但光标准入 katex 子树、行尾点一下会弹
   预渲染框 —— `math-caret` 的 v2.1.1 断言当场变红。退回。
2. **自己接管拖拽**（programmatic 扩选 + `caretRangeFromPoint`）：选区能建起来，但公式展开/增量
   重渲染会把它打回塌状态；加"每帧按最后落点重设"的自愈之后又卡在 1 个字符。放弃——原生拖拽在
   摘掉 `contenteditable` 之后本来就够用。
3. **全局摘 `contenteditable`**：`probe-tail-click` 量到"行尾点一下"会把光标解进隐藏源码
   （`caretInCode:true`、公式展开），正是 math-caret 要防的那件事。改成"按下那一帧、只摘那一条"。
4. **`refreshMathEditing` 里去掉 `selectedPreview` 分支**：为了修拖拽顺手改的，结果
   `math-history` 的 `ir list redo` 断言变红（重做之后预览要看得见）。已全部还原——最终版**没动**
   `math-edit.js` 的 `refreshMathEditing`。

## 五 明确没测到的

- 按在折叠公式上、**同一行内**左右方向拖拽（不跨行）仍起不了选区（上/下/跨行都正常）。
- 块公式（`$$…$$`）在拖拽选中的表现没有按 Typora 对齐（只保证不回归）。
- 大文档（49 万字符 / 5634 条公式）里这条新代码的交互延迟没有单独计时；模块的常态成本是
  "没有鼠标选区时几乎零开销"（`sync()` 早退），只有按下/选区变化才遍历公式节点。
