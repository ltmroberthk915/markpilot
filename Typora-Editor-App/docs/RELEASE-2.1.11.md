# MarkPilot 2.1.11 发布说明（私版）

**这一版修你 2026-09-14 报的四条**（原话）：

> 1. 模拟鼠标操作, 点击在 "数" 和 句号之间, 预期行为应该是current插入在句号之前，现在这么点大概率会跑到这个句话的前面位置.
> 2. 此外，向上拖拽选中的过程中，这个可编辑公式区域会有抽搐频繁抖动(可能跟上一步刚改的有关系) 这个现象仅限于从下往上拉. 从上往下拉没有这个现象
> 3. 图片选中删除后，需要两次CTRL+Z才能把图片拉过来
> 4. 选中行为还是有点稍微不符合人的理解，尤其是被选中区域的提示. 哪怕你实现不了，把所有被选中的文字也好，公式组件也好，都被蓝色背景框住, 你也至少应该把拖拽的光标停留的最后落点位置给显示出来吧? 这个最终松手位置得有 caret 闪烁吧

一句话结论：**① 退格不再吃掉 `**` 记号（光标不再被吸进看不见的记号洞）、② 从下往上拖时公式区不再抖动
（实测拖拽全程零布局变化）、④ 整个选区（含公式）都被蓝色底纹盖住、松手落点有一根闪烁的竖线**；
③ **本地 17 种走法（含自动保存时序）都只需一次 Ctrl+Z**，我没能复现你那种"要两次"，已把它钉成断言（见第 5 节）。

## 1. 四条各自的真因

**① 光标跑进"记号洞"**（同一个毛病 2.1.8 就有，不是上一版带出来的）

那段收尾是 `…Radon–Nikodym 导数**。`。折叠态下 `**` 是 0 宽、看不见的记号元素，点"数"和"。"之间时
浏览器/Vditor 会把光标**就近吸进那个记号里**。不只是位置看着怪：

- 退格会**吃掉记号里的一个星号**：`导数**。` 当场变成 `导数*。`（Markdown 被改坏，加粗断了）；
- `Shift+←` 选到记号再打字，会插出 `*X*`（变成斜体）。

判定用的判据是"**按下那一刻这个记号看不看得见**"（看不见就说明用户不可能瞄着它点），但这条判据的
实现方式本身踩了一次坑，见第 3 节。

**② 向上拖拽时公式区抽搐抖动（向下拖没有）**

真凶不在底纹，而在 Vditor 自己的 `vditor-ir__node--expand`：拖拽中选区端点走进哪条公式，Vditor 就把
那条公式**原地换成源码**（`code` 顶掉渲染结果，行宽、行高、折行位置全变）。指针还压在原地，于是它下面
的文字位移了，端点又落到另一条公式上——Vditor 再翻一次、再收回来，来回打转。实测向上拖时第 3、4 条
公式的 top 在 **226 ↔ 247** 之间反复横跳（60px 的段落抖 20px，一次拖拽 12 次 class 变动）。向下拖看不出
来，是因为"翻开的公式"落在已经经过的内容后面，位移压不到指针。

**④ 选中区提示不足 / 松手落点看不见**

两件事：底纹现在**确实**盖住了跨过的公式（见第 4 节的像素证人），松手落点补了一根 2px 的闪烁竖线
（选区本身没有光标，从下往上拖、起点落在词中间时确实要靠猜）。

**③ 图片删除要两次 Ctrl+Z**

**没能复现**。在开发树、2.1.8 打包产物、已安装的 2.1.10 上共试了 17 种走法（单击选中 + Delete /
Backspace、Ctrl 多选两张、Ctrl+X 剪切、图片独占文末块、图片夹在正文里、图片后跟公式段、删完等一下
再撤销、跨过自动保存的 1500ms 再撤销、撤销前先失焦……），**每一种都只需要一次 Ctrl+Z**，而且图片
是真的画回来了（`complete && naturalWidth>0`、矩形恢复到原尺寸）。这一条没有对应改动，只加了一条
"恰好一次就复原"的回归断言（第 5 节），将来谁弄成两次立刻红。**如果你还能撞到，请把当时的键和动作
告诉我**（删除用的是 Delete 还是 Backspace、是单选还是 Ctrl 多选、之前是不是刚粘贴/拖入过图片）。

## 3. 走错的两段路（留证，免得后人再踩）

**"按下那一帧不许读几何"**。记号守卫最初是在捕获阶段的 `mousedown` 里量每个记号的可视性
（`getComputedStyle` + `getBoundingClientRect`）。结果"行尾点一下"这个既有用例直接红了：光标从段尾
跑到**段首**。对照实验钉死了原因：同一份代码只把"是否动手"改成 false（**照旧读、但不做任何动作**）
——一样红；把读取整段去掉就恢复正常。也就是说问题出在**按下这一帧强制布局**，它改变了
Chromium/Vditor 对"点在没有文字的空处该落哪儿"的判定。所以现在按下时什么都不读，判断推迟到光标真的
落进记号之后（`selectionchange`）。

**量测会骗人**。中途我曾用"光标矩形"量到"点到数和句号之间，光标跑到 220px 以外的句子前面"——那是
marker 的盒子位置与它**实际画出来**的位置不一致造成的测量假象（放大截图证明画的位置是对的）。所以
①的验收全部改用**自证动作**：点一下再打一个字符/按一次退格，看源码里到底改了什么。

## 4. 验收（同一台机器、真实鼠标事件 + 独立见证）

  撤销后回到原样；并断言光标**没有**落在 `.vditor-ir__marker` 里。
- ② 逐拍采四条公式的 top（40ms 一次）→ **变化 0 次**；按下期间 `.typora-ir-pointer` 在、松手后不在。
- ④ a) **窗口真实像素**：主进程 `capturePage()` 取帧，按公式盒区域算平均色 —— 拖拽后蓝通道显著抬升

## 5. 顺手修掉/发现的三件旧账（都在这一版的验收里）

1. **块公式点击映射回归（我上一版带出来的）**：2.1.10 的"只管行内公式"门把块公式的点击也挡住了。
   改成"映射成功才接管"后，渲染层套件从"15 通过 / 1 失败"变成 **354 通过 / 0 失败**，且 `math-caret`
   58 条（含块公式的点击/退格断言）仍然全绿。
2. **场景 70 的断言写死了表格单空格**：Lute 存盘时会按列宽补空格（`| 甲   |`），于是正则匹配不到、
   报成"磁盘上这一行公式没变"。实测（探针直接读磁盘）**编辑是写下去了的**，是断言过于苛刻。
   已放宽为"磁盘行里有这次插入的 `\cdot 2`、且仍在一条 `$…$` 里"，产品行为未改。
3. **未修、只记录**：`test/regression.js` 那条块公式映射失败，在**把这一版所有改动都关掉**
   （≈2.1.10 基线）时同样复现——所以第 1 点修好之后它已转绿；若将来再红，用"关掉全部改动"这条
   A/B 能立刻判断是不是新引入的。

## 6. 没做的 / 已知边界（如实说明）

- **③ 没有复现，也就没有针对性修改**：只加了断言。要定位需要你描述的准确动作。
- 落点竖线是**新加的 UI**（Typora 本身没有）。它只在"鼠标拖出来的选区"上出现，2px、闪烁、不吃事件；
  如果你觉得吵，说一声我摘掉。
- 按下期间冻结公式展开态是**视觉压制**（DOM 的类不动）。它只作用于行内公式/图片节点；块公式（`$$…$$`）
  的展开/源码围栏行为未动。
- 拖拽中"跨过的公式显示底纹"依赖渲染结果可选（2.1.10 起 `user-select:text`）；**块公式**选中行为仍未
  对齐 Typora（这一版没碰它，`math-caret` 有断言守着）。

## 7. 你亲手验这三步（开发树/安装版同一套行为）

1. **记号洞**：打开那份概率论文档，点到"数"和"。"之间 → **按一次退格**：应当删掉"数"、加粗还在
   （不要出现 `导数*。`）；再点一次、打一个字符 → 字符落在正文里，不要插出 `*X*`。
2. **抖动**：在四行公式那段，从最后一行行尾**按住往上拉**到第一行行首：公式区**不该再抖**；松手后
   整段带蓝色底纹（含公式），并且松手那一点有一根闪烁竖线；打字后竖线消失。
3. **图片**：点选一张图片 → Delete → **按一次** Ctrl+Z：图片应当立刻回来。如果你那边要按两次，
   请告诉我当时用的键和动作顺序。
