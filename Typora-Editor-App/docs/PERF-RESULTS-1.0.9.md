# 1.0.9 性能实测

本轮先测量、再暂存候选实现并验证边界，最后才改应用代码。未调用真实 LLM，未修改真实笔记。

## 已采用：降低桌面统计与保存状态刷新的 CPU 开销

统计规则保持原样：中文逐字、英文/数字连续串按词、内部撇号和连字符保留词边界语义；字符数维持既有 UTF-16 计数。候选将多轮正则、全文替换及分行数组改成一次扫描。保存成功或错误状态更新且内容未变时，复用此前统计。

在同一进程内交替执行旧实现/候选实现，每份真实文档各 120 次，预热 20 次。时间单位为毫秒：

| 样本 | 字符数 | 原统计中位数 | 新统计中位数 | 原 P95 | 新 P95 |
|---|---:|---:|---:|---:|---:|
| 教材合订本 | 309,659 | 4.783 | 2.457 | 7.480 | 2.737 |
| 动态规划教材（渲染修复副本） | 178,107 | 2.588 | 1.313 | 4.554 | 1.424 |

两份样本统计中位耗时减少约 **49%**。这是统计模块的局部收益，不是整页输入速度、保存磁盘耗时或电池续航提升的百分比。缓存另减少同一内容在保存状态改变时的重复统计。

候选落盘前完成 605 组等价性样本，包含全部 65,536 个 UTF-16 编码值、600 组随机文本、空文本、CRLF、emoji、中文扩展字符、Unicode 空白、连续连字符和撇号。落盘后有独立回归测试及真实桌面输入/保存验证。

## 大文档渲染基线与仍然存在的限制

用真实教材副本完成开页、分阶段输入、5,634 个正文公式队列清空、50%/75%/95% 位置公式点击、滚动与 Markdown 一致性检查。本次单轮稳态输入到下一帧约 **155 ms**，滚动约 **52 fps**，公式点击到带可编辑源码的下一帧约 **219–283 ms**。这是当前环境下的基线，不能与早期不同测量方式的 16 ms 直接比较。

旧基准把隐藏大纲中的 55 个公式也计为待渲染，导致正文队列完成后继续等待。本轮修正为统计活动正文公式；没有为满足测试强制渲染隐藏大纲。实测确认输入只重解析 46 字符的当前小块（约 0.8 ms），因此没有凭猜测改写解析器或引入虚拟滚动。本轮性能改动限定在有稳定实测收益的桌面后台统计；仍未达到所有大文档操作 60 fps。

## 证据与复现

- `.perf/stats-candidate.json`：候选落盘前的 120 次交替测量。
- `.perf/perf-before-1.0.9.json`：完整渲染基线、公式点击、滚动和解析调用记录。
- `.perf/save-race-before.json`：旧保存竞态的实际复现，磁盘内容落后但 dirty 被误清除。
- `.perf/unit-1.0.9.log`：数据保护、统计及既有主进程逻辑回归。
- `.perf/desktop-protection.json`：真实主进程、IPC、编辑器、磁盘与版本历史对话框验证。

复现命令：`node scripts/stats-performance.cjs`、`npm run bench:renderer`、`npm run test:protection`。基准测试只操作隔离配置及教材副本。
