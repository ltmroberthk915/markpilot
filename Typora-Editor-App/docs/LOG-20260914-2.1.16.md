## 一 ① 行末口径：我把方向理解反了

用户第 6 轮的原话是「点渲染行的最后，光标跳过末尾逗号、跑到它再往前一个字符之前；正常应该出现在逗号前」，
我按"停在逗号之前"实现；第 7 轮他把要的效果说清楚了：

> 「点在 `$$ 1=\lim…=0, $$` 这一行的最后一个逗号及之后的任何本行元素处，光标都会被映射到逗号之后」

**修法**（`render/js/math-source-map.js`）：

- 渲染结果里最后一个**可见叶子字形**（文档序）连同它右侧的空白带 → `targetOffset` 返回 `prefix + end`
  （= 源码末尾）；
- 这条排在"命令落到反斜杠之后"**前面**（万一公式以命令结尾，行末语义也要压过它）；
- 它前面的字形仍按半格规则（左半→字形前、右半→字形后）；缝隙里同样按半格，保证单调。

**回归门**：场景 85 的 A 组改成新口径（点逗号左半/右半/右侧 30px/右侧 200px → 全部 78），
另加自证（点 `0` 左半 → 76、右半 → 77，证明半格规则没有被行末规则吃掉）。A/B（`tail: false`）：
点逗号左半边退回 77，断言红。

**像素网格复核**（`probe-math9.cjs`，用户那条公式 y=398 行）：`x 587..593 → 76`、`594..597 → 77`、
`598..608 → 78`，单调，且全网格只剩 1 处"回退"（显示模式 `\lim` 上下限与运算符横向重叠处，
那是 ② 要的行为）。

## 二 ④ 第二种机制：Vditor 自己的去抖 push

2.1.15 修掉的是我们自己的两处补历史点（纯光标移动）。这次换 **用户原文档** 复现：

`probe-img7.cjs`：把 `1-重识概率论.md` 复制到运行目录，在「紧跟第 196 行那条块公式」的位置插入
同一张 `<img … data-typora-scale="75">`，点选 → Delete：

```
修前：栈 1→2 **推入** ← commitImageEdit（真正的删除补丁）
      栈 2→3 **推入** ← index.min.js（setValue 之后 Vditor 自己的去抖 push；前后 mdLen 都是 15256）
      第 1 次 Ctrl+Z → 文档没变（mdLen 15256）；第 2 次才复原
修后：第 1 次 Ctrl+Z 就复原（mdLen 回到 15354）
```

**为什么小文档复现不出**：小文档里那次去抖 push 的补丁刚好为空（Vditor 自己会跳过空补丁）；
在"图片紧跟块公式"的排布下，重建文档后公式重排 / reconcile 挪节点让**HTML 快照**变了、
markdown 没变，补丁因此非空。

**修法（两版，第一版已撤）**：

1. 先试了"入栈一侧拦住 markdown 没变的补丁"——**把两条合法断言弄红了**
   （渲染层套件 `ir math undo`、`wysiwyg list undo`：它们正是"markdown 相同但结构不同"的撤销步），
   实测后**撤回**。
2. 改成 `render/js/typora-patches.js` 的 undo/redo 包装里**跳过空步**：走完一步后若 markdown
   一字未变且栈里还有更早的补丁，就再走一步（最多 3 步）。**只动手势、不碰记录**——记录一侧
   的守卫会误伤，这一侧不会。

**回归门**：场景 89（图片紧跟块公式：一次 Delete 之后**第一次** Ctrl+Z 就拿到图片、栈回到删除前、
磁盘逐字节一致）。A/B（关掉空步跳过）：三条断言红，且症状与用户描述一致（第一次撤销文档没变）。

## 三 ⑤ 向上拖拽经过块公式的高频抖动

**取证**（`probe-jitter.cjs`，逐拍 40ms；起手在块公式下方、终点在它上方）：

| | 块盒高度序列 | `--expand` 翻转 | 顶层块 top 组合 |
| --- | --- | --- | --- |
| 修前 向上拖 | `91,91,…,118,118,91,91,118,91,…` | 4 | 2 种 |
| 修前 向下拖 | `91,…,118,118,…,91` | 2 | 2 种 |
| 修后 两个方向 | 全程 `91` | **0** | **1 种** |

高度差的 27px 正是**源码行**那一条（`probe-parts.cjs` 逐零件量过：折叠态块盒 91 = 渲染结果 27 +
围栏伪元素占位；展开态 118 = 再加源码行 26~27）。

**根因**：2.1.11 的 `.typora-ir-pointer` CSS 只覆盖 `[data-type="inline-node"]`；块公式一被展开，
源码行插进版面 → 下面文字整段位移 → 指针底下的内容变了、拖拽端点落到别处 → `refreshMathEditing`
再翻一次，形成反馈环。

**试过但撤回的路**：照行内那套给块公式写 CSS（藏源码行与两枚 `$$` 围栏）。实测块盒高度从 118
掉到 **27**（比折叠态还矮——折叠态那 64px 来自 Vditor 画在 `::before/::after` 上的围栏），
位移更大 → 按"没有量到收益就撤"的规矩撤回。

**修法**（`render/js/math-edit.js` 的 `refreshMathEditing`）：鼠标按着（`.typora-ir-pointer`，
由 `math-select-reveal` 在按下时挂上）期间**不展开块公式**——`editing` 集合里跳过
`data-type="math-block"` 的 owner；已有的展开会在同一遍里被收回。松手后 pointer 类摘掉、照旧恢复。

**回归门**：场景 88（向上拖 + 向下拖对照：拖拽全程块盒高度只有 1 种取值、top 不变、顶层块布局
只有 1 种取值、`--expand` 翻转 0 次；并自证"这一拖真的选中了东西、起手在公式下方、终点在它上方"）。
A/B（`blocked` 恒假）：4 条断言红。

## 四 ③ 附带：面板不许顶着工具栏

给"避开预渲染框"加规则时实测发现：行上方有空间但被工具栏占着时，面板会顶到屏幕最上面（横跨工具栏，
实测面板 8..336、工具栏高 71）。改成**工具栏下沿当天花板**：`spaceAbove` 从天花板算起、
落位再 clamp 到它下面。场景 86 断到 10/10（新增"面板也没有顶着工具栏"），既有
`scripts/desktop-completion.cjs` 的"不许停在工具栏上"断言全绿。
