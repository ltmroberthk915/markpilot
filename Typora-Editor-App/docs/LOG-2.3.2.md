### 1.1 视觉确认（装机 2.3.1）

在装机产物上按 5 种光标位置逐一复现并截图：

| 光标位置 | 装机 2.3.1 实测 | 截图 |
| --- | --- | --- |
| `### \|标题内容`（标记之后） | 标题上方插一个空段、标题**整行下移**，`### 标题内容` 被展开画出、光标回到 `###` 左缘；md 一字未改 | `r16/a-heading/installed/installed-2.3.1-1-*.png` |
| `\|### 标题内容`（标记之前） | 与上一条**逐像素相同**（两张不画标记的整页图 sha256 同为 `e910eb77…`） | `…-2-*.png` |
| `### 标\|题内容`（文字中间） | 第一行 `### 标`（18px），第二行「题内容」是**普通段落**（14px，肉眼可辨变小） | `…-4-*.png` |

装机 asar 内 `patchHeadingEnter` 只有旧判据 `if (!leftWithoutMarkers.textContent)` → 前两种落进同一分支，与现象吻合。

### 1.2 修改方案与对抗

方案（子 Agent A）：改真源 `Typora-Editor/extension-src/render/js/typora-patches.js` 的 `patchHeadingEnter` 分支判据，加"光标在标记之后"这一维。

判据选择过程（有实测证据）：
- `Range.compareBoundaryPoints` 的四种 `how` 在真机对"标记之前 / 之内 / 之后"**全部返回 1**，完全分不出 → 不可用。
- 改用**结构判据**：左半（heading 起点 → 光标）的 `cloneContents()` 里出现 heading-marker 元素、且它的文字**不比原标记短**，就等于"整枚标记都在光标左边"。7 种真机形状 + 13 行游离 DOM 形状全对。
- 另加 **ATX 形态守卫**（`/^#{1,6}[ \t]*$/`）：setext 标题的标记内容是换行，语义与"井号钉在原行"无关，形态不认识就退回旧判据。

边界结论（dev 实测）：标记之前 = 块首语义不回退；标记文字中间 = 仍走块首（不许拆出 `#` + `## 标题` 这种级别错乱）；标记末尾 = 拆分；空标题 = `H3"### "(空) + P(空)`；h1..h6 六级级别不错乱。

### 1.3 落码

```js
// typora-patches.js · patchHeadingEnter
const 光标在标记之后 = (() => {
  const marker = heading.querySelector('[data-type="heading-marker"]');
  if (!marker) return false;
  if (!/^#{1,6}[ \t]*$/.test(marker.textContent)) return false;   // 只认 ATX 形态
  const cloned = first.querySelector('[data-type="heading-marker"]');
  return !!cloned && cloned.textContent.length >= marker.textContent.length;
})();
if (!leftWithoutMarkers.textContent && !光标在标记之后) { /* 块首：标题前插空段、整行下移 */ }
else { /* 拆分：标记钉原行、右半落成普通段落 */ }
```

## §2 问题2 · 点图片出源码（U-084）

### 2.1 视觉确认（装机 2.3.1，真实鼠标 SendInput）

让操作系统自己数双击（`GetDoubleClickTime()` = 500ms，双击矩形 4×4px）：

| 按下沿间隔 | 页面自报 detail | 是否出源码 |
| --- | --- | --- |
| 124 / 262 / 403 / 468 / 501 / 545 ms | `1,2` | **出**（481ms 仍出） |
| 608 / 701 / 1011 ms | `1,1` | **不出**（534ms 起不出） |

- 700ms × 6 轮 = **0/6 出**；150ms × 6 轮 = **6/6 出**。
- `A-间隔700ms.png` ≡ `B-单击1次-只选中.png` ≡ `A-480/520/600` ≡ `C-久隔2500`：**6 张整页图 sha256 完全相同**——第二下被静默吞掉，一个像素没变。
- 同族四形态（md 独占段图 / 段中图 / 文末图 / 裸 HTML 图块）一个不落。

→ 病根：出源码只挂在 `event.detail>=2` 上，而 detail 是**操作系统双击计数**的产物。点快了出、点慢了永远停在"只选中"。

### 2.2 两版方案与对抗结论

| | B 的初版 | D2 的对抗意见 | 最终统一 |
| --- | --- | --- | --- |
| 判据形态 | 隐形手势记录（"上一击是纯左键单击在这张图上"，click 顶部消费） | **绑用户看得见的选中框**：Esc / 删除失败路径这类"清掉了画面却没产生 click"的打断会让手势记录残留 → 画面没蓝框时第一击就弹源码 | 采用 D2：`mousedown` 顶部记"按下之前这张图是否带 `typora-img-selected`" |
| 时间项 | 无 | 背书（实测长按时 mousedown→click 是 2012ms，任何墙钟窗口都会静默失效） | 无任何时间项 |
| "已展开"算不算第 2 下 | 不算 | 背书不算（否则单击已展开的图会把光标抢进源码，与 138① 冲突） | 不算 |
| 命中面 | 精确落在 `<img>` 像素 | 建议放宽到"同一 owner 的非源码落点" | **不采纳**：点图右侧空白＝落"图片之后"是 U-071/U-079 的显式契约，放宽会与它抢 |
| 第 3 下折回（大图素材） | 未处理 | 指出：展开后源码行把大图顶下去，第 3 下打在原坐标＝图片上方空白，放行给 vditor `B()` 就会被折回（小图侥幸同行，属素材依赖的假绿） | 采纳（防御性）：新增"用户展开过的图，点它那一段空白 ⇒ 只钉住不折回"支。**复核轮在 13 个"块内空白"候选点上把它注掉（mut-b）后没有变红**——即目前没有腿能证明它必需；保留作防御，不主张有实测支撑 |

口径一句话：**蓝框在 ⇒ 下一击必出源码；蓝框不在 ⇒ 这一击只上蓝框。**

### 3.3 突变证据**不成立**（如实记账）

## §9 追加轮 · 图片多选指示框（U-085 / A-027）

用户追加报障：「之前做的那个第一次点击，然后按住CTRL再点击图片的那个选中指示框好像没了。这个你去查一下，是因为不同的图片格式不一样吗，还是什么原因？你兜一下底。」

### 9.1 确认（装机 2.3.2，8 形态 × 6 手势 48 格 / 24 张截图）

- **图片格式不是变量**：md 独占段图 / 裸 HTML 图块 / 段中行内 / 列表项内 / 引用块内 / 表格单元 / 文首 / 文末八种形态上，「单击 A → Ctrl 点 B（另一张）」**全部**正常出虚线框（`computed outline = rgb(40,170,241) dashed 2px`）；另测 png/base64/参考式/带宽高/对齐五个变体行为一致。
- **时序不是变量**（单击 A → g → Ctrl 点 B，g=0…1400ms 共 22/22 绿）；长文档也不是（1603 块文档里绿）。
- **坏的是"同一张"**：`单击 A（实线）→ 按住 Ctrl 再点 A 自己`，mousedown Ctrl 分支里那条早退「Ctrl 点已经单选的那一张 = 取消选择（与资源管理器一致）」把实线框摘掉，**没有任何虚线框接手**——race 探针的事件时间线只观测到"摘实"，"加虚"一次都没发生。同一手势点另一张却正常 ⇒ 同一手势两种语义。
- 该早退自 `8c01718 基线：2.1.29` 起就在，2.3.1 与 2.3.2 的多选链路**逐字相同** ⇒ **不是本轮回归**；但用户报的是行为，不能据此不改。
- **同一条分支的第二处损伤（对抗轮独立抓出）**：早退用 `getSelection().removeAllRanges()` 清选区，而 `keepEditorFocused()` 保存到的是**已被清空的选区** → Blink 把光标停在**文档开头**；紧接着按 Delete **吃掉第一行标题的 `# `**（标题塌成正文）、打字打进文首；迁移之后打字还会把字符写进图片引用（实测 `shot-blue.png` → `shot-blQue.png`）。

### 9.2 对抗结论

J 轮的字面改法（删早退 + "把迁移块提到 toggle 之前"）**是空操作**：迁移块本来就在 toggle 之前，删掉早退后"加虚"与"摘虚"在同一任务里跑完、中间一次绘制都没有，实测 A/B 两份产物都是 `frames=0`，唯一差别是 toast 文案。对抗轮给出修正版 K+N（迁移后**跳过** toggle + 光标还原），并否掉了 J 的"状态→类同步器"兜底（click 里图片相关分支全部提前 return，尾部不可达 ⇒ 不可验证代码）。

### 9.3 落码（`media-tools.js`）

1. Ctrl 分支里先取 `const 刚才是实线=(selectedImage===img);`（语义必须在迁移之前定）；
2. 迁移块不再 `removeAllRanges()`：优先把光标还回新增状态 `上次文本光标`（在"普通单击图片"那条分支 `selectNode(img)` **之前**捕获的折叠文本光标），没有就退到"这张图之后"的零宽锚位；
3. toggle 加门 `if(!刚才是实线){…}`——迁移过来的那张"迁移即选中"，不再被同任务的 toggle 摘掉；
4. **不加**同步器（见 9.2）。

## §10 纪律

- 素材基准只读，测试一律用副本；产品代码改动期间**不并行跑验收**（本轮实测抓到过一次"在途半成品被场景读到"：`ReferenceError` 让所有带鼠标的场景在 console 闸门判红，读数无效）。
- 每笔修复都走"复现红 → 改 → 同一发命令复验 → 突变（注掉必须变红）→ 视觉复核"。
- 面向用户的契约变更（标题回车语义、图片第 2 下必出、Ctrl 点已选中图＝并入多选）都已由用户二次确认；验收判据写成用户看得见的性质（第一行是不是空的同级标题、字号有没有变小、蓝框在不在、源码行出没出）。
