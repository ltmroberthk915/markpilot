# LOG-2.2.5：公式源码里的 ← 不再"绕过 a 左侧"、合成光标几何纠错、点公式后面那一下不再落空

本轮起因是两条用户报告（都在同一份 1717 字节的小素材上，doc A）：

1. `$$ad$$` 块公式的源码里，光标停在 `a|d` 时按 ←，**没有走到 a 的左侧**，而是跳到上一行的 `$$` 行尾
   （用户原话："左键会导致绕过 a 左侧"）；同一份文档里"行内公式独占一行"时光标样子也不对。
2. 点开行内公式之后，再点它**后面**的正文（"设"字），**光标进不去、公式也一直不收回渲染**。

三条修复，两条是这两条报告的直接成因，第三条是复现过程中顺手取到的同族证据。

## 一 ← 的落点：端点归属要留在**光标当前所在的那个文本节点**上

**改写者是自己的代码**。用 Selection API 代理 + 调用栈取证（`--trace`，见 §四）拿到的一拍：

```
① 光标在块公式源码 "ad" 的 offset 1（a|d）
② 按 ←
   栈：selectPoint (typora-patches.js:69) | HTMLPreElement.<anonymous> (typora-patches.js:835)
   落点：#text("$$") @ 2   ← 围栏文本节点
```

根因在 `sourcePoint(nodes, offset)`：把"源码拼接空间里的偏移"映射回 `(文本节点, 偏移)` 时，
顺序查找把**落在节点端点上的偏移**交给了**前**一个节点。块公式的拼接空间是 `$$` + `ad` + `$$`，
`a` 左侧那个位置（偏移 2）正好既是源码节点的起点、也是**前一个围栏节点的终点**——于是落点被算到
`$$` 上；而围栏与源码**不在一行**（围栏独占一行），用户看到的就是"光标跳到上一行的 `$$` 行尾"。

修法：`sourcePoint(nodes, offset, stay)` 多带一个 `stay`（光标此刻所在的文本节点），
偏移落在它自己的两个端点之一时**留在它自己身上**。实测（`probe-repro-trajectory.cjs`）：

| | 落点 | native 光标矩形 |
| --- | --- | --- |
| 修前 | `#text("$$") @ 2` | `{x:63, y:458}` ← 上一行（围栏行） |
| 修后 | `#text("ad") @ 0` | `{x:51, y:485}` ← **源码行、a 的左侧** |

整趟走查（`probe-repro-stepout.cjs`）随之变成一步一格、不再跳行：
`ad|`(1) → `|ad`(0) → `$$`@1 → `$$`@0 → 出块（进上一段末尾）。
行内公式`$a$`不受影响：它的围栏与源码同处一行，"留在自己身上"与旧行为**渲染在同一个像素**上，
但打字的落点更正确（插进源码开头而不是插进围栏文本）。

## 二 合成光标的几何：元素级落点要用**块内的子节点**、0×0 处**不许画**

用户第一张截图的样子（一根比字高一截的竖线挂在公式左边、旁边字形像被切了一半）来自
`patchSyntheticCaret` 的两处几何错误：

| 状态 | 修前 | 修后 |
| --- | --- | --- |
| `$a$` 独占一行，光标在段落元素级位置 | `{x:46, y:546, w:2, h:25}`（块框左上角 + 整行行高 25px） | `{x:46, y:550, w:2, h:16}`（公式节点的行与高，与原生 caret 同高） |
| 光标落进"此刻没画出来"的容器（块框 0×0） | `{x:0, y:0, w:2, h:25}` ← **窗口左上角冒出一根竖线** | 不画（`藏()`） |

- 元素级落点（`<p>` 第 N 个子节点之间）以前只在**块的兄弟**里找左右邻居，`$a$` 这种"整段只有一条公式"
  的情况什么都找不到，于是退回"块框左上角 + 整行行高"；现在按 `childNodes[offset]` 在**块内**找，
  位置与高度都跟原生 caret 一致。
- 块框 0×0（例如展开态里被藏起来的预览浮层）或算出来的位置跑到编辑面之外一律不画——
  实测算错时画到 (0,0)，"位置错的光标"比"看不见光标"更像 bug。
- 注释与取舍写进 `patchSyntheticCaret` 的文档注释（两条硬规则）。

## 三 点公式后面那一下：Vditor 把光标写进了源码的元素级位置（0×0）

复现（`probe-repro-aftermath*.cjs`，doc A "转化为间隔"那一行）：

```
① 点公式（展开）→ 光标在源码里，可见
② 点它后面的"设"字 → 光标 = CODE[data-type=math-inline] @ 0，矩形 0×0（看不见），
   公式保持展开、浮出的预渲染框一直压着下一行
```

逐事件取证（`probe-repro-aftermath3.cjs`）：

```
mousedown target = P（正文）            ← 按下那一刻这一点还在正文里
mouseup   target = SPAN.mbin（KaTeX 子树）← 抬笔时浮框正好经过这个像素
click     target = P
selectionchange：CODE.vditor-ir__marker--pre[math-inline] @ 0
写入口全是 Vditor 自己的（index.min.js 的 removeAllRanges/addRange）
```

也就是说这**不是**我们的映射写错，而是"展开重排让浮框瞬间压住用户点的那一点"，
Vditor 据此把这一按当成"点在公式上"，把光标写进源码的**元素级位置**——既画不出来，
又因为光标仍在节点内而让公式保持展开。

修法（`patchClickIntoFormulaSource`，事后校正，与 Home/End 同一形状）——只认这一种形状：

- 单次左键、无修饰键、按下与抬起的点基本没动（不是拖拽）；
- 落点**隐形**（caret 矩形高 0）且落在某个公式的源码 `code[data-type]` 里；
- **点击点在公式自己的盒子之外**（点盒子里＝"进源码编辑"，那是既有契约，不动）。

满足时按点击点重解一次落点（只接受可见、且不在预览/围栏里的位置）。实测同一动作：

| | 光标 | 公式 |
| --- | --- | --- |
| 修前 | `CODE[math-inline] @ 0`，`{w:0,h:0}` | 保持展开 |
| 修后 | `#text(". 设总长度为最") @ 3`，`{x:868,y:151,h:16}` | **收回渲染** |

（修后光标 x=868 是**折叠后**的重排位置：". 设"三个字符正好落在用户点的那个"设"字后面。）

## 四 工具：`--trace` 让"谁改了选区"当拍可见

`probe-real-ops.cjs` 新增 `--trace`（`--section=selstep` 用）：把
`removeAllRanges / addRange / setBaseAndExtent / collapse / extend` 换成**带调用栈**的代理，
并记一条 selectionchange 时间线；某一步长度塌了/缩了就把那一拍的写入口连栈打出来。
本轮第一处修复就是靠它一眼定位（栈里直接给出 `typora-patches.js:835`）。
用法：`node scripts/acceptance/probe-real-ops.cjs --section=selstep --doc=a --trace --startx=52 --starty=415 --presses=60`

## 六 这一轮**没有**动的两件事（都已取证，留给用户决定）

1. **块公式空白带里点一下没有光标**：`math-edit.js` 的 `fenceClick` →`blankLanding` 把这种点击翻成
   "块之前/之后"的插入点（元素级、0×0）。这条路径有明确来历——注释里记着上一次的 bug：
   按几何翻进源码后，"点文档首块公式上方 4px"会让光标进公式尾部、一次退格吃掉源码。
   本轮试过"点空白带＝进这条公式"的写法，但它的 mousedown 在捕获阶段被 `fenceClick`
   `stopImmediatePropagation` 吃掉，需要在更外层挂钩；因为改的是**既有语义**，先不做。
2. **浮出的预渲染框会压住下一行**：这是 2.1.x 就定的"Typora 式浮框"（场景 92 有 44 条断言守着），
   本轮的第三处修复只是不再让它把点击"翻译"进源码，框本身照旧。若用户认为"编辑公式时不该压住正文"，
   那是产品口径的改动，需要单独一轮。
