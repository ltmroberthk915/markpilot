# Typora Editor 1.0.11：任务栏快捷菜单

安装新版并启动一次后，右键任务栏上的 Typora Editor 图标即可使用；固定图标后，程序关闭时也可从菜单启动。

- 最近使用的 **15 个不同文件**，最新打开的排在前面。重复路径忽略大小写；失效路径与文件夹会过滤，并从原有 50 条历史中补足。
- 点击文件会直接打开编辑器，程序已运行时使用已有窗口。同名文件用所在目录区分；完整路径也保留在快捷方式描述里。
- 列表末尾的分隔线下为 **新建 Markdown 文件**：选择位置和名称后创建空白 `.md` 并直接编辑。已有文件不会被覆盖；取消操作保护当前文件。应用内同时提供 **文件 → 新建 Markdown 文件…** 和 **Ctrl+N**。

这些入口放在 Windows 的应用任务区。系统自带的“固定／取消固定”“关闭窗口”等条目仍在下方，不能由应用重排。使用 Tasks 可避免默认 Recent 区的条数限制；实际可见高度仍由屏幕空间决定。[Microsoft 的 Jump List 说明](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-icustomdestinationlist-beginlist)

菜单更新合并为 200 毫秒一次，内容相同不重复写入。文件可用性异步检查，断开的驱动器在 750 毫秒后跳过；没有空闲轮询。正常安装沿用原 AppUserModelID；便携版指向外层 EXE，显式指定的备用用户目录采用独立 ID 和历史。

## 验证

- 44 项单元测试：去重、15 条上限、顺序、特殊字符的 Windows 参数解码、便携路径、失效文件、异步竞争、系统拒绝、退出，以及新建取消、并发同名文件、未保存内容保护。
- 打包后的真实 App 入口通过 30 项文件打开／新建测试；源代码入口也通过同一组测试。
- 真实 1.0.11 EXE 通过 6 项检查，包含读取 Windows 实际持久化的 17 个 Shell Link（15 文件、分隔符、新建任务），再用其中的真实参数启动文件，以及单实例转交、直接编辑和保存。
- 原生界面检查：冷启动 `--new-md` 显示保存对话框；取消保留原会话文件；Ctrl+N 保存测试文档后直接进入编辑界面。

测试均使用 `.perf` 下的独立用户目录与测试文件。Windows 任务栏本身未进行自动点击／固定操作；验证依据是系统持久化的快捷菜单和真实启动链路。生产安装与用户的任务栏固定项未被测试修改。构建与校验信息见 `release-1.0.11.json`。
