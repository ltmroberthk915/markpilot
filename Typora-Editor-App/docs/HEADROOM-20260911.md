# 多维度量化：现在还有多少改进空间（2.0.17，2026-09-11）

用户问的是"是不是基本上没有什么改进空间了"。结论：**不是**。功能与体验维度已经接近可用上限
（滚动 0 掉帧、还原误差 4px、复制全部字节级通过），但**还有三块有量级意义的空间**，且每一块
都已经量到"现状数字 / 成本构成 / 能省多少"。下面是证据与估算，不是感觉。

测量口径：桌面安装版 2.0.17（`npm run accept`，8 场景 89 断言全绿）+ 开发树性能探针
`scripts/ir-perf-probe.cjs`（大素材 143,656 字符 / 245 KB / 2002 块 / 2500 处公式预览）。
延迟类取多次样本的**最小值**（单次冷启抖动实测 1.5s–5.3s），台账 `.perf/acceptance/baseline.json`。

## 二、还剩三块空间（按"收益 ÷ 成本"排序）

### 1. 冷启动的页面内 1.2 s —— **最大的一块，可省 ~1.0 s**
小文档冷启的 1538 ms 里，**1234 ms 是编辑器 iframe 装载 Vditor + Lute（3.8 MB）并首次解析渲染**，
与文档大小几乎无关（小文档 1234 ms vs 大文档 1629 ms）。也就是说：**打开任何文档都在先付这笔
固定开销**。

- 办法：应用启动后（首屏之后）**预热一遍编辑器 iframe**——把 Vditor、Lute、我们的补丁都装好，
  只等文档内容；真正打开时只灌内容。热打开已经是 128 ms，说明"装好的编辑器能让打开变成 0.1 s 级"。
- 预期：小文档冷启 1538 → **~500 ms**（窗口 488 + 灌内容 ~100）；中大文档同比例受益。
- 成本/风险：启动时多 ~1.2 s 的后台工作（放在首屏之后、分片做，用户不感知）；内存要提前付一份
  编辑器宿主（约 100–150 MB）；实现上要处理"预热宿主与当前文档的 iframe 复用"这条路径。
- 这是**唯一有量级收益**的剩余项，也是本轮之后我建议优先做的一项。

### 2. 大文档打开期间的长任务 461 ms + 139 ms —— 可省 ~100–200 ms
现状：首次排版的 461 ms 块必须在首屏之前完成（属硬成本），但 `markdown-prime` 还有单片
139 ms 的预热片、以及 91/139 ms 的两块后续任务。把它们再切细（片预算从 8 ms 降到 4 ms，
或把 prime 拆成"只算可见块 + 空闲补全"）能把 p95 卡顿再压一档。
- 预期：首屏 975 ms → **~850 ms**；用户可感的"卡一下"变少。
- 成本：低（改分片预算与 prime 顺序，不动架构）。收益：中。

### 3. 打字 p95 28 ms 与我们自己的 ~6 ms/键 —— 可省 ~5–8 ms/键
上一轮归因：每键成本里 Vditor 自己的 IR 光标复位（`removeAllRanges 282 ms + addRange 118 ms / 40 键
≈ 10 ms/键`）占大头，**我们自己的代码约 6 ms/键**（`refreshMathEditing` 全篇扫公式 ~3 ms + 调度 ~3 ms）。
"输入重解析收窄到当前块"这条 2026-09-05 就记下的修法，只能省下我们那 6 ms 里的一部分。
- 预期：均值 15.1 → **~10 ms**，p50 9.6 → ~8 ms；p95 主要取决于 Vditor/Blink，压不动。
- 成本：中（要动刷新范围与公式编辑态，有"展开态残留"的可见风险）；收益：小到中。

## 三、已经到底、不建议再动的部分

- **滚动**：0/180 掉帧、p95 16.8 ms（一帧预算 16.7 ms），已经没有可优化的空间；再动只会引入风险。
- **位置还原**：4 px 误差已低于人眼可辨（< 半行高），继续抠只剩噪声。
- **功能正确性**：8 场景 89 断言覆盖了打开/热打开/多选复制两条顺序/表格 CF_HTML/单图位图/
  软换行/位置还原/滚动；剩下的都是"补覆盖面"而不是"修缺陷"。
- **内存**：要再降必须虚拟化编辑面（把不可见块真正从 DOM 摘掉）或改公式渲染策略——前者与产品
  的"所见即所得编辑面"约束冲突（上轮已判定不做），后者的天花板是那 2500 个公式预览节点。
  在没有新约束（例如接受只读模式下才虚拟化）之前，**不建议动**。

## 四、复现命令

```bash
npm run accept                                   # 安装版 8 场景（数字进 .perf/acceptance/installed/report.json）
node_modules/electron/dist/electron.exe scripts/ir-perf-probe.cjs \
  --label=quant --fixture=".perf/acceptance/fixtures/large.md"   # 首屏/长任务/打字/内存
node scripts/acceptance/run.cjs --app=installed --label=tmp --only=scroll   # 滚动帧间隔
```

## 五、一句话总结

**"把该修的都修完了"和"没有改进空间"是两件事**：功能与体验维度确实到顶了（掉帧 0、
还原 4px、复制全字节级通过）；性能维度还剩一块**量级收益**——冷启动那 1.2 s 的编辑器装载，
靠"启动后预热编辑器宿主"可以压到 0.5 s 级；再往下是两处 100 ms / 5 ms 量级的细活。
这三项都已在上面量化到"能省多少、要付什么代价"，下一轮可以直接按收益顺序开工。
