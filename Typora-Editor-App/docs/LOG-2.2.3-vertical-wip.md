## 一 方法论：为什么随机全篇能抓到、我自己的夹具抓不到

不是"测得少"，是**形状是照着我的假设挑的**：

- 我写的场景（109/110）夹具是"纯公式行夹在两段之间"这种干净形状，断言写的是**我的实现**
  （"光标进公式源码"）。假设对不上真实文档的地方，夹具根本走不到。
- 真实文档里全是我没造的东西：标题行、`**加粗**` 领起的行、折行长段落、空公式块、
  行内公式在行首/行中/行尾、块公式多行源码——每一类都可能让"我假设的几何"失效。
- 判据层级也错了：我断言**机制**，用户感受到的是**属性**（看得见 / 一次一行 / 列不跑）。
  机制对了、属性错了，我的绿灯没有价值。

改法（已写入 `references/acceptance.md` §7，成为默认风格）：

1. 形状来自**真实材料副本**（`--file=<副本>`，原件只读）；
2. 判据必须能用用户的话说，并在**随机起点**下全篇成立：可见性 / 逐行性 / 列稳定性；
3. 固定 seed、偏离样例带"起点+目标列+实际落点"（可定点复现）；
4. 探针自己的记账只看**可见读数**（隐形读数 y=0 会把"还能不能继续走"判错——见 §3）。

## 二 四类缺陷：机制与现状

| 类别 | 机制（实测证据） | 现状 |
| --- | --- | --- |
| **隐形落点**（"光标没了"） | Vditor 的方向键处理在**边界**上给出 0×0 的位置；放行就会接手 | **已修**：到顶/到底直接拦下、什么都不做。全篇行走 0/5 轮 |
| **逐行性**（按了不动 / 跳行） | ① 扫描把"整行只有一条行内公式"的行整行跳过：那行里只有 contenteditable=false 的渲染结果，`caretRangeFromPoint` 给的是不可编辑位置；② 折叠态公式源码自己的 rect 是 0×0，被"可用性"筛掉 | **已修**：`formulaLineAt` 把目标列映射进源码 + `boxOf`（几何退回**公式节点**的盒子）。双向 14/14 步、场景 109⑤/110①③ 全绿 |
| **上移失灵** | 探针记账 bug（隐形读数当了锚）**不是产品缺陷**——这一点是靠版本标记 + 最小手势排查出来的 | 已澄清（见 pitfalls §29） |
| **列稳定性** | 每次按键后 Vditor 自己的 `c ← B` 都会重设一次选区（`removeAllRanges + addRange(它算的区间)`，它只看行不看列）；我们放到**window 捕获段**抢先，能把列守住（定向诊断：目标列 60 → 落点 59/59/60/60 ✓），但**全篇行走里仍有 17–22 处/轮**落在行首或行尾 | **未修完** |

列稳定性剩下的部分有两个已知来源：① 公式边缘的归一化（`refreshMathEditing` 会把贴边光标挪到公式外侧，
这是产品既有语义）；② 我们写完选区后仍可能被 Vditor 的 selectionchange 处理改写（行内公式"每两下塌一次"
就是同一个机制）。下一步：把校正挂到**它之后**（监听 selectionchange 一次性重放目标列），
并把"公式边缘归一化"算进判据（贴边钳制不算偏离）。
