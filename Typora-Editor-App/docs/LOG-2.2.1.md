# LOG-2.2.1：围栏当普通字符 + 空公式看得见 + 纯公式行不再被纵向移动跳过

本轮没有发布动作（未打包、未推远端、未上架）。记录的是 2026-09-17 用户报告的四件事、
复现证据、根因、修法、口径变更的边界，以及如实留在账上的东西。

## 一 用户报告（原文照录，便于以后对账）

1. `$$\n\n$$` 这样的空块公式"渲染后根本无法从页面上看到, 会留下很多隐形垃圾, 且无法被选中删除"。
2. 块公式（有内容）光标停在闭围栏 `$$` 之后，按住 Shift 连按 ← "尝试选中失败"。
3. "上下方向键遇到 单行仅有 inline math 的 会导致光标跳过这一行, 而非正常逻辑上跑到 inline math 行最后"。
4. 紧贴公式块时弹的那句提示（"这里紧贴公式块，退格/删除会把公式拆散，已拦下；要删整条公式请先选中它"）
   "不如直接帮用户选中, 展开编辑公式代码形态, 光标插到最后"；随后追加总口径：
   "点退格也好，方向键也好，鼠标拖拽选中也好，最好能直接把这些 fence 当普通字符处理，
   你现在这样太别扭了，卡手"，并提醒"这是一项系统性改变…可能会导致我们之前很多 patch 会出问题"，
   要求派子代理调查影响面。
5. 另一条独立报告：把行内公式 fence 内的内容删掉之后"会突变成 block math fence"。

## 二 复现与根因

全部读数来自 `scripts/acceptance/` 下的探针（都在仓库里，可复跑）：

| 现象 | 探针 | 根因（实测） |
| --- | --- | --- |
| 空块公式看不见 | `probe-empty-block.cjs` | 空块源码实测是**一个换行**（`"\n"`，不是空串），KaTeX 对空源码什么都不画；折叠态下源码与 `$$` 都是隐藏的，页面上只剩一块 93px 的空白，没有任何可命中物 |
| 空块里按删除写坏文档 | `probe-empty-delete.cjs`（DOM/Selection/execCommand 代理 + 调用栈） | 光标在块源码里（`code@0`）时走的是浏览器默认删除；`pre>code` 被删成 Lute 认不出的形状，markdown 当场写进一行**字面 `span`**（`$$\nspan\n$$`） |
| 闭围栏后 Shift+← 选不中 | `probe-math-keys2.cjs`（Selection API 代理 + selectionchange 时间线） | 我们的方向键补丁只认 `data-type="inline-node"`；块公式源码里的方向键整个交给 Vditor 自己的 keydown，它每次 `removeAllRanges()+addRange(自己算的区间)`，而算出来的区间**每两下塌一次**（选中 1 个字符 → 长度 0 → 又选中 1 个字符） |
| 纯公式行被纵向跳过 | `probe-math-keys.cjs`（同一文档只换中间那一行） | Chromium 按"可编辑落点"的行盒找纵向目标：纯文字/`$a$ $b$`/`$a$ 乙` 都正常，**只有单独一条 `$a$`** 被整行跳过——那一行上只有折叠态的公式（围栏 display:none、源码隐藏、渲染结果 contenteditable=false），没有任何可编辑落点 |
| 行内公式删空 → 突变成块围栏 | `probe-fence-text.cjs` F7 | 空的行内公式被序列化成独占一行的 `$$`，下一次解析就成了块公式围栏。**修法不能只放在 `commit()` 里**：打点计数证明这条删除路径不一定经过 commit（commit 1 次、blank 0 次） |

## 三 口径变更（这是本轮最大的一件事）

旧口径（2.1.1 起逐步建立）：**围栏上/贴边按退格只弹一句说明，文档一个字节都不改**
（`FENCE_HINT` / `BOUNDARY_HINT` / `hopOutside`）。它换来的是"不会误伤公式"，代价是
"按下去没反应"——用户这次的判词是"太卡手"。

新口径（按用户要求照 Typora 的围栏手感）：

- **行内公式的 `$` 是真字符**：贴边退格 = 删掉靠这一端的那一个 `$`，公式降级为字面文本
  （`$a$` + 退格 → `$a`，内容一个字符都不少）。光标站在围栏文本上时同样按这一个字符处理。
- **块公式的 `$$` 不做成可删字符**，改成**删源码里靠自己这一端的一个字符**（退格删尾巴、
  删除键删开头）。两条实测理由：① 块围栏文本是渲染生成的，直接改它的文本 `getValue()`
  一个字节都不变（用户按下去像"什么都没发生"，F6/F9 都量到）；② 真去 markdown 里把围栏写成
  单个 `$` 会让 Lute 重新配对围栏、把后面的内容吞进公式源码，而我们的"未闭合围栏收尾"
  （`math-markdown.js`，场景 102）又会把它补回来——一次退格跟两条自动化规则打架。
  块公式在 Typora 里光标本来就在源码里，`$$` 只是外壳，删源码字符与它一致。
- **只保留一类"不改文档"的手势**：紧贴块公式的**块级边界**（相邻段落首/尾、块级位置相邻）。
  实测放行给浏览器时一次退格会把**后面那一整段删掉**（F5：`后段乙` 从 markdown 里消失）。
  这一类不再弹说明，改成展开成源码形态并**整条选中**（用户原话："直接帮用户选中, 展开编辑
  公式代码形态"）；第二次按键按常规选区语义删掉选中的源码。
- **空公式看得见**：渲染落定时按源码是否为空挂 `data-empty-math`，`index.css` 画一枚
  "空公式"占位（虚线框、随主题取色）。空块里按退格/删除 = 整条移除（不再写 `span`）；
  行内公式只剩最后一个字符时按删除 = 整条摘掉（不留空壳，也就不会突变成块围栏）。

## 七 我自己引入又修掉的缺陷（如实记账）

1. **TDZ**：把"移动端"计算提到 `forward` 声明之前，`forward ? ... : ...` 在暂时性死区里抛
   `ReferenceError`；异常被外层吞掉，表现成"整段补丁静默失效"——现象是"方向键补丁好像没装"。
   排查过程：先复算守卫（全通过）→ 打点（走到"步进段"就停）→ 加 try/catch 定位到
   `sourceOffset` 之前。修法：`forward` 提前声明，并在注释里写明这个坑。
2. **`recoverMarkerInput` 越界恢复**（第四节表里那条）：把正常 `$$` 的第二个 `$` 搬进源码，
   场景 74 的"在前 `$$` 处打字"抓到的。
3. 一次探测里的临时探针片段（`probe-empty-delete.cjs` 的日志、`probe-arrow-fault.cjs`）留在
   `scripts/acceptance/` 下，属于取证工具、不是产品代码；产品代码里的临时打点已全部摘除
   （`grep -c "TEMP-INSTRUMENT\|__arrowTrace\|__dbg"` 为 0）。
