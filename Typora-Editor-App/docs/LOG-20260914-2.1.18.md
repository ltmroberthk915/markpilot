# 2.1.18 工作日志（2026-09-14）：候选框里的「同一类」是内部字眼

用户在自己机器上目测 2.1.17 时发现：「候选框还有『同一类』这种工程字眼漏出来了」。

## 一 成因

2.1.17 加"同类补全"时，我在候选的说明栏（面板右侧那列 `<small>`）给同族条目加了后缀
`· 同一类（字体）`，本意是让用户知道"这条为什么也被列出来"。**分组名是实现细节**，不该出现在界面上。

## 二 修法

`render/js/completion-sources.js`：`detail` 一律等于命令自己的中文解释（`detail: title`）；
`group` 只用于挑同族兄弟，不再参与展示。（表里那 13 个分组常量仍然保留——它们是同类补全的依据。）

## 三 回归门（把用户的口径写成断言）

场景 90 原来断的是"说明里 ≥4 条标出同一类"——**这条现在反过来断**：

```js
const explained = mathbb.说明.filter(text => /同一类|同一组|分类：|·/.test(text)).length;
ctx.assert('候选说明栏只放命令自己的中文解释：不许漏出"同一类"这类分组/工程字眼', explained === 0, …);
```

（正则第一版写得太宽——把分组名本身也列进去，结果 `\uparrow` 的说明「上箭头」撞上「箭头」误报，
实测一次后收窄为"内部字眼"本身：`同一类|同一组|分类：|·`。表里没有任何一条自带 `·`，所以这条判据干净。）

其余断言照旧：`\mathbb` 带出 5 个指定同族且首条是它自己、`\frac`/`\sum` 各自的同族、
只敲 `\` 时前四条仍是 `\frac,\sqrt,\sum,\int`、`\m` 时不堆同族（改成断"每条标签都以 `\m` 开头"）、
以及选第二条按 Tab 真的插进公式源码。场景 90 = 11/11（6 证人）。
