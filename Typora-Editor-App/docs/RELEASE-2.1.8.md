## 1. 逐窗口关掉应用之后，窗口与文件全都回来

**根因**：关窗处理器把"用户只关掉一个窗口"和"用户在逐个关窗口把应用关掉"当成同一件事——一律
`detachRec()` 把这个窗口从 `state.windows` 里划掉。于是逐个点 X 时，每关一个就少一个，最后只剩
最后关掉的那个（"哪一个幸存"纯属偶然，所以表现看着随机）。另外 `win.on('closed')` 里那次
`persistWindows()` 会在窗口销毁后重算名单（此时 `recs()` 已经空了），是否把名单写空取决于
400 毫秒的落盘防抖——这是同一个现象"时而一个、时而一个都没有"的来源。

**修法**（`app/main/main.js`）：
- 关掉一个窗口只是**挂起**（`pendingDrops`），带 5 秒宽限：宽限期内应用退出了 → 撤销；
  宽限期到点应用还活着 → 才真正落盘删除（保留"只关掉一个就不再恢复"的原语义）。
- 应用开始退出（`quitting` 或这是最后一个窗口）时把会话名单**冻结**（`exitSession`），
  之后窗口一个个销毁都不再重算，也不许宽限定时器在退出途中把名字删掉。
- 窗口销毁（`closed`）时只从注册表里拿掉，不再重写会话。

**判据**：`scripts/acceptance/scenarios/80-session-and-scroll-2.1.8.cjs` 的 H 组——关掉第一个窗口的
当下它仍挂在名单里（2 条）；两个都关完、进程退出后名单仍是 2 条；重启后两个窗口连文件一起回来。

## 2. 打开文档时滚动还原在 1 秒内收工（不再抖满 6 秒）

**根因**（`extension-src/render/js/util.js`）：判断"锚点贴准了没有"的 `anchorError()` 把两项相减的
顺序写反，返回的是 **2×偏差**——实测偏差 1 像素时它报 2、偏差 −11 时报 22，永远越不过自己定的
`<= 2px` 收敛线。于是 `ticker`(120ms)/`poll`(250ms) 会把滚动位置重写到 `ANCHOR_GIVE_UP_MS`
(6000ms) 兜底为止：实测 **applies=76**（正常应 ≤10）。这 6 秒里任何布局变化都会被重新"粘"一次，
就是你感觉到的抖动。

**修法**：判据与贴位置用同一口径 `|(block.top − view.top) + delta|`；并且修正量不足 1 像素时
不再写 `scrollTop`（写入会打断浏览器自身的滚动锚定，反而制造小幅跳动）。

**实测对照**（同一份用户 state.json、同一个文件、同一个 1030×656 窗口、60ms 采样）：

| | 修前 | 修后 |
| --- | --- | --- |
| 锚点误差读数 | 2（=2×delta，永远不收敛） | 0 |
| 收工时刻 | 6.3 秒（兜底） | **1.16 秒** |
| `applies` | 76 | **13** |
| 收工后画面 | 静止 | 静止 |

## 3. 右键菜单不再压住鼠标和你点的那一行

**根因**：编辑器右键菜单（`render/js/media-tools.js`）与侧栏文件树右键菜单（`app/shell/shell.js`）
都把菜单左上角钉在 `(clientX, clientY)` 上，鼠标与被右键的那一行都被盖住。

**修法**：四个候选位置依次尝试——那一行下方 → 那一行上方 → 鼠标右侧 → 鼠标左侧，取第一个
"整块在屏内且不覆盖鼠标"的；四条都放不下时退回"屏内 + 不压鼠标"的最靠近位置（菜单内部本来
就能滚动）。正文菜单同时保证不覆盖被右键的那一行。

**判据**：场景 80 的 J 组，两处菜单分别量 `getBoundingClientRect()` 与鼠标点、被点行的矩形，
断言四者两两不重叠。
