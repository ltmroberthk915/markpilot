# 2.1.14 工作日志（2026-09-14）：点字的"上半截"把光标扔到行首

用户第 5 条报告（决定性线索）：

> 点这个最后一个 "计"字中心偏上会触发! 实测任何字的偏上都会触发, 应该是点击在行内相对高度判定的问题

## 一 先认我的方法错在哪

前几轮我把那一行**逐字点了一遍**（101 个字），结论是"全对"——因为落点取的是**每个字的中心**
（`c.y + c.h / 2`）。这个 bug 只在**字的上半截**触发，点中心永远碰不到。101 个字全部"通过"，
恰恰把真正的缺陷盖住了。用户一句"偏上"补上了我缺的那个变量。

**教训（写进规矩）**：判定"点击落点 → 光标位置"的探针，纵向至少要取**上缘/中心/下缘**三点；
只测中心等于没测。

同一轮里还有一次**自己造的假证据**：`probe-paren2.cjs` 早期版本用 `const c = m.cells[i] || m.cells[0]`
取目标字符，`i` 算不出来（`indexOf` 返回 -1）时退化成"点第一个字"，于是报了一次假的"❌ 跑到行首"
（真相是那次点的是「即」，光标当然在 0）。已删掉兜底、改成算不出来就抛错。

## 二 复现（真产物 2.1.13 + 用户文档，确定性）

`probe-paren12.cjs`：定位用户截图里那一行（含 `$\sum b_i\mu\{1^{-1}_{A_i}(b_i)\}$`），
段落里每个可见字符 × 纵向三点（上缘+2 / 中心 / 下缘-2），共 162 次真点击，每次前把光标放回段落末尾做中立位。

判据：`|光标可见位 - 点的那个字| > 2` 记偏离（落点在公式源码里的单独统计，那本来就该进源码）。

| 纵向位置 | 修前 偏离（落在正文的点击） | 修后 |
| --- | --- | --- |
| **上缘+2** | **27/29** | 2/30 |
| 中心 | 1/29 | 1/29 |
| 下缘-2 | 1/29 | 1/29 |

修前那 27 次光标全部落到 `(PRE.vditor-reset, 92)`——**编辑器根下第 92 个块的边界**；
而那一行正文正是第 92 个块，所以光标显示在**这一行的最开始**。与用户描述一致。

## 三 根因（几何量到像素 + 栈追踪）

`probe-paren13.cjs` 做两件事：

1. **栈追踪**（patch `Selection.prototype.*` / `Range.prototype.*`，过滤掉探针自己的调用）：
   坏落点那一次的调用栈是
   `Range.setStartAfter ← HTMLPreElement.fenceClick (js/math-edit.js:741)`
   `Selection.removeAllRanges/addRange ← fenceClick (js/math-edit.js:743)`
   → 是 `fenceClick` 里 **`blankLanding` 那一支**干的。
2. **对照 Chromium 自己的答案**：同一个像素 `document.caretRangeFromPoint(x,y)` 一直返回
   `TEXT(（原笔记此处写作 ) offset 2`（正确的文字位置）——也就是说**浏览器本来是对的，是我们的处理器把它改坏的**。

几何（同一份文档）：

```
块 90：<p>                                           y = 216 .. 241
块 91：DIV[data-type="math-block"]（130px 高的 $$…$$）  y = 257 .. 387
块 92：<p>（用户说的那一行）                            y = 387 .. 412
```

`blankLanding` 的纵向容差是**公式盒 ±10px**；块 91 的底（387）+10 = 397，
而块 92 的字形盒大约从 y=386/391 起 —— **"正文第一行字的上半截"整段落在容差里**，
被当成"公式下方的留白"，落点被翻译成公式之后那个插入点 `(根, 92)`。

`blankLanding` 存在的理由必须保留：留白不属于任何块，Chromium 会把那个点解析成隐藏源码里的位置，
接着一次退格就吃掉公式里一个字符（2.1.3 修的老问题，`test:math-caret` 里有 5 组断言看着它）。

## 四 修法（`js/math-edit.js`，一处）

留白在几何上就是"**任何块的盒子之外**"，所以给出结论前先看落点有没有压在**别的块**的盒子里：

```js
const other = kids[index === lo ? lo - 1 : lo];
if (other) { const side = other.getBoundingClientRect();
  if (y >= side.top && y <= side.bottom && x >= side.left - 1 && x <= side.right + 1) return null; }
```

压着就认定是正文，交回给浏览器。实测（`probe-paren13`，同一行 8 个纵向位置）：
修前 8/8 落到段落之外，修后 8/8 落回正文文字。
