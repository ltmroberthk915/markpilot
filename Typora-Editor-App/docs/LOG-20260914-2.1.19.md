## 一 查到的成熟做法（作为策略依据）

VS Code 的补全排序模型（`vscode.d.ts` 的 `sortText` 说明 + `base/common/filters.js` 的 `fuzzyScore`）：

- **匹配质量决定次序**：`sortText` / 声明顺序只用于初始排序；一旦键入前缀，排序按"匹配得多好"来，
  只在**匹配得一样好**时才回到 `sortText`、`priority`、`preselect`、`kind`、`label` 这些平局键；
- 匹配分里对**词首命中**（`matchOnWordStartOnly`）与**连续命中**给加成，对跨度扣分；
- 常见语言服务的做法（gopls/clangd 的 `filterText` 技巧）也印证：想要自己的次序生效，就得让
  "匹配分"这一层不再主导。

LaTeX 命令补全落到我们这份表上：**完全命中 → 前缀命中 → 同族兄弟**是最要紧的三档，
模糊命中只该当兜底。

## 二 旧实现错在哪（两处，都是量出来的）

```js
const score = key => (key === prefix.slice(1) ? 10 : 0) + (nearby.includes('\\' + key) ? 3 : 0);
```

1. **上下文跨档提权**：`nearby` 里出现过就给 +3，对**所有**条目生效 → 一个含 `\int` 的公式里，
   `\int` 拿到 +3、`\in` 因为 `\\in` 是 `\\int` 的子串也拿到 +3 → 它们压过了按常用度排在前面的命令
   （截图那三行）。旧实现还用 `String.includes` 判"出现过"，子串误判正是 `\in` 的来源。
2. **同族补全的触发条件写错了**：`rows.length < FAMILY_BELOW` 里的 `rows` 含**模糊命中**，
   于是敲 `\frac` 时（前缀只有 1 条，但 `\dfrac`/`\tfrac`/`\cfrac` 三条模糊命中已让 rows=4）
   同族补全被整个跳过，`\sqrt` 消失（单元探针 `probe-cands-unit.mjs` 量到）。

## 三 新策略（`render/js/completion-sources.js`）

分档（越小越靠前），同档内次序 = 本文档公式里已用过（精确 token，只作**同级**次级键）→ 表内声明顺序：

| 档 | 含义 | 例子 |
| --- | --- | --- |
| 0 | 完全命中命令名 | 敲 `\mathbb` → `\mathbb` 第一 |
| 1 | 前缀命中（同档按"键入部分占命令名的比例"降序） | 敲 `\math` → `\mathbb`/`\mathbf`（6 字）先于 `\mathcal`（7 字） |
| 2 | **同族兄弟**（插在强命中之后、弱命中之前；同族内按"与命中那条的最长公共前缀"降序） | `\mathbb` → `\mathbf`（公共前缀 `mathb`）→ `\mathcal`/`\mathscr`（`math`）→ … |
| 3 | 说明（中文）命中 | 键入含中文的 token 时（当前上下文的正则只产出 `\`+ASCII，所以这条是备用档） |
| 4 | 子序列模糊命中（`fuzzyScore`：词首/连续加成、跨度扣分；只对 ≥2 字符的 token 开） | 敲 `\lr` → `\leftrightarrow`、`\Leftrightarrow` |

另外把 `\text` 从"字体"组挪到独立的"文字"组（它是文字排版，不是数学字母表），
这样 `\mathbb` 的同族顺序正好是 `\mathbf`、`\mathcal`、`\mathscr`…（也正是用户点名的那两条靠前）。

