## 二 四条各自的取证过程

### ①「点数和句号之间，光标跑到句子前面」

2. `probe-four-1b`（拆因素）→ 只有加粗的段落（无公式）同样中招 → 与公式无关。

   **这条弯路记在这里：量测方法本身会造出假症状。**
4. `probe-four-1f`（自证动作：点一下再打 `X`，读源码）→ 八个落点的插入位置全部合理，光标定位本身没错。

   但**退格会吃掉一个星号**（`导数**。` → `导数*。`），`Shift+←` 两次再打字会插出 `*X*`。
6. `probe-four-1h`（A/B 老产物）→ **2.1.8 一模一样**：不是这一轮带出来的，是长期存在的"记号洞"。

### ②「向上拖拽公式区抽搐抖动」

1. `probe-four-2/2b`：逐拍（40ms）采四条公式的 top + class 变动计数。

   - 向下拖：`layoutChanges 3`（几乎只是"被翻开那条变成 0"的正常现象）；
   - **2.1.8 基线：`layoutChanges 0`、`mut 0`**——旧版这条手势根本不产生选区（所以"不抖"是因为什么都没发生）。
2. `probe-four-2c`（把每次 DOM 变动连属性一起记下来）→ 12 次全部是
   `SPAN.vditor-ir__node → vditor-ir__node--expand` 的来回切换，即 **Vditor 把端点所在的公式原地翻成源码**，
   行宽行高随之变化，指针下的文字位移，端点又落到另一条上 —— 反馈环。

4. 复测：`layoutChanges 0`、四条 top 全程 `[181,204,226,249]` 一动不动（class 仍在切换，但不再影响布局）。

### ③「图片要两次 Ctrl+Z」

`probe-four-3` / `3b` / `3c` / `3d` / `3e` / `3f` / `3g` 共 17 种走法（开发树 / 2.1.8 / 已安装 2.1.10 三处）：

## 三 走错的路（留证）

1. **按下那一帧读几何 = 破坏光标判定**。记号守卫最初在捕获阶段 `mousedown` 里读每个记号的可视性
   （`getComputedStyle`/`getBoundingClientRect`）。结果既有用例 `math-caret` 的"行尾输入落在公式之后"直接红：
   点段尾空处时光标从**段尾跑到段首**。对照实验：
   - 只把 `armed` 改成 false（**照旧读、不动作**）→ 一样红；
   - 把读取整段去掉 → 恢复正常。
   结论：问题出在"按下这一帧强制布局"本身，它改变了 Chromium/Vditor 对"点在空处"的落点判定。
   最终实现：按下只置标记、**零读取**；判断推迟到 `selectionchange`（光标真落进记号之后）。
2. **`isCode` 规则**。Vditor IR 里**公式源码的 `code` 元素也带 `marker` 类**。守卫第一版把"光标在 marker 里"
   当成"在记号里"，于是块公式点击后被从源码里请出去、落到 `$$` 围栏上——`math-caret` 的
   "点击块公式后光标落在源码里" 报 `TEXT($$)@2`。修法：`code` 一律按内容算，且块公式节点整类跳过。
3. **量测方法的假象**（见 ①-3）：光标矩形不可信，改用自证动作。
4. **块公式点击映射回归（我自己上一版带出来的）**。跑 `npm run test:renderer` 抓到
   `Display math preview locates its separate source block: 源码光标偏移错误: 0 != 9`。
   二分：把这一版全部改动关掉（≈2.1.10 基线）**同样失败** → 不是这一版；继续二分到
   2.1.10 给点击映射加的 `if (host.dataset.type !== "inline-node") return;` —— 那道门把块公式的点击也挡住了。
   修法：块公式改成"**映射成功才接管**，算不出偏移就还给 Vditor 的 rawblock 路径"。修完
   `test:renderer` **354 通过 / 0 失败**，`math-caret` 58 条仍全绿。
5. **场景 70 的假失败**。`存盘后磁盘上的这一行公式真的变了` 在 2.1.10 打包产物上同样红。查证：
   断言把磁盘行写成 `| 甲 |`（单空格），而 Lute 存盘会按列宽补空格（`| 甲   |`）；用探针直接读磁盘
   证明**编辑是写下去了的**（`$x^2\cdot 2+1$`）。同时断言还假设"打字插在公式最前"（点击落点映射到
   源码中间是**正确**行为，渲染层套件里那组映射用例是绿的）。已把断言放宽为"磁盘行含这次插入的
   `\cdot 2`、且仍在一条 `$…$` 里"，产品行为未改。
