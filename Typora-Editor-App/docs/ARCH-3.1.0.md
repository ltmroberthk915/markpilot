## 0 测量纪律（真事故换来的）

以下各条各自对应本轮的一次**误读数或假结论**；违反任一条都可能得到"看起来对"的错结论。

1. **起 dev 引擎前必须清 `ELECTRON_RUN_AS_NODE`** —— 宿主环境设置了该变量时，`electron.exe` 会以**纯 Node 模式**启动：`require('electron')` 只拿到二进制路径、`app` 未定义、进程**秒退**。清掉后 CDP 约 1 秒就绪。（`spawn` 前 `delete env.ELECTRON_RUN_AS_NODE`。）
2. **"同步前的副本"陷阱** —— 改 `src-cm6\**` 后 `MarkPilot-CM6\renderer\cm6\app.js` **不会自动更新**（同步是显式一步、且单向）。⇒ **验行为前先确认两份 `app.js` 哈希一致**，否则你验的是上一版。
3. **CM6 只给可见区建 widget DOM** —— 视口外的行没有 DOM。⇒ 任何"图片数量 / 出图率 / widget 数"读数**必须标注是"视口内"还是"全篇扫"**，两者数量级可以完全不同。
4. **`scrollHeight` 会随 widget 渲染变大** —— 图片 widget 一建，文档总高就增长。⇒ **只在开头读一次 `scrollHeight` 必然漏尾部**；要按 mark **逐个定位**（滚到它、再读）。
5. **失败态是"秒级"事件** —— 远程图 403 的实测落定时间是 **4.4s / 9.6s**。⇒ "有没有占位 / 有没有出图"**必须等落定**再读；早读会得到"既没图也没占位"的中间态。
6. **剪贴板是全局唯一资源** —— 并行实例会互相顶掉：期望的载荷被换成**别人**的表格 TSV（`names` 里出现 `HTML Format` / `Chromium internal source URL` 就是被顶）。⇒ 剪贴板判据必须 **seq 配对**（读前后序列号）+ **被顶就重试** + **读 `names` 判外来口味**。
7. **GDI 类剪贴板格式不是 HGLOBAL** —— `CF_BITMAP`(2) / `CF_METAFILEPICT`(3) / `CF_ENHMETAFILE`(14) 是 **GDI 句柄**，对它调 `GlobalSize`/`GlobalLock` 会**崩掉枚举进程**（`0xC0000374 STATUS_HEAP_CORRUPTION`、**零输出**）⇒ 该读数**整条报废**。而"位图在场时读剪贴板"正是**位图类判据的必需动作**（判据：剪贴板先放位图 ⇒ 复制后位图必须消失或换载荷）⇒ 这个崩溃点刚好落在最关键的一条判据上。**已修**：GDI 类只记 `kind='GDI-handle'`、**不读载荷**（`bytes:0`）。
   **修后实测**（用"位图在场"这个**原本必崩**的前提）：`pwsh 7` 与 `powershell.exe 5.1` 均输出 `DONE seq=18877 formats=3 [CF_DIB,CF_BITMAP,CF_DIBV5]`，两份 JSON（`clip-bs7.json` / `clip-bs51.json`）**`seq`/`formatCount`/`names` 三项全一致**。
8. **`.ps1` 必须带 UTF-8 BOM** —— 否则 PowerShell **5.1** 按 ANSI 解析文件里的中文注释 ⇒ **语法错、JSON 不生成** ⇒ 判据拿到空串而**假红**（复核时因此吃过 7 条假红）。`cu\` 下 4 个 ps1（`clipdump` / `excel-paste` / `clip-setimage` / `clip-settext`）**现已全部带 BOM**。
   **附注（本轮实测的一个不对称）**：修后 `clip-bs7.json`（pwsh 7 写）**无** BOM，`clip-bs51.json`（5.1 写）**有** BOM ⇒ **读这两份证据时要用"去 BOM 再 parse"**（Node CLI 的 `JSON.parse` 会因 BOM 直接抛 `Unexpected token`）。

## 0b 读数陷阱（会制造假结论的那些）

§0 是"起环境与读证据的基本纪律"；本节专收**看起来读到了、其实读错了**的那些坑，按五组归并。
每题只写：**机制 → 症状 → 正确做法**。有盘上证据的标出路径。

### B1 宿主 / 启动

- **清 `ELECTRON_RUN_AS_NODE`**：该变量在场时 `electron.exe` 以**纯 Node 模式**启动，`require('electron')` 只返回二进制路径、`app` 未定义 ⇒ **秒退**；表现为"引擎起不来"。清掉后 CDP 约 1 秒就绪。
- **"同步前的副本"陷阱**：`dsh-markpilot\src-cm6\**` 变更后，`MarkPilot-CM6\renderer\cm6\app.js` **不会自动更新**。官方同步脚本 `MarkPilot-CM6\scripts\sync-engine.mjs` 头部即写明"**只读同步**……本应用**永不手改**引擎产物，只做字节级复制并校验"，且方向单向（`SRC = dsh-markpilot/renderer-cm6` → `DST = ../renderer/cm6/`）。⇒ **验行为前先断言两份 `app.js` 逐字节同一**（`Buffer.compare === 0`），否则你验的是上一版。

### B2 读数有"状态前提"

- **CM6 只给可见区建 widget DOM** ⇒ 任何"图片数量 / 出图率 / widget 数"读数**必须标注是"视口内"还是"全篇扫"**，两者数量级可完全不同。
- **`scrollHeight` 会随 widget 渲染变大**：图片 widget 一建，文档总高就增长 ⇒ **只在开头读一次 `scrollHeight` 必然漏尾部**；要**按 mark 逐个定位**（滚到它、再读）。
- **失败态是"秒级"事件**：远程图 403 实测落定 **4.4s / 9.6s** ⇒ "有没有占位 / 有没有出图"**必须等落定**再读，早读会拿到"既没图也没占位"的中间态。
- **toast 有寿命**：`toast(text, ms = 1800)`（`extras.js`），`.mp-toast` **1800ms 后自动隐藏** ⇒ 提示文案类判据必须**按键后立刻轮询**（建议 100ms 一档、上限 3s）。**2500ms 后再读永远读不到**（不是没有提示，是已经消失了）。
- **粘贴/插入后原地读 `.mp-img` 会得到 `[]`**：因为 **F7 规则** —— 光标落在 image mark 内且 `src.length ≤ 512` 时**故意不挂 widget、露源码**（`inlineMarkDecorations` 里 `longSrc = mark.image.src.length > 512`，短 src 且 `inSel` 时不建 widget）⇒ **先移开光标再读**，否则会把**正常行为**误判成"没出图"。

### B3 剪贴板（全局唯一资源）

- **会被并行实例顶掉**：期望载荷被换成**别人**的表格 TSV —— `names` 里出现 `HTML Format` / `Chromium internal source URL` 即被顶。⇒ 判据要 **seq 配对 + 发现被顶就重试 + 读 `names` 认外来口味**。
- **GDI 类格式不是 HGLOBAL**（详情见 §0 第 7 条）：`CF_BITMAP`(2) / `CF_METAFILEPICT`(3) / `CF_ENHMETAFILE`(14) 调 `GlobalSize`/`GlobalLock` 会 **`0xC0000374` 崩掉枚举进程、零输出**。修后 `clipdump.ps1` 记 `$GDI = @(2, 3, 14)` 并只标 `kind='GDI-handle'`、**不读载荷**。证据：`.mp-verify\cu\evidence\clip-bs7.json` 里 `CF_BITMAP` 条目为 `{bytes:0, kind:"GDI-handle"}`。
- **无头 Chromium 的剪贴板到不了 Win32**：`copyRich()` 在渲染进程里成功（`navigator.clipboard.write` 被调用、载荷已在 `clipboardData`），但 `clipdump` 侧读到 `formats = 0` —— 文本口味能提交、**位图口味在无头环境不提交**。⇒ **剪贴板"字节类"判据必须在真宿主（EXE / 真实桌面）做**；无头里只能验到"渲染进程内部拿到了载荷"这一层。
  （本次成文时**未在盘上定位到**一条带来源标记的 `formatCount:0` 记录文件；机制与读数由本轮真宿主对照实验得出，**列为本节唯一未落盘留证的条目**。）

### B4 探针与判据要自我怀疑

- **`grep` 返回 0 时，先核对自己的查询范围**再改方案。现场形态：只 `grep` 了 `main.js`，结论却写成"两个文件都没有" ⇒ 差一点另起一套实现。⇒ **查询为 0 时第一步是"扩大范围重查"，不是"下结论"。**
- **判据包必须自证身份**（哨兵 + 换包日志 + 换前/换后哈希）："绿侧跑成红侧"与"红侧跑成绿侧"**都会静默发生**。现场形态：探针没有 `--engine` 支持 ⇒ 以为在跑红侧，实际跑的仍是绿侧包。
- **放夹具后先验证夹具真的到位**（口味清单 / 字节 / 尺寸）再拿读数下结论。现场形态：`pwsh 7` 没有 `Set-Clipboard -Path` ⇒ 那次"放了个 Files 夹具"其实仍是 `CF_DIB`，后续读数全建立在错误的夹具上。
- **"某臂 0 红"必须先用已知会红的臂做阳性对照**；阳性对照**不红 ⇒ 尺子坏了**，不是代码好了。现场形态（盘上可核）：`.mp-verify\beta-keys\probes\p0.cjs` **只 `console.log` 原始读数**（`' ①a 尾空白行 Tab：' + JSON.stringify(...)`），**全文 0 个 `✅` / `❌` / `PASS` / `FAIL`** ⇒ 任何"数 `✅`/`❌`"的统计器对它都恒为 **0 红**（六个臂全 0 红）。
- **用 `src` 首尾字符当去重键在 data URI 上必然失效**：产品里 `ImageWidget` 的 `srcKey = src.length + "|" + src.slice(0,32) + "|" + src.slice(-32)` 是**为性能做的近似**（widget 想避免逐字比较 90 万字符）；**探针侧拿它当"图身份"会错** —— data URI 首尾高度相似且极长 ⇒ **不同图被合并、同图重复计数**。

### B5 工程纪律

- **不许用 shell 文本工具改含模板字符串的源码**：`Get-Content | -replace | Set-Content` 这类管道**两次**弄坏过占位（一次弄坏 `${R.FRAME_SEL}`、一次弄坏探针模板）⇒ **改代码一律走编辑工具或整份写文件**；shell 只用于"跑"和"读"。
  **配套三条**：① **模板字符串内部的注释不许出现反引号**（会让模板提前结束，见 §0 第 8 条同族现象）；② **命令拼接类读数必须打印实际入参**（否则"拼错了"与"执行失败"分不开）；③ **突变包必须自证标记**（证明跑的是突变包而不是原包）。
- **独占资源必须串行**：**剪贴板 / app-slot 锁 / 打包窗口 / 引擎产物替换窗口**。实测:"换包取改前读数"与"正在打包"会**互相污染** —— 一方在读、另一方在换文件。⇒ 这四类操作要么取锁，要么明确排队；换包前后**必须记哈希**，并让读数带上"基于哪个哈希"。
- **红侧也要有期望值**：红侧**不是"看起来变红了"**，而是**复现已知旧读数**。本轮实例：红侧要复现报告里 **15,646.65 px²** 那个量级（实测 **15,646.31**，差 0.34 为聚合口径）⇒ 只有落在同一量级才算"红对了"；只看到"有红字"可能是**另一个**原因造成的红。
- **读数的取值链与前置条件都要自证**（同族四实例，每个都能让整列读数失真）：
  ① **字段名写错**（`island.left` vs `island.x` ⇒ `undefined >= 0` 恒假 ⇒ **整列判反**）；
  ② **同一量在两字段用不同口径**（把**滚动条左缘**当右缘 ⇒ 假交集 `87.5px²`）；
  ③ **`page.evaluate` 收到"返回模板串的函数"** ⇒ 四行读数**全是 `undefined`**（传进去的是函数而不是值）；
  ④ **悬停测试的起点态没断言** ⇒ 全程跑在**错误状态**上（后面每个读数都无意义）。
  ⇒ 通则：**任何一列读数，先自证"它取到了值、且取的是我以为的那个量、且起点态成立"**。
- **`resizeTo` 无法精确命中内宽**（6 次迭代仍停在 **1159**，1px 台阶）⇒ **必须精确同宽的几何对比不能靠它**：改用**同构判据**（比 `w/h` 与 `(W−w)/2`），并**禁用"逐像素相同"字样**（在那个前提下逐像素相同是不可达的承诺）。
- **提示类断言要看"最终留下的那一条"**：toast 是**单例**、后写覆盖 ⇒ **中间态正确 ≠ 最终态正确**。要断言"用户最后看到什么"，而不是"某一刻出现过什么"。
- **记录文件里的"显示位数"不是原始精度** —— 看到的 `19.2` 可能是 `19.19834…` 舍入后的显示。**验证是否自洽用反推**：`面积 ÷ 宽 = 高`（本轮实例：`15,646.65 ÷ 815 = 19.19834`，回代 `815 × 19.19834 = 15,646.65` **逐位吻合** ⇒ 自洽）。
  **两个方向都要防**：① **别把显示舍入当成数据矛盾**（拿 `19.2` 反推得 15,648.00、差 1.35 ⇒ 会误判"记录自相矛盾"）；② **也别用显示值去重算并宣称精确**（那等于把舍入误差当结论）。⇒ **要么用反推核自洽、要么标"显示值/精度未知"。**
- **输出（报告 / 文档 / 回报）里的每个数字都必须能指到来源** —— 记录文件、算式或读数；**写不出来源的数，宁可不写**。与上一条**同族但不同病**：上一条是"**精度错**"（把舍入值当精确），这一条是"**来源缺**"（数字没有出处）。
  ⇒ 落笔前对每个数问一句：**"它出自哪个文件 / 哪步算式 / 哪次读数？"** 答不上来就删掉它，或明确标成"估计"。**凭空写出的数字比写错数字更难被发现** —— 错数还有可能被反推查出来，无出处的数字连查的入口都没有。
- **判据涉及一个连续区间时，样本必须打"两端 ＋ 内部点"**（本轮最值钱的一条）。现场：task-10 的公式与判据**不同构**，缺陷**只在 `gap ∈ [14.8, 40)` 出现**；而四支夹具的 `gap` **恰好 = 0** ⇒ 两种写法**数值相同** ⇒ **8/8 全绿却是假绿**。独立复核用一个 **`gap = 25.84` 的内部点**一次打出交集（详录见 §18 / §19.2）。
  ⇒ 通则：**只打两端（尤其只打 0 与"足够大"）会漏掉整段区间**；区间型判据必须证明"内部也被采过"。
- **夹具文件也要"绑身份"**：报告头写清夹具的 `sha256` ⇒ "夹具被改过"**永远公开可查**，读数也必须与**具体修订**绑定。配套两条：**旁挂记录不写进夹具正文**（写进去会动条目数 ＝ 改变被测对象）；**交付前核身份**（现场：写者靠核 `shellApp` 认出"陈旧 json 被当成新结果"，文档侧靠核盘上三行认出"**授权 ≠ 已落地**" —— 同一族）。
- **引用读数必须写清"哪个文件 + 哪个快照"** —— **复核侧同样适用**，不只是产品读数。现场（亲历）：`task10-main.json` 被下一轮复核**覆盖**（3.2 万→7.7 万字节级改写、sha16 变为 `e1579b24884d`），**原先在其中出现的 `11537` / `14937` 随之消失**，同一批数字改由 `task10-mutants2.json` 承载。
  ⇒ 正确姿势：**一个文件名不足以定位一份读数**；要写 **文件 + sha16 + 快照时刻（＋字段名）**。后续的正解是**汇总件**（如 `t10adv-summary-*.json`：自带 `snapshot.sourceFile / sourceSha16 / sourceAt`，并声明"本汇总全部读数来自那一次运行"）—— **让证据自己说明它出自哪一次运行**。
- **夹具 / 清单的生成与修补一律"原子写"（临时文件 + rename）** —— 且**禁止对内联命令**（`node -e`、pwsh 单行）**做 `-replace` / `Set-Content` / `WriteAllText` 落盘**。这与"别用 shell 文本工具改含模板串的源码"**同族**，但代价更高：**原子写下即使两个写者重叠，也只会"一个赢"，不会写出交错文本**（本轮的清单事故正是**保长度区域覆盖写**产生的错位切片）。
  **旁证（说明为什么这条要写成制度而不是"注意点"）**：清单事故的**写者始终未定位** —— 四条腿自查全"无"，唯一强线索是两个只读核对脚本的 mtime 紧贴二次损坏时刻，**但脚本本身只读** ⇒ 最可能是**内联命令**，而**脚本与会话扫描都看不见内联命令**。⇒ **看不见的写者，只能用"写不坏"的写法规避，不能靠"找到它"**。
- **★ "因果"必须有对照臂** —— 凡判据形如"**动作 A 导致状态 B**"，必须**配一条对照臂"不做 A 时 B 不变"**；**缺对照臂时，结论只能写"相关"，不能写"由 A 导致"**。
  **现场（task-3 / C1 端到端，证据 `.mp-verify\bar-overlap\t3-reload.json`）**：① 文档 = 原始内容 → ② **改了盘上文件、还没点「重新加载」** ⇒ `midDoc` **与 `before` 逐字节相同**（**这就是对照臂**）→ ③ 真 CDP 点「重新加载」→ ④ `after` ＝ 盘上新内容且含新增标记（`gotMarker: true`）。
  **为什么必须有②**：没有它只能说"**点了它、内容变了**"（**相关**）；有它才能说"**不做该动作时状态不变、做它才变**"（**因果**）—— 否则"**应用某处自动读回了盘上内容**"这类替代解释**无法排除**。
  **与既有条目同族但不同病**："**前置条件要当门用**"管的是"**采样时状态对不对**"；**这一条**管的是"**因果能不能归给被改的那处**"。
- **红/绿读数不许同址**：红侧实验**覆盖过**绿侧的 json ⇒ **必须文件名区分**（本轮现场：`task10-verify.json` 被红侧实验覆盖，回头已读不到绿侧读数）。
- **产品口径两条纠正**：
  ① **起实例不占 app-slot 锁**（`AGENTS.md` 子代理铁律 4）—— 改用**全新 profile ＋ 起前数残留 ＋ 跑完杀自己那棵树**；
  ② **焦点断言的范围分两类**：**键类读数**前要 `hasFocus` **且** `activeElement ∈ .cm-editor`；**鼠标类**只要求 `hasFocus` —— 点工具栏按钮会让焦点**离开编辑面**，那是**预期行为**，不是失败。

## 6 E · 代码块行号（已落地）

**规格来源**：Typora 本机实测（左独立栏、右对齐、灰色低对比、1px 细竖分隔线、每块从 1 重数、空行占号、行内代码无号）。

**实现（纯渲染层，三条硬约束同时满足）**
- `lineStylesField` 新增 `codeLines: [{line, n}]` —— 只记"第几行"，**不写进源码文本**；
- `codeLineNoPlugin`（`ViewPlugin`）把行号写进**行 DOM 属性** `data-mp-n`；
- CSS 用 `counter-increment` + `::before { content: counter(mp-code-line) }` 画数字，`counter-reset` 由块容器界定 ⇒ **每块从 1 重数**。

**为什么这样写**：① **不进内容** ⇒ 复制 / `copyRich` / 导出 HTML / PDF / `mdBodyChunks` 都拿不到行号（这是硬判据）；② **性能** ⇒ 只在文档变或视口变时写一轮属性，不在每键路径新增扫描；③ **长行折行只算一个号** ⇒ 号挂在行元素上，与视觉行数无关。

**过程中修掉的两个真缺陷**
1. 插件原来只在 `docChanged | viewportChanged` 跑 ⇒ **长行把后面的行推出视口时漏号**（视口外的行没有 DOM，属性挂不上）。改为每次 `update` 跑（只遍历代码行，不扫全文）。
2. `.mp-code > code` 这条选择器**从不命中** —— CM6 的围栏行渲染成 `SPAN.ͼx`，**没有 `code` 元素** ⇒ 1px 竖线改画在**行盒左缘**（那 1px 落在 24px 留白内，正文列不动）。

**判据**：10/10（5 行块含空行＝`1..5`、两块各自从 1 起、引用区围栏块有号、行内代码无号、导出/复制/源码三处无行号、长行折行 4 视觉行只 1 个号、右对齐+低对比灰+绝对定位+字号小于正文、1px 竖线）。暗/亮两主题 2 倍放大截图已人工核对。

## 13 图片不渲染的根因与失败可见层（task-12，已落地）

### 13.1 根因：JS 赋值绕过 HTML 解析器，实体原样上线

Typora 写出的 HTML 属性里 `&` 被写成实体 `&amp;`（HTML 正常写法）。产品路径是：

```
img.src = mpImgSrc(<属性原文>)          // 属性原文里带 &amp;
```

**JS 赋值走的是 URL 解析，不是 HTML 解析** ⇒ `&amp;` **原样**进入 URL ⇒ 图床收到**被污染的 query**（实测收到 `…&state=SIG&amp;ty=p`，**参数名成了 `amp;ty`**）⇒ 签名校验失败 ⇒ **403** ⇒ 图不显示。

### 13.2 因果 A/B（本地签名图床，只差一个变量）

| 变量 | HTTP | naturalWidth | 渲染盒 | 屏幕 |
|---|---|---|---|---|
| 全 `&amp;` | **403** | 0 | 0 × 18 | 空白 |
| 只换裸 `&` | **200** | 真图 | **815 × 509.4** | 正常 |

⇒ 单变量对照，根因锁定在**实体未被解码**这一处。

### 13.3 为什么 v2 能显示、v3 不能（机制）

v2 是 **Vditor**（`renderer\index.html` 加载 `cdn/vditor/dist/index.min.js`、挂 `#vditor`）。它**走 HTML 解析器建 DOM** ⇒ 属性里的实体会在解析阶段**被解码**。v3 是 CM6 + 自己 `img.src = …` 赋值 ⇒ 没有解码这一步。**同一份文档、同一个 URL，差别只在"谁来做 URL 解析"。**

### 13.4 修法（函数名口径）

- **只改 `imgAttrs`**（裸 `<img>` 分支）：把属性值过一遍新 helper **`mpHtmlUnescape`**。
- `mpHtmlUnescape` 的口径：**只解一层**；仅白名单命名实体（`amp`/`lt`/`gt`/`quot`/`apos`/`nbsp`）与数字引用（`&#38;`、`&#x26;`）；非法码点（含代理区 U+D800–U+DFFF、> U+10FFFF）产出 **U+FFFD**；**不抛异常**；命名实体不在白名单时**原样返回整段**（`&notanentity;` 不动）。
- **`scanImageMarks` 的 `![]()` 分支与 `mpImgSrc` 一行未动。**

### 13.5 判据实例（5 解 + 3 原样 = 8/8）

**必须解开**：`?file_id=X&amp;state=S&amp;ty=p` → `?file_id=X&state=S&ty=p`；`x&amp;y.png` → `x&y.png`；`&amp;amp;` → `&amp;`（**只解一层**）；`&#38;state=` → `&state=`；`&#x26;state=` → `&state=`。
**必须原样**：`a&b.png`（裸 `&` 不是实体，不动）；`a&notanentity;b`（非白名单，整段不动）；`%26amp%3B`（百分号编码，不动）。
**另**：markdown `![](…&amp;…)` 分支**不经过**该 helper ⇒ 保持原状（改前改后一致）。

### 13.6 失败可见层（不变量：只要 mark 是图片，屏幕上必须有可见物）

- 源里：**`mpImgFailGuard`** + `.mp-img.is-failed` / `.mp-img-fallback` —— 破损标记 + **完整 URL** + 原因。
- **修前**：失败态是一个 **0 × 18 的空盒**（`min-height:18px` + `--mp-capsule` 底色，**暗色下与背景同色**）⇒ 屏幕上"什么都没有"。这正是"看着像空内容"的来源。
- **修后**：渲染高 **26.2 → 104**，`is-failed` 占位可见（占位带完整 URL 与原因）。
- **不变量（写进实现纪律）**：**只要 mark 是图片，屏幕上就必须有可见物** —— 不允许出现"源码被遮住 + 图没出来"的空白态。

### 13.7 F7 规则在图片上的既有行为（保留，但失败态例外）

`inlineMarkDecorations` 里有一条：**光标落在 image mark 内且 `src.length ≤ 512` ⇒ 不挂 widget、故意露源码**（便于直接改地址）。三个触发路径：① 点那一行；② 图是文档第一行；③ 点图本身。
**该能力保留**，但**加载失败时一律显示占位、不许露源码**（否则又回到"看不出这里有图"）。

唯一的早退是 `t.length > 20000`（`huge`），它**只管**转义隐藏与行内标记 `scan()`，**不影响图片扫描**。

   上溯途中**根本遇不到 `.cm-line`** ⇒ 属性静默挂不上（那句 `catch` 把它吞了）。
2. **写入挂点错**：属性只在 `update()`（事务）里写 ⇒ CM6 在没有事务时自己重建/补渲染行 DOM 的
   那些时刻（视口渲染、行高重排）**没有任何 update 可挂** ⇒ 该挂的属性整批漏掉。

**修法**：定位改**结构对位**（`.cm-line` 是 `contentDOM` 直接子元素且按文档顺序 ⇒ 行号可推：
普通行 = 计数 +1；代码行 = 围栏序号 + `data-mp-n`）；写入挂到 `ViewPlugin.measure()`（每轮布局后跑），
并加**三输入门控**（文档变 / 视口变 / 已渲染行数变，三者都没变就直接返回）保证零重扫。

**性能纪律（本轮实测换来的硬口径）**：`update()` 里**不许无条件 `requestMeasure()`** ——
那会让每键多跑两轮完整布局，8.5MB 文档上把每键 p50 从个位数抬到 **93.4ms**；
只有"视口真的换了"才请求一次测量。同夹具同尺子的对照臂：现行包 87.5 / 上一版包 87.1–87.4（无回退）。

### 20.1 C1「重新加载」：**两方独立推理被代码注释推翻，落码动作＝不加任何代码**

**需求**：给「重新加载」接上行。**两次独立推理**（先后由不同角色给出）都得出同一结论：重载后应 **①清空撤销栈**（否则 `Ctrl+Z` 会回到**已被磁盘覆盖的旧内容**，随后一保存就**把外部改动冲掉** ⇒ 判为数据丢失路径）、**②把光标钳到合法位置**（"保住原位置"被当作虚假承诺）。

**推翻它的是实现注释** —— 落码前先读了实现（壳侧 `applyDoc` → 引擎 `main.js` 的 `setValue`），读到逐字三条：
```
① 旧撤销分支经最小 ChangeSet 映射存活（全量替换会塌缩成零长 no-op——
   addToHistory:false 只挡新增历史项，挡不住旧分支被冲，复核 B 臂实锤）；
② 外改非历史项＝Ctrl+Z 永远动不了外部改动（盘上外改守恒）；
③ 光标交给 CM6 原生位置映射（上方插 9 字 → col 精确保持，优于手动钳位）。
```
（**以上三条已在盘上逐字核到**，位于 `main.js` 的 `setValue`；该函数确为"最小 diff 形态"：求公共前/后缀、只替换中段，并以 `Transaction.addToHistory.of(false)` 派发。）

⇒ **两条建议同时撤回**：清空撤销栈会**毁掉用户自己的撤销分支**；手动钳位会**把好行为换成差行为**（原生位置映射已精确保持列）—— **两条都是回归**。于是落码动作变成"**不加任何代码**"。

**纪律**：
> **在动一个既有机制之前，先读它的实现与注释里的"为什么"。** 若实现**刻意**做了某事并写了理由，先假定它是**经过验证的选择**（此处注释还标了"复核 B 臂实锤"）。
> **"从第一性原理推出一个合理结论"不等于"现有实现没解决它"** —— **两条独立推理同时指向同一结论，也可能一起错。**
> 配套：**注释的价值在于"救下未来的一次改动"** —— 本轮就是它救的。**同一族的反面案例已记过**：注释**描述了从未落地的机制**（§16 那条"每块从 1 重数"）—— 两者说明同一件事：**注释要么必须真、要么就是陷阱**。

找 `<img>` 的 `>`、找 `![]()` 的配平 `)`、实体替换正则。改法：引号内/URL 内**原生跳读** + 无 `&` 早退。

### 22.3 ★ 流程教训：**跳步型改写的等价性必须用"定向枚举"，随机 fuzz 挡不住**

Lead 的第一版"引号内 `indexOf` 跳步"**不等价**：值是空串（`<img src="a.png" alt="">`）或闭引号
紧邻另一个引号时，闭引号**就在当前位**，`indexOf(quote, j + 1)` 会跳过它 ⇒ 引号态错位 ⇒
图片整张不渲染、同行后续 `<img>` 一起丢。
- 20 万条**随机** fuzz：**0 命中**；而**结构枚举**（属性三元组形态）：**70.4% 分歧**。
- ⇒ 纪律：凡"`indexOf`/跳步/状态位翻转"型改写，**必须**配"**空值 · 空字段 · 连续分隔符**"的
  定向枚举；随机 fuzz 对相邻分隔符**系统性欠采样**，不能作为等价性主证据。

### 22.4 ★ 已落地的 `a1ScanMath` 此前**就是错的**（对抗复核查出，已修）

- **现象**：单步编辑穷举 1539 例中 5 例与全量扫描不一致；最小复现 `$$\na\n$$\n$$\nb\n$$`，
  症状是**公式块整条消失**（静默）。
- **根因**：窗口（`dirty ± 1`）两端可能切在多行结构中间，而 `a1LineStates`（"看行首"的粗状态机）
  与 `scanMathSpans` 真实开合口径**不等价**；`scanMathSpans` 对**未闭合** `$$` 整块不认 ⇒
  "窗口产出为空"被误判成"没切断"。设计里承诺的"行数变化兜底"在代码里**不存在**。
- **修法**：① 窗口自洽扩张（用**扫描器自己的产出**判是否切在半截：span 触窗口末尾就往后扩、
  从窗口首字符起就往前扩，扩不动⇒全文重扫）；② 脏区邻域（±2 行）出现 `$`/反引号/`~`/`<!--`
  ⇒ 全文重扫（`math-chars-nearby`）。
- **复验**：1539 例单步穷举 0 不一致；6 条最小复现全过；2000 步随机多步 fuzz 0 不一致。

### 22.5 A1"按行缓存"路线的判定：**不按原设计推进**

对抗复核用**真实 `ChangeSet`** 把方案按字面实现后跑 46 份带编辑序列的夹具，得到：
多行件端点（跨行 `$$`、跨行注释）**不是行局部量**（复用旧端点 ⇒ 注释尾部露出 / 公式块消失）；
`scanTables` 的整表 `widths`/`cells` 同理（复用 ⇒ 列宽不跟随、覆盖层按旧格写回 ⇒ **可能写错格**）。
⇒ 结论：**行级复用的前提不成立**，除非先把"跨行件端点"与"整表量"从行产出里拆出去。
现行落地方案＝**只修热点 + 保守门**（见 §22.2 / §22.4），并把"行内分片"列为 OPEN-1 的剩余面。

### 22.6 零宽空格（U+200B）曾经"看得见"：真因与修法（2026-10-09）

- **现象**：编辑面上 `零·宽·字符` 之间各冒出一个**红色圆点**，占宽 5.5px（清单 §5.12 期望 ≤2px）。
- **当时（错误）的结论**："两条量法同值 ⇒ 字体度量 ⇒ 非缺陷"。**错在推理**：
  `coordsAtPos` 与 DOM `Range` 量的是**同一个渲染结果**，同值只说明测量一致。
- **真因（两步就能查出来，值得固化成流程）**：
  1. **把同一个字符放到编辑器外、用同一个字体栈量**：宽 **0.01px**（CJK 上下文 0；
     `Arial / SimSun / Consolas / monospace / Noto Sans SC …` 十一种字体全是 0 或 0.01）⇒ 与字体无关。
  2. **把那一行的 DOM 节点逐个打出来**：字符位置上不是文本节点，而是
     `<span class="cm-specialChar" title="Control character zero width space">•</span>`
     ⇒ CM6 `highlightSpecialChars`（随 `basicSetup`）的**可见占位字形**，是产品行为。
- **修法**：引擎 CSS 一条规则，只针对这一个控制字符——
  `.cm-content .cm-specialChar[title="Control character zero width space"] { font-size: 0; }`
  - 候选实测：`font-size:0` ⇒ 5.5 → **0**、行高 25.2 **不变**、光标两侧差 0（采用）；
    `inline-block;width:0` ⇒ 行高被顶到 **33.73px**（否）；`display:none` ⇒ 也可但改动面更大（否）。
  - **其它控制字符保留默认红点**：软连字符、双向控制符出现在正文里通常是事故，看得见比看不见好。
  - **脆弱点**：选择器靠 CM6 写的 `title` 文案精确匹配；文案一变规则失效、红点回来。
    **守卫者就是 §5.12 判据本身**（它直接量那个 span 的实占宽）——它是可失败的，不是装饰。
- **复核**：视觉（修复前后各一张 2 倍放大图，`shots/zwsp-before.png` / `zwsp-after.png`，
  红点消失且行高不变）+ 全量验收 **80/80**。

### 22.7 按键代价的分层：数据层只占 0–2%（消融实验，2026-10-09）

**做法**：一份**可切换**的引擎（五个产出函数开头插 `if (globalThis.__MP_ABL) return <空>`），
同一产物跑两遍（置位 / 不置位），逐枪比 dispatch。**两臂同尺子、同顺序**。

| 位置 | 引擎全量 | 扫描器停摆 | 数据层占比 |
|---|---|---|---|
| 文档末尾 | 16.3 ms | 15.9 ms | **0.4 ms（2%）** |
| 巨行中部（91.6 万字符的行） | 40.8 ms | 46.5 ms | ≈ 0（落在噪声里） |

⇒ **按键代价不按"文档多大"算，按"改动的那一行有多宽"算**，且这笔钱不在我们的数据层：
① 改动行的 DOM 文本重写（一行 = 一个文本节点）；② Lezer 重解析该行；③ 高度图/视口/测量。

**三条方法学教训（都踩过）**：
1. **`state.update()` 量到 0ms**：CM6 的 `StateField` 是**惰性**的——字段值在第一次被**读**时才算，
   而读它的是视图更新。⇒ 真实开销全在 `view.dispatch()` 里；想逐字段计时必须在"视图读它"的时刻量，
   在外面包 `field.update` 是量不到的（这也解释了早先"字段暴露"那条路为何拿不到读数）。
2. **`ChangeSet` 构造 + 应用到 Text 树 = 0ms**：绳层不是瓶颈，别在这上面做优化。
3. **测量顺序会污染读数**：先量巨行、再量文档末尾 ⇒ 末尾读到 46.1ms；倒过来 ⇒ 16.3ms
   （与独立探针 13ms 对上）。因为每次在巨行里插入都要重写 91.6 万字符的行，
   留下的延迟测量/重排落进下一次计时。⇒ **"同一把尺子"包含"同一测量顺序"。**

### 22.8 ★ CM6 会抹掉"它没管的行属性"——代码块行号那一课的通用结论（2026-10-09）

**病象**：光标停在**开围栏行**时，代码块行号整块错位（5 行里只有空行有号）；同一份文档光标在别处时是好的
⇒ 只在特定光标位置复现。

**三层根因**（查了三轮才定到，都记在案）：
1. **对位靠 `.mp-fence` 计数**：`.mp-fence` 这个类**在光标落到该行时会消失**（该行切源码态）⇒ `fenceNo` 少算 ⇒ 号错位；
2. **三输入门早退**：门是"字段对象 / 视口键 / 已渲染行数"，而"光标移动导致行 DOM 重建"时**三个都没变** ⇒ 早退 ⇒
   新元素上的号永远补不回来；
3. **★CM6 会就地抹掉外部属性**：某一行的装饰集变化时，CM6 会**按它自己的模型重新应用该行属性**，
   于是我们自己挂的 `data-mp-n` **被抹掉，而元素对象没换**（WeakMap 命中 ⇒ "处理过就跳过" ⇒ 永不补写）。
   现场证据：同一次滚动里**刚滚过去读到 `[1,2,3]`，1.2 秒后变成 `[null,2,null]`**；
   而这段时间里 `apply()` 一次都没跑（埋点现场记录为空）⇒ 坐实"就地抹掉"。

**落地的口径（可复用）**：
- **不猜结构**：已渲染行用**它自己的位置**换文档行号（`view.posAtDOM(el, 0)`）再查表——
  不要用"类名/计数"推（类名会随光标态变）。
- **缓存要带校验**：WeakMap 记的是"这个元素该显示什么号"，跳过前**再读一次属性**——
  **属性仍在才算跳过**；被抹掉就按缓存补写（纯属性读取，不触发布局）。
- **失败什么都不做**：解析不出来就不写、不摘、不缓存（下一轮再试）；**摘号**另加"DOM 文本与源码一致"的确认，
  免得把引用区那种"源码带 `> ` 前缀、DOM 里被隐藏"的行误摘。

**通用结论**：**行级 DOM 属性不是稳定存储**——只要它不由 CM6 的装饰模型托管，就可能在任何一次
装饰集变化时被重置。凡"往行元素上挂自定义属性"的实现，都必须假设"它随时会没"，并准备一次廉价的重写。

### 22.9 ★ 程序化"整篇替换"必须显式给 selection；自动保存必须有体积骤降守卫（2026-10-09）

**病象**（磁盘级数据丢失）：用户在 A 文档里选了一段文字 → 打开 B 文档（最近菜单/拖入）→
在 B 里敲第一个字 ⇒ **整篇 B 被那一个字替换**；500ms 去抖的自动保存**如实**把结果写回 B 的路径
（实测 8.13MB → **9 B**）。

**链条**（每一环都有实测读数）：
1. `window.mpEngine.setValue` 走的是**最小 diff 中段替换**（算公共前/后缀），那笔 `dispatch` **不带 `selection`**；
2. CM6 把旧文档里既有的**非空选区**经位置映射带过去：两端都落在被替换区间内、association 相反
   ⇒ 选区被拉成 `[start, start + insert.length]` ≈ **整篇**（定点实测 `[9,13]` → `[8523372,1]`）；
3. 第一个按键把整篇替换掉；自动保存落盘。
- **为什么平时测不出来**：**光标不拉伸**（空选区映射正常）⇒ "单跑 §7.8 的新实例"与"同文档外改"两类实验必然阴性；
  只有"先留下非空选区、再换文档"才触发。

**两条通用纪律（本项目适用）**：
1. **凡是程序化替换（尤其是可能整篇替换的路径），必须显式给出替换后的选区**，不能默认交给位置映射——
   映射规则是"把旧位置搬到新文档"，而"旧选区"在这种场景下没有语义。判据用一条：**端点落在被替换区间内 ⇒ 塌缩到替换起点**。
2. **自动保存要有"体积骤降"守卫**：待写长度相对已知体积骤降（如 <20% 且绝对值 >2 万字符）时
   **不静默写盘**，弹确认并留痕（`doSave:drastic-shrink`）。`Ctrl+S` 是明确意图，不拦。
   —— 根因修好了，这类守卫仍然值得留：**它把"某类 bug 的后果"从"数据丢失"降级为"一次确认"**。

**验证方式（值得照抄）**：根修 + **突变验证**（把修复那一行注掉 ⇒ 同一支复现脚本必须重新变红）；
守卫 + **复现态验证**（根修注掉、守卫在岗 ⇒ 内存里文档仍被清空，但磁盘写入被拦、夹具完好）。


### 22.10 管道里的字段会被静默截断

**病象**（本轮实测两例，同一根因）：
1. **PDF 里的公式只有结构没有排版**：渲染侧把 KaTeX 类样式（`mathCss`）随 `export:htmlDone` 一起送来，
   但主进程的处理器只透传了 `{ok, file, error, mode}` 四个字段 ⇒ 打印层读 `html.mathCss` 永远读到 `undefined`
   ⇒ 那段"公式 CSS 只在打印窗口里注入"的代码从未生效。用户看到的是公式印成 `dPdQ` 那种形态。
2. **排版预算闸门形同虚设**：新加的 `sourceBytes` 撞进同一个处理器，同样被丢 ⇒ "源 ≥300KB 跳过精细断行"
   这条闸门只剩"可排块 ≥1800"一条腿。

**为什么难发现**：两处都**不报错**——字段少一个，下游读 `undefined`，有默认值就静默走默认分支；
日志里也只记"用了什么"，不记"收到了什么"。

**通用规则（本项目适用）**：
1. **跨进程/跨模块传参时，接收侧要显式列出需要的字段**（同意图字段集中在一处），不要"整体透传"也不要"只挑一部分"——
   前者让无关字段无声进入下游，后者就是本轮的病。
2. **凡是"参数从别处来"的分支，必须在日志/结果里记下"收到的值"**（本轮把 `mathCss.source/bytes` 放进导出结果，
   探针因此能直接断言；在此之前它恒为空却无人察觉）。
3. **单位要写进字段名**：同一个闸门，渲染侧送的是**字符数**、阈值是**字节**（2.x 口径），
   中文文档会宽松约 3 倍（首次取证读数：`1029` 字符其实对应 `2901` 字节）。
   现在字段名写成 `sourceChars` / `sourceBytes`（折算上界），并在代码里写明折算方式。

**打印期排版的两条硬约束（导出链 KP 落地时确立）**：
1. **磁盘产物不许被排版改写**：精细断行只作用于"这一趟打印的内存 DOM"，
   「导出为文件夹」的 HTML 与 PDF 用的那份必须**逐字节相同**（这条可核对，也被写进了 `export-pdf.js` 文件头）。
2. **必须在与纸面同宽的布局里测量**：打印窗口是屏幕布局，而 `printToPDF` 是打印布局
   （A4 − 边距 ⇒ 正文宽 680.64px）。排版前若不把屏幕布局压到纸面宽度，算出来的断行贴到纸上就是错版
   （2.x 线在正文层显式设 672px，同一个原因）。
