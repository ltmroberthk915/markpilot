## 一、取证（先看清 DOM 真相，再动代码）

四轮探针（`scripts/math-caret-probe.cjs`、`math-matrix-probe.cjs`、`math-geometry-probe.cjs`、
`math-debug-probe.cjs`，都只观测不改产品代码）：

### 1.1 节点形状（IR）

- 行内公式：`<span data-type="inline-node" class="vditor-ir__node"><span class="vditor-ir__marker">$</span>
  <code data-type="math-inline" class="vditor-ir__marker vditor-ir__marker--pre">a+1</code>
  <span class="vditor-ir__preview" contenteditable="false">…KaTeX…</span>
  <span class="vditor-ir__marker">$</span></span>`——折叠态三个 marker 全是 `display:none`（0×0），
  只有 preview 是可点的那 22×16 一块。
- 块公式：`<div data-block="0" data-type="math-block" class="vditor-ir__node"><span data-type="math-block-open-marker">$$</span>
  <pre class="vditor-ir__marker--pre vditor-ir__marker">…</pre><pre class="vditor-ir__preview">…</pre>
  <span data-type="math-block-close-marker">$$</span></div>`——两个 `$$` 标记 span 由 Vditor 的 CSS
  永久 `display:none`，展开态画出来的 `$$` 是 `.vditor-ir__node--expand[data-type="math-block"]::before/::after`
  的**伪元素内容**。

### 1.2 用户报告 1（行尾弹预渲染框）复现

- 点「以公式结尾」那一行的最右端 → `expanded:["inline-node"]`，光标落在 `span[inline-node]@4`；
- 光标先落在正文再按 `End` → 同样 `expanded:["inline-node"]`；
- 截图（`.perf/math-geometry/inline-right-end.png`）显示的就是那个带边框阴影的浮层——即用户说的「预渲染框」。

机制：Chromium 把行尾的光标落在 owner 的**直接子位置**（offset=childNodes.length）或零宽 `$` 标记里，
Vditor 每次选区变化都会「给光标所在的 `vditor-ir__node` 挂 `--expand`」，于是公式被展开、浮层出现。

### 1.3 用户报告 2（`$$` 落不了光标）复现

展开块公式后，从 owner 左边缘 0/3/6/9/12/16/22px 逐点点击，**7 个落点全是 `code[math-block]@0`**；
几何探针显示两个 `$$` 标记 span 的盒子恒为 `0,0,0`（`display:none`）。伪元素不参与命中测试，
所以「两个 `$` 之间」这个位置在文档里根本不存在。

### 1.4 用户报告 3（贴边退格毁公式）复现

行为矩阵（`math-matrix-probe`，每例前用 `setValue` 复位到同一份 fixture）实测到的破坏：

| 光标位置 | 修复前按一次退格的结果 |
| --- | --- |
| 块公式源码开头 (`code@0`) | `$$\nx+y=1\n$$` → 变成一行纯文本 `x+y=1`（**围栏整块消失**） |
| 块公式块起点 (`owner@start`) | `公式前的段落。` + 公式 → `公式前的段落。x+y=1`（**并进上一段**） |
| 块公式块终点 (`owner@end`) | 吃掉源码最后一个字符并留下 `$$` 残骸 |
| 块公式后一段的段首 | 第一次不改文档、光标跳进源码；**第二次吃掉源码字符** |
| 块公式前一段的段尾 + Delete | `公式前的段落。` + 公式 → `公式前的段落。x+y=1`（**并进上一段**） |
| 行内公式贴尾 (`owner@end` / 尾标记) | 吃掉收尾的 `$` → 公式变成一行字面文本 `$a+1` |
| 行内公式源码末尾 + Delete | **整条公式消失**（`行内公式在这  后面还有字。`） |
| 整条公式选中后删除（块） | markdown 里出现一行字面 `span`，**后面的段落被一起吃掉** |

素材（`排版测试-数理逻辑1(1).md`）里用鼠标点在「`(1)` 公式与 `(2)` 之间」再退格，
复现出用户报的那一条：块公式数量从 4 掉到 3（**整条 `$$…$$` 被销毁**）。

## 二、修复（渲染层单一真源 `Typora-Editor/extension-src/render`，`npm run sync` 进 app/renderer）

### 2.1 `js/math-edit.js`：把「贴边」定义清楚

- `formulaEdge(owner, range)` → `{where:'start'|'end', layer:'outer'|'code'}`：
  - `layer:'outer'` = owner 的首/尾**子位置**、或首/尾 `$` 标记的外侧（Chromium 在行首行尾的常用落点）；
  - `layer:'code'` = 源码的第 0 个 / 最后一个位置（块公式的围栏在 IR 里不可编辑，源码边界就是围栏）。
- `refreshMathEditing`：
  - 贴边不算「在编辑公式」（避免行尾一停就展开）；
  - 贴边光标**挪到公式外面**（视觉位置不变，但语义就是行首/行尾；也避免光标停在 `display:none` 的标记里画不出来）；
  - 收回**任何**公式 owner 身上的 `--expand`（不只我们自己挂的——Vditor 也会挂）；
  - 收回之后再确认一遍（实测点公式正中时，第一帧光标还在 owner 边界上、随后才被移进源码，
    只跑一次会把该展开的也收掉）。这条是新增的唯一额外成本，且只走「刚收回」这一条路径。
- `boundaryNode`（退格/删除的贴边判定）按实测逐条定：
  - 外层边界：删的就是这条公式（按删除方向判断）→ 选中整条；
  - 块公式的**外侧开头**退格、**源码开头**退格、**源码末尾**删除 → 都会拆围栏 → 选中整条；
  - **向内**改字（源码末尾退格、源码开头删除）→ 原样放行（实测这两条是用户正常打字的路）；
  - 紧邻的块公式（段落首退格 / 段尾删除、或光标停在块公式之前）→ 选中整条公式。
- `mathNodeOfRange` + `removeNode`：整条公式被选中后再按删除，自己摘节点（块公式换成空段落，
  行内留一个零长文本锚点接管光标），**不再交给浏览器**（实测浏览器删 `div[data-type="math-block"]`
  会留下字面 `span` 并吃掉后面的段落）。
- `keydown`：公式源码内 `Ctrl+B/I/U` 一律吞掉（`FORMATTING` 白名单之外照旧，剪贴板/撤销/全选不受影响）；
  行内公式源码里回车只把光标移到公式之后、不改文档（块公式照旧换行）。

### 2.2 `js/edit-shortcuts.js`：格式命令不进公式源码

新增 `MATH_SOURCE = 'code[data-type="math-inline"],code[data-type="math-block"]'`：
格式类动作（加粗/下划线/引用/代码）在公式源码里直接 `preventDefault + stopImmediatePropagation`，
公式命令本身（添加/取消公式）照旧。

### 2.3 `index.css`：块公式展开态用真实 `$$`

```css
.vditor-ir .vditor-ir__node--expand[data-type="math-block"]::before,
.vditor-ir .vditor-ir__node--expand[data-type="math-block"]::after { content: none; }
.vditor-ir .vditor-ir__node--expand[data-type="math-block"] > span[data-type="math-block-open-marker"],
.vditor-ir .vditor-ir__node--expand[data-type="math-block"] > span[data-type="math-block-close-marker"] {
  display: inline; color: var(--second-color); user-select: text;
}
```

折叠态不受影响（照旧只有渲染结果）；展开态视觉与原来一致（`$$` 原来就是画在这一行的同位置），
只是从伪元素换成可命中、可选中、可按字符编辑的真实文本。

## 五、如实记下的「没改」与取舍

- **公式源码里的 `Tab`** 会插入两个空格（实测 `$a+1$` → `$a  +1$`）。TeX 里空白无语义、公式不会坏，
  为把改动面压到最小，**保持原样**。
- **公式源码里输入 `$`** 会插入字面 `$`（`$a+1$` → `$a$+1$`）。这是模块既有且刻意的策略
  （源码里的 `$` 与 `|` 都按普通 TeX 输入处理），**保持原样**。
- **行内公式源码里回车**：现在这一下不改文档、只把光标移到公式之后（修复前会产生 `$a$a+1+1$` 这种垃圾）。
  我也试过「移出光标后重发一次回车让 Vditor 断行」，实测 Vditor 不响应合成事件（不改文档也不断行），
  所以选了保守版：**不回文档**。真实使用时第二下回车就是正常断行。
- **删除整条块公式**会在原位留下一个空段落（光标有地方落）。这是刻意的：不留空行就没有锚点。
- **「`$$` 之前」那个位置**（前标记 offset 0）会被归一化成「公式之前」（视觉同一处），
  实测鼠标点不到那么左的位置、按 `Home` 也会归位；两个 `$` 之间、两个 `$` 之后都能落光标。

## 八、需要你亲手验的三件事

1. 打开《排版测试-数理逻辑1(1).md》：光标点在一行末尾、而这一行以公式结尾 → 不该再冒出预渲染框；
   点公式本身 → 仍然展开源码给你改。
2. 点一个 `$$ … $$` 块公式展开 → 鼠标点在前后两个 `$$` 上，光标应该能落在里面（两个 `$` 之间也能）；
3. 光标停在 `(2)` 前那一行按退格 → 公式还在（第一下只是把整条公式选中，再按一下才整条删除）。
