## 一、取证（全部对着**已安装的 2.1.1** 跑，CDP 真鼠标/真键盘）

上一轮的教训：修复只在开发树里被断言过。所以这一轮第一步不是改代码，而是**用真产物复现你的三条**。为此写了五个一次性探针（`scripts/acceptance/probe-math-user{,2,3,4,5}.cjs`，只观测，不改产品代码；素材一律先复制、结束删副本）。

### 1.1 `(2)` 前那条"空行"在 IR 里根本不存在

素材那一段的 DOM 结构（探针直接转储）：

```
blockquote
├─ p      "受限量词的否定: 范围不动, 翻量词否内核 (1)"
├─ div[data-type=math-block]   $$…\exists x\in A…$$     ← (1) 的公式块
├─ p      "(2)"
├─ div[data-type=math-block]   $$…\forall x\in A…$$     ← (2) 的公式块
└─ …
```

源码里的 `>` 空行在 IR 里被折叠掉了：`(1)` 的公式块**直接压着** `(2)`。你点的那条"空行"，在屏幕上是公式块的底部留白（公式块 85px 高，渲染结果只占 27px）。点它 → 光标落进公式源码（实测 `TEXT"\neg\,\exists x\in A…"@0`，或 `code[math-block]@0`）→ 退格就出事。

### 1.2 「公式直接被删除」的真实机制（探针 A1/A2）

| 操作 | 2.1.1 实测 |
|---|---|
| 点 (1) 的渲染结果（光标落成 `code[math-block]@0`）→ 退格一次 | **整块 `$$…$$` 散进上一段**：`> (1)` 变成 `> (1)\neg\,\exists x\in A, P(x)…`，围栏没了 |
| 点公式底部留白 → 退格一次 | 文档不变（被 2.1.1 拦住了） |
| 同上 → **再**按一次退格 | **开头的 `$$` 被吃掉**：`> $$` → `>` |

也就是说：2.1.1 的保护只覆盖了"光标在源码文本里"的形状，`code@0` 这种元素级形状完全没有保护（一次退格就毁）；而被拦住的形状，第二下也会破坏围栏——你说的"公式直接被删除"，在 2.1.1 上完全成立。

### 1.3 `$$` 围栏：可见，但意义不成立（探针 B）

展开后两个 `$$` 确实是 15×14 的真实元素（2.1.1 的 CSS 修复生效），但命中之后的行为是坏的：

| 点哪儿 | 2.1.1 实测光标 |
|---|---|
| 前 `$$` 正中 | 落在 `TEXT"$$"@1`（标记里）——但**接着打字，字符跑到了源码末尾**（`…\neg P(x)Z`）：所见非所得 |
| 前 `$$` 左半 | 被甩到块外（`blockquote@1`），公式反而收起 |
| 后 `$$` 任意位置 | 光标掉进下一段（`TEXT"(2)"@0/1`） |

这就是"无法把光标插到前后两个 `$$` 的任何位置"的真相：能画出光标的位置不是可编辑位置，可编辑位置又点不到。

### 1.4 行尾公式的预渲染框：时序竞争（探针 3/4）

同一个"点公式左缘外 1px"的操作，两次运行结果不同：一次 `展开=inline-node`（浮框留着），一次 `展开=(空)`。原因是 Vditor 自己会在选区变化时给光标所在（或紧邻）的节点挂 `--expand`，而 2.1.1 只在选区变化那一遍"收一次"，**谁先谁后不由我们决定**。你看到的是"收不回"的那一半。

### 1.5 顺带确认：点击 → 光标落点映射（探针 3）

行内公式框内按比例点击（宽 84px）：框内 0.05 → `code@0`；0.2→`TEXT@0`；0.5→`TEXT@6`；0.98 与"右缘内 1px" → `TEXT@12`（源码末尾，仍然在公式里）。**框外** 1px 起 → `p@2`（不在公式里）。所以"贴边"判定的安全边界只能按容器位置分，不能按像素分。

## 二、修复

改的都是 `Typora-Editor/extension-src/render`（单一真源，`app/renderer` 由 `npm run sync` 生成）：

### 2.1 `formulaEdge` 补齐**元素级**光标位置（`js/math-edit.js`）

新增两支：容器是源码元素自身（`code@0` / `code@childCount`）时按源码边界处理；容器是围栏标记元素时按外层边界处理。这直接修掉 1.2 表格里那两种破坏（一次退格散块、第二次吃围栏）。

### 2.2 贴边退格改成「只把光标挪出去」，不再"整条选中"

命中贴边位置时：`preventDefault` → `hopOutside(node, backward)`（把光标挪到公式外面最近的**文字**位置）→ 文档零改动。第二下按的就是普通文字退格。顺带把行内公式源码第 0 个位置也纳入拦截（v2.0.4 那个"整条消失"的形状对行内仍会漏）。

用户主动整条选中公式再删除的路径保持不变（`mathNodeOfRange` → `removeNode`，不留 `span` 残渣）。

### 2.3 展开态改为**结构性强制**（`MutationObserver`）

`installMathEditing` 里新增一个只盯 `attributeFilter:['class']` 的观察器：**任何**加在公式节点上的 `--expand`，只要不是"光标真的在它的源码/预览里"造成的，立刻撤掉。不再有"再跑一遍"的时序赌博。原来那条一遍性收回逻辑保留（快路径），观察器是兜底。

### 2.4 `$$` 围栏点击语义（`mousedown` 捕获）

点开围栏 → 光标落在源码**开头**（`code` 第一个文本节点 offset 0）；点闭围栏 → 落在源码**末尾**。这两个位置都是真实可编辑位置，接着打字的字符就落在你点的那一侧（磁盘字节为证，见 §3.2）。

### 2.5 保留不动

2.1.1 的其余修复（整条删除不留残渣、公式源码内 `Ctrl+B/I/U` 与回车不改坏 TeX、折叠态不显示围栏、`edit-shortcuts.js` 里公式源码内的格式键忽略）全部保留。

## 四、如实披露（三件）

1. **没做到的事**：你期望"源码编辑只删掉最后一个 `$`"。`$$` / `$` 是 Vditor 每次重排时重新生成的标记，IR 里不存在"删掉一个 `$`"这个可编辑动作（实测改标记文本不参与序列化、会被丢弃）。本版选择**贴边退格不改文档**（第二下删公式外的普通文字），而不是假装删一个 `$` 把公式变成半截文本。要删整条公式：整条选中 + 一次 `Backspace`/`Delete`。
2. **见过一次不可复现的抖动**：`test:renderer` 批次第一次跑时出现 5 条公式渲染/映射断言红（`regression.js` 里等 KaTeX 完成的时序断言），随后单独重跑该模式 16/16 通过、完整批次连跑两次全绿、2.1.1 渲染层同批次也绿。失败簇的形态与"窗口被判为隐藏时数学调度暂停"这一已知环境因素一致。我顺手给观察器加了 `e[mode]?.element` 空值保护（装载/切换期确有 `element` 尚未就绪的窗口，原写法会从 MutationObserver 回调里抛异常）。
3. **本轮我自己犯过一个状态错误**：后台跑的基准 A/B 脚本被中断，`app/renderer` 停留在 2.1.1 渲染层，导致随后两次"观察器成本"探针测的是旧层（结果显示"产品没建观察器"）。发现后 `npm run sync` 复原并重跑，§3.4 的数字来自复原后的运行。涉及这两次探针的任何结论都已作废。
