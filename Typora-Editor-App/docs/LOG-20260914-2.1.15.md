## 一 ① 点块公式行末，光标跳过末尾逗号

**取证**：`scripts/acceptance/probe-math9.cjs`（不点击、直接调产品函数 `sourceOffsetAtPoint`，
把"落点 → 源码偏移"按 **1 像素网格**铺出来）。用的是**用户原文档第 195 行**那条
`1=\lim_{n\to\infty}\int f_n\,d\mu\neq\int\Big(\lim_{n\to\infty}f_n\Big)d\mu=0,`：

```
字形盒： «=»@75 x 571..584   «0»@76 x 589..598   «,»@77 x 598..602
y=398：  x 587..597 → 76      x 598..885 → 77      x 886..888 → null
```

- 行末那条 288px 的空白带（x 598..885）本来就停在末尾逗号之前（**这一段是对的**）；
- 会"跳过逗号"的是 `0` 的右半边（x 594..597 那几像素）→ 76，即"光标落在要点的字符再往前一格"。

**根因**：`targetOffset` 一律返回字形**起点**。一个 9px 宽的数字格子，点右半边也停在它前面。

**修法**（`render/js/math-source-map.js`）：

1. `mappedMathNodeAtPoint` 改成返回 `{node, after}`（半格信息）；
2. 左半 → 字形起点；右半 → 字形之后（`end`）；
3. **公式最后一个字形**的右半边仍然停在它之前（`end < rendered.length` 才允许"之后"）——
   保证"点行末"永远停在最后一个字符之前；行末空白带落到的那个"最近字形"也走这条；
4. 缝隙里的"最近字形"同样按半格判定（否则缝里会退回上一格：实测第一版修复后在
   `=`(571..584) 与 `0`(589..598) 之间那 5px 的缝里出现 `76 → 75 → 76` 的非单调，
   补上之后 569..577→75、578..593→76、594+→77 单调）；
5. 命令字形（`rendered[start] === '\\'` 且长度 >1）左右半边都落到反斜杠之后（见 ②）。

**回归门**：`scripts/acceptance/scenarios/85-block-math-click-2.1.15.cjs`（A 组）。
A/B（把 `half()` 强制为 false）：点 `0` 右半边 → **76**（用户报的形状），断言红。

## 二 ② 点显示模式的 ∑/∫，光标落进 `\sum_{}` 第一个参数

**取证**：`scripts/acceptance/probe-math6.cjs`（真产物；每次点击前当场重量几何，避免"取几何"与
"真点击"之间版面变化污染落点——上一版探针就栽在这上面）。

```
显示模式：<span class="mop op-limits" data-typora-source-start="0">   ← 映射挂在外层 mop
            └ <span class="mop op-symbol large-op">∑</span>           ← 字形自己没有映射
点 ∑ 正中 (397,240) → 映射值 7 → \sum_{i|=1}
行内对照 $\sum_{i=1}^{n} a_i$：∑ 自己有映射（∑@0-4）→ 点它是 \|sum（offset 1）
```

**根因**：旧实现第三级判定是"离落点最近的**映射字形**"；∑ 自己没映射，最近的就是下标里的 `=`。

**修法**：在"包含落点的叶子字形"与"最近字形"之间加一级——落点压在**自己没有映射、但这一层确实
画着字**（无子元素且文本非空）的元素上时，用它**外层映射元素**的位置；容器不给 `after`（容器
的 `end` 是"组"的右界，不是字形右界）。命令一律进到反斜杠之后。

> 复查发现的两个坑（都用同一张像素网格量出来的）：
> 1. KaTeX 的 vlist/strut 空壳会横向盖到相邻字形上（y=398 处 x=410 那 1px），拿它当依据会把光标
>    退回上一格 → 加"这一层自己就画着字"的过滤；
> 2. 修完 ①② 之后整张网格只剩 1 处"回退"：y=398 的 x=344..367 → 3（`\lim` 字形映射到外层
>    `\lim` 的 `\|lim`），而它左边的下标 `n` 给 8——这是**显示模式上下限与运算符在横向上重叠**
>    的固有结果，也正是 ② 要的行为，保留。

**回归门**：场景 85 的 B/B′ 组。A/B（关掉那条兜底）：点 ∑ → **7**（`\sum_{i|=1}`，用户报的形状），
断言红；B′ 组同时断言"块公式点 ∑ 与行内点 ∑ 得到同一个 offset（=1）"。

## 四 ④ 删除图片要两次 Ctrl+Z

**取证**：`scripts/acceptance/probe-img4.cjs`（把 `undo.addToUndoStack` 包起来逐次记录调用栈 +
栈长变化；用用户那张 1167×1264 的截图做素材）。修前：

```
栈 1 → 2  **推入**   ← beginDocumentEdit (media-tools.js)
栈 2 → 3  **推入**   ← commitImageEdit  (media-tools.js)   ← 真正的删除补丁
（另有 3 次调用因为补丁为空被 Vditor 自己跳过）
```

一次用户动作推两条历史；多出来那条的 markdown 与上一条完全相同（按 Ctrl+Z 时"什么也不发生"）。

**根因**：Vditor 的历史快照**带光标位置**（`addToUndoStack` 内部先 `addCaret`），所以"点选图片把
光标搬到图片所在块"这种纯光标移动也算一次差异；我们在两处无条件补历史点，把它固化成了死历史。

**修法**（`render/js/media-tools.js`）：`pushHistoryIfChanged(api)`——只有"历史快照换算出的
markdown ≠ 当前 markdown"才补（判据与 `typora-patches.js` 的 `flush` 完全一致）。
`beginDocumentEdit` 与 `commitImageEdit` 两处都换成它。修后：栈 1→2（只 1 条），一次 Ctrl+Z 复原，
栈回到 1（不留死历史）。

**回归门**：`scenarios/87-image-delete-undo-scroll-2.1.15.cjs` 的 ④ 组（断言"栈只涨 1"+"一次撤销
后栈回到删除前"）。A/B（换回无条件补）：两条断言都红。

## 五 ⑤ 删除"顶边已经滚出上沿"的图片：下方文字不动

实现（`media-tools.js`）：

- **条件**：图片盒 `top <` 可视区上沿（只剩下半截 + 下方文字可见）；
- **补偿量**：删除前后**内容总高（scrollHeight）的变化量**，而不是图片盒/块的几何。
  实测（场景 87 的证人）：图片盒 881px、图片所在块 `getBoundingClientRect()` 906px、
  内容总高实际少 **920px**（块级图片那一块还带外边距）；按几何量算会差 39px（第一版就是差这
  39px 被场景抓出来的）；
- **镜像情况**：图片整体在视口里 → `keepBelow` 为假 → 视口不动（下方文字上移一格），即用户说的
  "那条没问题"。

**回归门**：场景 87 的 ⑤ 组（三段下方文字位移 ≤ 3px + 自证"视口确实上移了"）+ B 组（镜像情形
scrollTop 不动）。A/B（`keepBelow` 恒为假）：⑤ 组断言红。

> 取证中的一个坑（已记）：验收窗口里**滚动容器是 `.vditor-ir` 里面那个 `pre.vditor-reset`**，
> 不是 `.vditor-ir` 自己（实测只有它 `scrollHeight > clientHeight`；`document.querySelector('.vditor-ir')`
> 的 scrollTop 怎么设都不动）。第一版场景把滚动设在 `.vditor-ir` 上，导致"图片顶边在上沿之上"
> 这个前提根本没造出来、量为 0 位移——已改成 `.vditor-ir .vditor-reset`。

## 六之二 已知项：`73-mixed-editing-stress` 偶发红（**不在**这一轮的 5 条里）

现象（三条一起红）：粘贴进去的字符串**出现 2 次** → 剪切后还剩 1 次 → 撤销后变 2 次。这是上一轮
就记为"需要单独一轮排查"的老问题。

- 本轮实测的**偶发率**：dev 连跑 4 次 **2 次红**；installed 连跑 3 次 **2 次红**；同一版产物也有跑出
  19/19 全绿的时候（本轮全量 dev 验收里它一次就过了）。
- 我顺手做过的两件事，都按"没有量到收益就撤"的规矩处理：
  1. ② 的历史修复**确实**拿掉了它的一部分成因（"多一条空历史"），所以现在偶尔能全绿；
  2. 加过一个"粘贴前先看 markdown 变没变"的防重护栏——**4 次里仍然红 2 次**，没有量到收益，
     已按规矩撤回（`probe-paste.cjs` 里单次走"右键菜单 → 粘贴"三轮都是干净的 count=1，
     说明重插只在这条压力场景的前置步骤之后才出现，需要单独一轮才能钉住）。
- 结论：**这一版不为它做未经验证的改动**，留待单独一轮（连同它的粘贴/剪切/撤销三条一起重新取证）。
