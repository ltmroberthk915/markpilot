1. 用两份**真实文档**做大规模测试——`新建 Markdown 文档-副本.md`（植树题，行内+块公式密集）
   与 `1-重识概率论.md`（169KB，272 处行内公式、17 处块公式、含表格）；
2. **先解决文本 / 行内公式 / 块公式在真实的键盘、鼠标、组合键、键鼠配合、拖拽操作下的所有 bug**，
   验收规则以 Typora 使用习惯为准、符合人类的视觉与手感；
3. 以及新立的**总规则**（视觉检验 + 真人拟真操作 + Typora 习惯 + 交互逻辑，见
   工作区 `AGENTS.md` 的「交互验收总规则」、本 skill 的铁律 26/27、`references/acceptance.md` §8）。

3. 光标真隐形（0×0）时标记也画不出来——那本身就是"光标没了"的视觉证据。

## 二 修掉的问题（每条都带复现读数与突变验证）

### 2.1 边界处丢掉目标列 ⇒"到底再回来位置不闭合"（用户 2.2.2 报告的主项）

纵向补丁在"到顶/到底"分支里调了 `reset()`，把**连续移动的目标列**一起清掉了；
于是"按 ↓ 到底 → 再按 ↑"会把**底行那一列**当成新的目标列。
读数（doc A，seed=20260918）：修复前 ↑ 段 48/77 次落点列偏离，修复后 0；V5 往返闭合转绿。

### 2.2 命中测试挑到相邻行的落点 ⇒"↓ 跳行"

`resolveAt` 按"离目标列最近"挑候选，会挑中**相邻行**的位置（实测目标列 569 时挑中
`x=876, 顶=340`），于是 y 已经扫到 380 也仍然认为它属于当前行，中间那一行被整行跳过。
改为**先取矩形真的盖住 y 的候选**；盖不住的候选之间则**先比行距、再比列距**。
读数：doc B 的 `V3 逐行不跳` 从 2 次失败转 0（doc A 66/66、doc B 52/52）。

### 2.3 扫描方向没有校验 ⇒"按 ↓ 反而往上跳"

`scan` 只要求"找到了不同的一行"，不校验方向，配合 2.2 的改动会出现 366 → 340 的回跳。
加一条方向硬约束（↓ 必须 `box.top > before.top`）。

### 2.4 目标列落在探测列空档里 ⇒ 落在行中而不是行端

固定探测列（目标列 ±32 与 0…200）覆盖不到较宽的行尾，目标列 419、行右端 368 时落在 205。
补 `lineEdgeHit`：把这一行的**最左/最右可落点**也当候选，取离目标列最近的那个。
读数：doc B `V4 列稳定` 43/43、doc A 60/60。

### 2.5 标题行的"标记展开"改写布局 ⇒ 差一个字

光标落进标题行时 Vditor 才把 `###` 显示出来、整行右移（实测同一行 y=125：光标不在这一行时
行尾 x=200，一进来变成 x=242）。"下一拍重算"原来按**已经钳过的列**去对，只能停在新布局里的
205；改成按**原始目标列**在新布局里取最近可用位置，并把重算挂到 `selectionchange`（带 200ms
截止、最多补 3 次）——比 rAF 晚的那一拍也能补上。视觉验收：修复后光标标记与目标列导线重合。

### 2.6 兜底落点（从预览映射进源码）被"放得准就早退"挡住

弱落点（`codeAtHit` 兜底）可能离目标列很远，而重算的前置判定"放得准就早退"会把它挡掉。
改为弱落点必再校一次。

### 2.7 ←/→ 在文档边界把光标放到 0×0 ⇒"光标没了"

新增 `patchCaretWatchdog`：导航键之后若光标隐形**且已经跑到所有内容块之外**，按 Typora 习惯
补一步（→ 行尾去下一行行首、← 行首去上一行行尾；实在没有就放回上一次可见位置）。
关键约束：**块内那些"看不见但正确"的位置一律不动**（公式源码折叠态、预览、围栏标记）——
否则会把"在公式里打字/走出公式"整段行为改坏（实测场景 101 由 32/32 掉到 6/12，收窄后回到 32/32）。

## 四 口径澄清（探针侧的修正，产品无缺陷）

1. **列的"正解"不是目标列本身**：目标列超出该行可落范围时，正解是**离目标列最近的可用位置**。
   探针一开始拿"目标列"当期望，把正常钳制（标题行的行首/行尾、短行）报成缺陷——改成
   `nearestOnLine`（按 y 盖住过滤、逐点扫）后误报消失。
2. **同一 y 带里可能叠着别的行/别的元素的落点**：块公式源码行 y=682 会扫出 x=866
   （应用的缩放徽标 `BUTTON.typora-zoom-badge`）与上一行尾巴；探针的行跨度与最近可用列都必须
   **按行顶/按 y 盖住过滤**，否则量出"左缘 866 / 右缘 897"这种自相矛盾的读数。
3. **键盘读数前必须确认焦点在编辑器 iframe 里**：焦点不在时按 ↓ 光标照样动、却没有任何
   keydown 进 iframe（窗口捕获监听计数 0），此时整轮读数都是假的（曾把一轮 V4 全判成缺陷）。
4. **表格有自己的交互模型**：随机起点要避开表格（单元格内的选区由浏览器按 cell 约束），
   否则会把"跨单元格选区重置"误记成选区缺陷——避开表格后 doc B 的 S2 由 31/36 变 50/50。
5. **拖拽期间可能滚动**：视口坐标就不同尺了，比较前要么把滚动量加回去、要么整轮不判。
6. 临时仪表（`__vertBuild`/`__vertKeys`/`__vtrace` 等）一律标 `TEMP-INSTRUMENT` 并在交付前清除；
   轨迹改为按需开启（`window.__vertTraceOn`，探针自动打开，产品默认零开销）。
