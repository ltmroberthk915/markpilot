# LOG-2.2.7：横向走进"整行只有一条公式"的行 + 验收探针的滚动一直是空操作 + 跳标题行的根因

本轮按用户"按你推荐处理"，做的是 2.2.6 报告里点名的下一件：**doc B 的横向 H3/H4 红**
（"→ 跳行"）。查下去牵出三件事，其中两件落了地，第三件（跳标题行）**定位到根因但修法被自己否掉**，
按项目纪律撤回、只留证据。

## 一 先说验收侧的发现：探针的滚动**一直是空操作**（先修工具，再谈现象）

`probe-real-ops` 的 `scroll(fraction)` 一直是 `window.scrollTo/scrollBy`，而**这个编辑器的滚动容器
在外壳那一层**——帧内 `window.scrollY` 恒为 0，实测：

```
滚动：{"文档高":10219, "视口高":713, "目标":951, "实际scrollY":0}
```

也就是说 doc B（166 KB）此前每一轮都只在**首屏**走查（每轮换了随机点，但没换过区域）。
先修工具（`scripts/acceptance/probe-real-ops.cjs`）：

- `scroll()` 改成"取该比例处的那一块 → `scrollIntoView({block:'start'})`"（跨帧唯一带得动滚动的方式）；
- `scrollY()` 改成"正文根的视口偏移"（与是谁在滚无关），鼠标/组合键段里"滚动前后是否变化"那条判据
  从此才真的有内容；
- H4 失败样例补上**被跳过那一行的身份**（层/文本/块内公式数/可见性/块序列/Selection 写入口栈）——
  只有 y 的样例事后没法判断"是产品跳行还是测量口径"，这一轮就卡在这里。

## 二 横向进"整行只有一条行内公式"的行：光标**没了**（已修）

用 5 行小素材确定性复现（`probe-repro-hline.cjs`）：

| 动作 | 修前 | 修后 |
| --- | --- | --- |
| 上一段末尾按 **→**（下一行是整行 `$a+b$`） | 落 `P@0`，矩形 **0×0**、公式不展开 | 落**源码** `#text("a+b")@0`，`{x:59,y:133,h:13}` 可见、节点**展开** |
| 下一段开头按 **←**（上一行同一条公式） | 落 `P@1`，同上隐形 | 落源码末尾 `@3`，可见、展开 |
| 行尾是公式（不是整行公式）的段落 | 正常 | 正常（不碰） |

**上下方向走同一条公式本来就是对的**（↓/↑ 落源码 offset 3、可见、展开 13px）——那是
`patchVerticalMathLine` 的本事；横向一直没有这一手。新增 `patchHorizontalMathLine`（事后校正，同一形状）：
←/→ 之后若"折叠 + 落点隐形 + 落在只有一条公式的块里（元素级位置）"，就把光标放进那条公式的源码
（→ 去开头、← 去末尾）；展开由 math-edit 自己的按键刷新完成（实测按键路径会展开，程序化落点不会）。

顺带修了 `邻行`（隐形兜底用的"找相邻可编辑行"）的一条老毛病：它只判"行顶不同"，会被**软换行边界**
坑到——段落在软换行处把光标渲染在**上一行的行尾**，于是"往下走"的兜底反而把光标放到上面去。
现在要求落点**严格落在行进方向上**。

## 三 "→ 跳过标题行"：根因是 Chromium 自己的移动，修法试过、**否掉并撤回**

doc B 剩下的那一条红（H4 轮 3 步 5）：起点在段末（x=464, y=298），按 → 落到下下段的 y=386，
**跳过中间的 `### 1.3.3 Def 勒贝格积分`（y=348）**。取证：

- `--trace` 的 Selection 写入口**一个都没有**（只有一次 selectionchange）⇒ **脚本没插手**，
  是 Chromium 原生光标移动；
- 被跳过的那一行**不是** `content-visibility` 跳过区（`被跳过子树: []`，元素就是 `H3.vditor-ir__node`，
  `isEditable: true`，命中也给得出可见位置 y=357）⇒ 用户**看得见**这一行，所以不是测量假象。

接着试了"**逐行拦截**"（←/→ 之后若落点比一行远、且中间还有可编辑文本行，就把光标挪回最近那一行）：

- 有效：H4 由 10/11 变 **6/6**，环形记录里能看到 `{"方向":"→","锚y":298,"落y":386,"位移":87,"校正到":349}`；
- **但代价不能接受**：H2（不卡死）从 128/128 掉到 **125/128**、H3 从 3/4 掉到 **2/4**——
  锚点几何在"增量重渲染 + 自动滚动"下不可靠（记录里出现过 `锚y:1278 / 落y:273` 这种量级），
  偶发把光标挪回原行 ⇒ 表现为"按了不动"。
- 按项目纪律（"宁可什么都不发生，也不能悄悄改坏"；"不放宽断言"）**整段撤回**，只保留上面第二节的
  横向公式行修复与 `邻行` 方向守卫。

**结论（doc B 的 H3/H4 各 1 条红保留）**：这是 Chromium 原生移动跳过一行"看得见的可编辑行"，
我们不做按键接管（2.2.4 的教训：接管 Home/End 会把场景 75 打红）；要做就得先有一个
"锚点身份稳定、跨重渲染可复算"的落点模型——那是 DOM 层那条线的活（与遗留 #1 同一笔账）。
