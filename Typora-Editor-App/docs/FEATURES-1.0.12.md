# 1.0.12 / VSIX 0.1.22：章节上下文、阅读调色盘与固定工具栏

三个改动已进入共享编辑器，EXE 和 VS Code / Trae 使用相同实现。通用 Typora CSS 安装器本轮只做兼容性评估，尚未作为功能发布。

## 章节上下文：本地建立索引，随原请求发送

打开文件时，从宿主已有的 Markdown 建立完整标题索引，不遍历页面 DOM，不请求模型，也不读取其他文件。补全仍直接生成建议，没有新增“先判断目的”的 API 调用。发送的是当前章节的上级标题、当前标题、前一个同级标题及随后两个标题，最多 1,200 字符；不会把整份目录反复塞进 prompt。没有标题时不增加该字段。

正文局部上下文、公式缺口和右侧已有内容保持原来的取样方式。标题只提供学科和章节线索，提示模型优先保留局部符号，不生成新标题。标题结构默认开启，可在补全图标的下拉菜单中关闭「章节上下文」。开关保存在各宿主原有补全配置中，不改变模型选择、API Key 或自动触发等待时间。

同一个文档版本复用索引；文档改变后，在下一次 AI 请求时更新。唯一源码片段无法定位、重复片段无法消歧时省略结构，沿用原有局部上下文。缓存键包含章节信息，避免同名小节下相似公式误用另一章的建议。关闭文件释放索引；未增加常驻轮询或后台模型请求。

### 实测成本

只读使用桌面真实文件「动态规划教材（渲染修复副本）.md」，178,107 个 UTF-16 字符、150 个标题。SHA-256：`854c06a50d591c99b53810bcb0951e291b1c7bd495336d22897b855c3748599f`。

| 项目 | 本机测量 |
|---|---:|
| 第一次建立索引 | 3.30 ms |
| 40 次预热后重建，中位数 / P95 | 0.79 / 1.38 ms |
| 从 100 个真实位置定位并选取标题，中位数 / P95 | 0.031 / 0.082 ms |
| 70 个数学位置、30 个正文位置附加的标题字符数 | 最小 68 / 中位 218 / 最大 321 |
| 所有文档的标题正文上限 | 1,200 字符 |
| 打开文件产生的模型请求 / 输入 token | 0 / 0 |

补全时新增标题及少量标签、说明会增加输入 token、模型预填充工作；实际金额和网络延迟取决于模型、分词和计费，不能把字符数当成准确 token 数。宿主保留一份规范化源码及标题索引，内存随文档大小增长。以上是本地准备成本，**没有进行在线 LLM 质量 A/B 对照或调用付费 API**；章节信息是否提高正确率仍需后续语义评测，不能从 3 ms 推导补全质量或整机续航收益。

### API 不可用的边界

单元测试覆盖缺少 Key、关闭章节上下文、HTTP 401 / 429 / 503、断网及无效 JSON。实际桌面和插件宿主用本地 HTTP 桩验证错误反馈后仍能进行本地公式补全、编辑和落盘保存。原有超时、取消、中文输入法、缓存复用和撤销机制保留。开文件不依赖 API 可用性。

标题解析是保守的 Markdown 索引：支持 ATX / Setext、层级跳跃、CRLF、标题中的公式；排除围栏代码、独立公式块、YAML、注释、常见原始 HTML 块、缩进代码和引用/列表中的伪标题。它不取代 Vditor 的完整 Markdown 解析器。

## 阅读调色盘

工具栏主题图标旁新增调色盘图标，提供「跟随主题」「米色纸张」「柔和淡绿」。可以保留 Konayuki Dark 的界面和字体，同时将正文设为米色或淡绿。调色盘只改变阅读颜色，不改变公式源码、正文、历史或渲染节点；切换不会触发公式重新排队。配色随文件重开保留。

正文、链接、引用、表格、代码背景、高亮和行号使用对应配色。样例正文对比度大于 7:1，链接和样例代码各 token、行号至少 4.5:1；这是可读性检查，不代表预防眼疲劳的医疗效果。手动给文字/公式指定的特殊颜色和图表内部配色不强制重染。

四个主题分别切换三种配色，验证 Markdown、公式节点身份和渲染计数保持不变；即时渲染、所见即所得、源码模式均覆盖。Esc 关闭调色盘对话框，并恢复原来的焦点和选区。

## 固定工具栏与大纲

工具栏始终位于编辑器顶部、跨正文和大纲区域排列；展开大纲不再改变工具栏左侧 padding。大纲从工具栏下沿开始填满剩余高度，右侧边界继续支持拖动、键盘调宽和宽度记忆。鼠标停在大纲按钮上可连续点击展开、折叠。

实测 1,180 / 650 / 420 px 宽度下，同一屏幕坐标能打开和关闭大纲，按钮位置与工具栏高度不变。修正 Vditor 将小于 520 px 的 IDE 分栏视为手机而拒绝展开的情况；大纲自动收窄，常见窄分栏保留约 240 px 正文空间。窗口本身变窄时工具栏仍可正常换行，展开/折叠大纲不会造成额外换行。

## Typora 社区 CSS：可做受限导入，不能保证原样兼容

Typora 的正文入口是 `#write`，其字体、颜色、标题、段落等样式可以映射到 Vditor 阅读区域。编辑状态、侧栏、代码和公式使用不同 DOM。Typora 官方也提醒自定义 CSS 会影响编辑行为；适配需要编辑回归，不能仅检查截图。[官方主题结构说明](https://theme.typora.io/doc/Write-Custom-Theme/)、[代码块样式说明](https://support.typora.io/Code-Block-Styles/)。

本轮用浏览器 CSSOM 离线解析已随项目保留的 Konayuki 原版 Light / Dark 文件，没有加载远程字体或执行主题内容。两份各有 216 条样式规则、385 个选择器。其中 112 个涉及 `#write`，80 个通过了基础正文迁移的启发式筛选；35 个涉及 CodeMirror，122 个涉及 Typora 特定 UI，1 个涉及 MathJax。分类有交叉，**这些数量不是兼容率**。现有 Konayuki 已通过定制转换和补充 Vditor 样式适配，并非把原 CSS 直接应用就完成兼容。

建议按下列范围考虑下一步，工期是基于现有两个宿主的工程预估，并非已完成导入器后的实测：

| 范围 | 预计增量成本 | 可承诺边界 |
|---|---|---|
| 本地 CSS 选择、保存、启用/停用、一键恢复；正文作用域隔离 | 1–2 人日 | 原生 Vditor CSS 和基础排版个性化 |
| Typora `#write` / 变量映射、主题目录与相对字体图片、预览、两端回归 | 额外 3–5 人日 | 兼容一批正文主题；逐项列出忽略项 |
| 任意主题的 CodeMirror、MathJax、侧栏、编辑状态和打印全量还原 | 无法给固定总价；持续逐主题适配 | 无法承诺一键原样兼容所有社区主题 |

推荐先实现前两层，提供「正文兼容导入」和原始 CSS 开关。使用 CSS 解析器处理选择器和资源路径，保留来源与许可证，并隔离编辑控件；不要全局替换 `#write` 后把任意 CSS 直接注入整个应用。当前这版的入口只有内置主题和独立调色盘，没有隐藏的社区主题安装入口。
