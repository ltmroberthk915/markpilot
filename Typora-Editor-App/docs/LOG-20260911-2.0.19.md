# MarkPilot 2.0.19 发布说明（2026-09-11，自用版）

本轮只做三件事：**修好导出入口**、**清掉装样子不干活的工具栏按钮**、**修鼠标侧键把编辑区翻走**。
外加一次性能测量：结论是**没有可测的优化空间**（数字见下）。

---

## 一、导出入口：文件从来没有被创建过

### 现象（用户反馈）
点「导出 PDF」→ 屏幕提示"导出中"→ 结束后**不知道文件去哪了**。

### 根因（实测取证，非推断）
工具栏「更多」菜单里当时存在**两个**导出入口：

| 入口 | 长什么样 | 里面有 PDF 吗 |
| --- | --- | --- |
| 我们自己的 `document-export` | 只有一个下载箭头图标，**没有文字、连 aria-label 都是空的** | 没有（点开是原生四格式菜单，但用户找不到它） |
| Vditor 内置 `export` | 明明白白写着「导出」 | **只有它有 PDF / HTML** |

用户想导 PDF，只能点第二个。三条路逐条实测（隔离 profile + 一次性素材）：

| 路径 | 保存对话框 | 磁盘产物 | 屏幕提示 |
| --- | --- | --- | --- |
| 更多 → 内置「导出」→ PDF | **0 次** | **无** | 「生成中」 |
| 更多 → 内置「导出」→ Markdown | **0 次** | 静默下载进系统下载目录（实测文件名被改写成 `# 导出诊断__正文.md`） | 无 |
| 文件 → 导出 → PDF 文档… | 弹出 | `%PDF-`，55,621 字节 | 「已导出 + 完整路径」 |

内置 PDF 路径的实锤：它把内容写进 `#vditorExportIframe`（实测**高度 0px、内容 544 字符**）再调
`window.print()`。在 Electron 里这不会产出任何文件——**文件压根没被创建**，所以"去哪了"无从谈起。

**应用自己的导出引擎一直是好的**：PDF（`%PDF-`）、Word（`PK`）、HTML（1.5 MB 独立网页）、
便携 Markdown（逐字节相等）四格式全部通过，现有导出回归 27 项全绿。

### 修复
1. 移除 Vditor 内置 `export`（连带 `#vditorExportIframe` 不再被注入）。
2. 「导出」提升为**工具栏一级按钮并带可见文字**，提示写明「会先问保存位置」；⋮ 菜单里不再重复一个导出入口。
3. 导出成功后**自动在资源管理器里定位产物**（`shell.showItemInFolder`，失败不影响导出结果）。
4. 取消保存对话框时发一条 `quiet` 通知，清掉上一次留在对话框里的「已导出 …」残影，且**不为取消弹新窗口**。

## 二、录音按钮：不是"不生效"，是"点两次正文就打不了字"

### 作者意图（有据可查）
不是继承来的死 UI，是本项目自己在 **0.1.7-local**「补回 Vditor 默认 34 个工具项」时**故意加回来凑数**的：

- `extension-src/CHANGELOG.md` 0.1.7-local：「补回内置表情……**录音**、撤销、重做及全屏按钮。」
- 同文件：「**录音恢复原生入口，录音文件保存仍需 Trae 宿主适配。**」
- `test/VERIFICATION.md`：「**录音仅恢复原生按钮。未申请麦克风权限；当前扩展的上传桥仍按图片保存文件，录音文件保存尚未适配。**」

### 实测后果（逐项取证）
1. 点下去**真的占用了麦克风**——拿到 1 条音轨（`AB13X USB Audio`）。Electron 默认放行媒体权限，**全程没有弹窗问过用户**。
2. 再点一次停止：音频（`video/webm`）被塞进**图片**上传通道 → 弹「**图片插入失败：不支持的图片格式**」→ **磁盘上没有任何音频文件**。
3. ⚠️ 录音开始时 Vditor 把编辑面设成 `contenteditable="false"`，**停止后不还原**：

| 时刻 | 可见编辑面 `.vditor-ir PRE` | Chromium 级按键注入（只发给测试窗口） |
| --- | --- | --- |
| 录音前 | `contenteditable=true` | 12 → 14 字符（能打字） |
| 录音中 | `contenteditable=false` | 14 → 14（打不进去） |
| 停止后 | **仍是 `false`** | 16 → 16（打不进去） |
| 切到源码视图 | sv 面 `true` | 17 → 19（能打字） |
| 切回编辑视图 | **仍是 `false`** | 18 → 18（**还是打不进去**） |

即：**点一下录音、再点一下停止，回到正常编辑模式后就再也打不了字**，且没有任何提示。
（另一种情况是系统拒绝麦克风，那样只弹一句"该设备不支持录音功能"，看起来就像"按键不生效"。）

### 处置（用户决定）
**整体移除**。应用侧从来没有音频落盘 / 转写链路，留着只有坑。

## 四、鼠标侧键把整个编辑区翻走

### 现象（用户反馈）
按鼠标「后退」侧键 → **整个页面消失**；再按「前进」→ 才拉回来。

### 根因
编辑面把每份文档都装进 `#editor` iframe，而 `app/shell/shell.js` 的 `f.src = url`
**每开一份文档都会往这个 iframe 的会话历史里压一条记录**（实测：开两份文档后 `iframe.history.length` = 1 → 2）。
Chromium 把鼠标 X1/X2 当作浏览器后退/前进，于是「后退」把这个 iframe 导航回上一个文档页甚至空白页
—— 编辑区整片消失；「前进」再导航回来。

### 修复（四道，只拦侧键，中键/右键照旧）
1. 主进程 `app-command`：吞掉 `browser-backward` / `browser-forward`（Windows 上鼠标侧键就是 WM_APPCOMMAND）。
2. 主进程 `before-input-event`：拦下 Alt+←/→（**不少鼠标驱动把侧键映射成这两个组合键**）；`Alt+Ctrl+B` 侧边栏开关不受影响。
3. 主进程 `will-navigate`：主框架不许离开本应用自己的源（顺带堵住拖入 URL、页面里漏网链接）。
4. 渲染层：外壳文档与编辑面各加一层 `mousedown`/`auxclick` 守卫，`button >= 3` 时 preventDefault（中键 = 1、右键 = 2 原样放行）。

⚠️ **诚实披露**：`app-command` 与真实的 X1/X2 物理按键**无法用程序合成**（Electron 的 `sendInputEvent`
只支持 left/middle/right），所以第 1 条我只验证了处理函数自身的判定逻辑（派发事件 + 断言 `preventDefault` 被调用），
**没有验证到操作系统送命令这一段**。这段需要用户用他自己的鼠标亲手验。第 2/3/4 条都有真实断言覆盖。

## 五、性能：这次**没有可测的空间**

用户要求：「争取在移除功能的时候优化性能，看看有没有空间，没有空间就算了。」

同一台机、同一素材、同一测量点（真 DOM 断言：正文真的进了 IR DOM），只换那 5 个 Vditor 工具项的有无，
各 7 轮交替开两份小文档：

| | 未移除（对照） | 已移除（本版） | 差 |
| --- | --- | --- | --- |
| 工具栏 DOM 节点 | 498 | 482 | −16 |
| 工具栏按钮 | 320 | 312 | −8 |
| 浮层面板 innerHTML | 21,264 字符 | 20,792 字符 | −472 |
| 编辑面内 iframe | 1 | 0 | −1 |
| 打开小文档中位 | **131.9 ms** | **133.3 ms** | +1.4 ms（在噪声内，方向还是反的） |
| 最小 / 最大 | 126.9 / 157.5 ms | 128.7 / 150.9 ms | 区间几乎完全重叠 |

**结论：移除这些项没有带来可测的收益。** 被测出的结构差异只有 16 个 DOM 节点、8 个按钮、1 个隐藏 iframe；
连"最小值"这个最抗噪声的统计量都无法区分（126.9 vs 128.7 ms），差异低于本尺子的分辨率
（本轮单次抖动带约 30 ms，远大于改动本身）。
所以本轮的这些移除**是为了正确性与体验，不是为性能**；台账在 `.perf/perf-ab/{before,after}.json`。

## 九、2.0.20：导出按钮去掉可见文字（用户反馈"太丑，中英文都要能看懂"）

### 改动
用户原话：「这个导出按钮还带着中文，太丑了。给他换一个按钮，让中国人外国人都能看懂，不要带文字了。」

- 去掉按钮上的 `<span class="typora-toolbar-label">导出</span>`，改为**纯图标**。
- 图标换成各平台通用的「**方框 + 箭头出框**」（box-arrow-up-right，即 export / 发出 的通用图形），
  与旁边的上传按钮（图片图标）、下载类图标都不撞。
- 图标说不清的部分放进**悬停提示**，中英并列：
  `导出 / Export（PDF · Word · HTML · Markdown，先选保存位置）`
- 功能、保存对话框、导出后自动定位资源管理器——与 2.0.19 完全一致。

### 为什么另起 2.0.20 而不是重打 2.0.19
2.0.19 已经**装到用户机器上**并且用户可能已经验过（本轮结束时实测：安装目录里就是 2.0.19 的
`app.asar`，sha256 `ae87842d…`，且 MarkPilot 正在运行）。同样的版本号重新出包会让"版本 ↔ 哈希"
不再一一对应，违反铁律 11 的精神，故第三位递增为 **2.0.20**。

### 断言更新（`scripts/desktop-export-entry.cjs`，31 项全绿）
原来那条「导出按钮带可见文字」改为三条更严的契约：

- 导出按钮**不带任何可见文字**（`label === '' && textContent === ''`）；
- 导出按钮是**纯图标**（恰好 1 个 svg，无文字节点）；
- 悬停提示必须包含四种格式 + 「保存」，且**中英并列**（`/Export/` 命中）。
- 另外单独一条钉住老毛病：⋮ 菜单里**不得**再出现第二个导出入口。
