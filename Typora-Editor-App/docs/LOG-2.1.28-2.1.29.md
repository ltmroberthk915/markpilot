## 一、① 软换行 + 中文输入法：光标被复位到段落开头

### 取证

新写探针 `scripts/acceptance/probe-ime-softbreak.cjs`：真按键（`Input.dispatchKeyEvent`）按 Shift+Enter，再用 CDP 的 IME 通道（`Input.imeSetComposition` + `Input.insertText`）打字；在 iframe 内挂捕获阶段的录音机，记录 composition/input/beforeinput 事件与每一步的选区。三例对照：

| 用例 | 光标在软换行后的落点 | 输入法打字的结果 |
| --- | --- | --- |
| A 段尾（有零宽脚手架） | compositionstart 选区 39 → **0**（组合被打断重启） | 字插进**段落开头**（`路边路边等间隔…`） |
| B 段中（无脚手架） | 39 → 40 → 41 平滑 | 字落在光标处（**正常**） |
| C 短段落行尾 | 同 A（跳 0） | 同 A |

差异只有一处：块尾软换行插的零宽脚手架。而它由 `input` 监听摘掉——输入法上屏的 `input`（`inputType=insertCompositionText`）也在其中。

### 根因

**在组合还活着的时候改组合所在的文本节点**：Blink 把这次组合判作失效、在节点开头重新起一次（所以 cursor 跳到 0），候选串与上屏的字都插进了段落开头。

### 修法（`render/js/typora-patches.js` 的 `removePlaceholder`）

- 组合期间只记状态不动 DOM：`let composing` + `compositionstart/compositionend` 维护，`removePlaceholder` 入口双重守卫（`composing || event.isComposing`）。
- `compositionend` 之后**推到下一个宏任务**（`setTimeout(removePlaceholder, 0)`）再摘。这一步是实测逼出来的：先在 `compositionend` 处理器里同步摘，光标**照跳不误**（组合期间那条 39→0 的指纹消失、组合稳定推进到 40/41，但 compositionend 之后立刻又跳 0）——Blink 要等这条事件派发返回之后才把组合落定。
- 另加一条：只有新行上真落了字才摘（`last.data[last.data.length - 2] === "\n"` 就直接返回），输入法空组合被取消时块尾那行不会塌掉。

### 判据（场景 100，21 条断言 / 8 证人）

- **像素证人**：窗口真实像素，观察窗是段落两行高；改前第一行有墨、第二行无墨；上屏后**第一行逐行逐点的墨量/最左/最右全都相等**（段首没被插进任何字）、**第二行从没有墨变成有墨**。
- **磁盘证人**：存盘后文件里是 `…多少棵？\n路边`，且不含零宽空格。
- **事件流证人**：全程只出现一次 `compositionstart`（组合没被打断重启）——根因的直接指纹。
- 指标：`imeSoftBreak.compositionRestarts`（次，越低越好）。
- **负对照**：临时撤掉守卫后同一场景 11/21，失败项正是用户描述的症状（`路边路边等间隔种树…`，字插在段首）。

## 二、② 公式光标家族

### 先按用户要求"按实际书写笔记流程按实际键盘输入一个一个测"

新写体检探针 `scripts/acceptance/probe-note-flow.cjs`：从空文档开始，用真按键一路写一条笔记（标题 → 正文 → 软换行 → 行内公式 → 块公式 → 加粗 → 行内代码 → 列表），共 82 步，其中 36 步是"输入型"校验。校验的不变量与光标在哪无关：

> 输入 T 之后，块的源码文本 == 输入前文本在光标处插入 T；光标 == 原光标 + len(T)

跑完 0 不符（修好之后）。过程中探针自身踩的坑（记录下来免得下次再踩）：

- 用"点一下写作区"拿焦点不行：编辑区顶部那 30px 被浮动工具栏占着，点了什么都没发生，随后 68 步全部静默落空（全报"没有选区"）。改成显式 `surface.focus()` + 落一个折叠 Range。
- `Enter` 必须走 harness 的 `enter()`（带 `text:'\r'` 那个 char 事件）。自己拼 `Input.dispatchKeyEvent` 只发 rawKeyDown，浏览器不做默认插入，回车成了空操作，C/D/E/G 四条流程全歪。
- 块公式的块是编辑面的直接子节点（不在 `<p>` 里），量"块源码"时要退到公式节点自己；`$$\n…\n$$` 与 `$$…$$` 的换行差异是 Lute 收放围栏的形式，比对时要归一化。
- 字符串 `'$$'` 在 `String.replace` 的**替换串**里是转义（会被换成单个 `$`），要用函数形式。

### 四处根因与修法

| # | 根因 | 修法 |
| --- | --- | --- |
| 1 | `selectOutside` 优先落在公式节点旁的**空文本节点**上；Chromium 把空文本节点上的位置归一化回前一个文本节点，而公式里的前一个文本节点正是零宽的 `$` 标记——于是"右方向键走出公式"把光标停在右 `$` 上，**再按也走不出去**（实测 offset 4 → 4 → 4），接着打的字被当成"在围栏上打字"塞回源码 | `selectOutside` 跳过零长文本节点；没有可用文本节点时落在父元素的边界位置（实测这种位置型光标读回来还是它自己，在它上面打字如实落在公式外侧——探针 `probe-outside-point` 的 Q1/Q2） |
| 2 | `fenceCaret` 把"站在围栏上"一律当成"字符只能进源码"；行内公式的 `$` 其实有**内外两半**（开 `$` 之前 / 闭 `$` 之后是正文） | `fenceCaret` 按 `focusOffset` 与 `$` 的位置分出 `outside`；外侧走新的 `insertBeside`（直接建一个装着这段文字的文本节点，不落在位置型光标或空文本节点上）与 `standOutside`（输入法起手先归位再让输入法往里打） |
| 3 | 方向键在公式外侧是整块跳过去（用户要 Typora 那样"进去"） | `patchMathCaret` 增加"外侧紧贴 + 方向朝公式"分支：把光标放进源码（展开态由 Vditor 跟着光标挂上） |
| 4 | 光标停在行内公式的 `$` 标记上时按 Shift+Enter，换行被写进标记文本里——"闭 `$` 之后"这个位置随之消失，接着打的字又被公式收走 | `patchSoftBreak` 先归位到公式外侧的**真实文本位置**（`selectOutside`）再插换行 |

### 块公式的核查结论（用户点名要查）

没有同类光标问题：`$$` 独立成段立刻成块公式、打字落在光标处的源码里、围栏不会被拆散、块里回车是源码换行（既有设计，公式仍是同一个块）。`$$\n…\n$$` 与 `$$…$$` 之间的换行差异是 Lute 自己收放围栏的形式，与光标无关。

### 判据（场景 101，32 条断言 / 15 证人）

- ① 真键盘搭出 `前$q$后`；② 用户报的那一条：右方向键走到右 `$` 之外用**真输入法通道**上屏"甲" → 块源码 `前$q$甲后`、公式源码仍是 `q`、markdown 同步、磁盘文件里也是 `前$q$甲后`（**磁盘证人**）；
- ③ 方向键从外侧朝公式走 → 光标 `inCode === 0`、节点展开、**像素证人**（行内公式节点的盒子真的变宽：8px → 33px）；
- ④ 公式后 Shift+Enter + 打字：换行与字都落在公式外；
- ⑤ 公式在段尾（光标正停在右 `$` 上）的三种动作：打字、再按一次右方向键（必须真的走出去、展开态收起）、按 Shift+Enter；外加"公式在段落最末尾（右边没有任何文本节点）"那一例；
- ⑥ 块公式：`$$` 立刻成块公式、打字落在光标处、围栏不散、块内回车仍是同一个块公式；
- ⑦ 源与开发树逐字节一致 + 两处守卫代码在。
- 指标：`mathCaret.strayIntoFormula`（次，越低越好，实测 0）。
- **负对照（四条逐条生效）**：

| 撤掉哪一处 | 场景 101 的结果 |
| --- | --- |
| A 围栏不分内外半 | 27/32：`末$w子$` —— 字又进了公式（用户报的症状），磁盘证人同时失效 |
| B 空文本节点不算落点 | 31/32：只有静态守卫那条失败（见下面"如实记录"） |

## 三、顺带修掉验收基座自身的一个缺陷

`scripts/acceptance/harness.cjs` 记录 `app-stderr.log` 的"本次追加起点"用的是 `fs.statSync().size`（**字节数**），而 `attachMainInspector` 读日志后是按**字符串** `slice` 的。日志里一旦出现中文（本轮就是 KaTeX 的 `Unicode text character 甲 used in math mode`），字节数就大于字符数，切点被推后、把本次的 `Debugger listening on ws://…` 整段切掉，表现为**同一个场景每次都说"主进程调试器没接上"**（排查花了些时间：先怀疑端口占用、又怀疑残留进程，最后对着 stderr 日志才发现那行明明在）。改成按字符数记偏移。
