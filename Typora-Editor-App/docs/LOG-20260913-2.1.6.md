## 一 复现与定性（七支探针，逐条读数，不猜）

复现一律在**真产物**（安装版 EXE）与开发树上各跑一遍；坐标用 CDP 真鼠标事件打在真实屏幕上。

### 1. 先把现象量出来：`scripts/acceptance/probe-image-rightclick.cjs`

| 读数 | 值 |
|---|---|
| 右键图片之后的选区 | `startKind: #text`、**块 0**、`offset 0`、文本是 `# 第一部分 高等概率论基础` |
| 该光标的屏幕位置 | `caretY: -7059`（在视口上方 7059px，用户根本看不见） |
| 视口 | 没有跟着滚（滚到图片的位置不变） |
| 我们自己的处理器 | `contextmenu` 里 `menu.focus()` 记到的选区**已经是**文档开头 ⇒ 事情发生在我们之前 |

### 2. 谁干的：iframe realm 里给所有能改选区/滚动/焦点的入口套记录器

`Selection.addRange/removeAllRanges/collapse/…`、`HTMLElement.focus`、`scrollIntoView`、
`Element.scrollTop` 的 setter、`window.scrollTo/scrollBy` —— 一条记录都没有。
⇒ **不是任何 JS 干的，是 Blink 的原生行为**。结合"命中点不可编辑 + 当前没有选区"这两个前提，
对应的就是 `SelectionController::SetSelectionFromNone()`：把选区设成"整篇文档的内容"、光标落到第 0 位。

### 3. 触发在哪一步：`probe-image-rightclick2.cjs` / `probe-wysiwyg-steps.cjs`

- IR：只按下（不抬起）就已经在块 0 ⇒ 触发点是 **mousedown**；
- 在捕获阶段对右键 mousedown 调 `preventDefault()`，IR 就恢复正常（且我们的右键菜单照常弹出——
  `preventDefault` 不会吞掉 `contextmenu` 事件）；
- **WYSIWYG**：同一个 handler、同一个分支、`preventDefault` 也确实被调用了（记录器读到
  `defaultPrevented: true`），**光标照样在块 0** ⇒ 那边 Blink 是**在派发 mousedown 之前**改的选区，
  JS 拦不住一个已经发生的变更。

### 4. 病理集合有多大：`probe-rightclick-targets.cjs`（21 类目标逐个右键）

| 命中目标 | 右键后光标 |
|---|---|
| 图片本体、包图片的 `span.vditor-ir__node`、行内公式渲染、块公式节点、块公式渲染、代码高亮岛、原样 HTML 图片块、`contenteditable=false` 预览岛 | **被扔到块 0**（病理） |
| 正文段落、标题文字、表格单元格、代码块源码、引用块、行内代码、分隔线 | 落在点击处（Blink 正常语义，必须保留） |

⇒ 判据取"命中点放不下光标"：不可编辑（含预览岛）**或**是 `<img>` / `.katex`。
注意**不能只看 `isContentEditable`**：IR 里行内图片的 `img.isContentEditable` 实测是 `true`
（它继承了可编辑父级），但它照样中招。

### 5. 补光标补到哪里才算对：`probe-caret-timeline.cjs` / `probe-caret-strategy.cjs`

时间线采样（按下后 0/40/120/300/700/1200ms）发现两件事：

1. **mouseup/contextmenu 这一步 Blink 会再摆一次**：原样 HTML 图片块按下时已经补到块 4，抬手后又回块 0；
   素材上的图按下时补到块 111，抬手后回块 0（光标离视口 7059px）。
2. 补出来的位置**还要能用**：用"接着打一个字"当判据，三种补法里只有一种不打坏文档开头：

| 补法 | 落点 | 接着打字的结果 |
|---|---|---|
| `caretRangeFromPoint` | P / offset 4 → 最终被归一化进岛里（`editable: false`） | 字符打到**文档最前面**：`# Q第一部分 高等概率论基础` |
| 邻近可编辑文本 | 同上 | 同上 |
| **岛所在顶层块的边界之前** | `PRE` / offset 111（root 层、可编辑） | 文档开头一字不变 ✔ |

另外，`focus()` 会把光标摆到内容开头，而且这一步是**异步**落下来的：先 focus 再在 microtask 里补选区
仍被覆盖，把补选区放到下一个任务里才生效（`probe-caret-restore.cjs` 的四个时序变体：`focus`、
`nofocus`、`focusmicro`、`focustask`）。

## 二 修法（只动 `extension-src/render/js/media-tools.js` 一处）

```js
// 判据：命中点放不下光标（不可编辑 / 图片 / 公式渲染 / 包着图片的 vditor-ir__node）
const rightClickNeedsGuard = event => { … };

document.addEventListener('mousedown', event => {
  if (event.button === 2 && rightClickNeedsGuard(event)) { event.preventDefault(); ensureCaretNearRightClick(event); }
  …原有逻辑不动…
}, true);

document.addEventListener('contextmenu', event => {
  …原有逻辑…
  if (rightClickNeedsGuard(event)) ensureCaretNearRightClick(event);   // 抬手那一步会被再摆一次，这里再补
  showContextMenu(api, event, {table, img});
}, true);
```

`ensureCaretNearRightClick`：**只**在"编辑区里没有光标"或"光标正好在文档最开头（那正是 Blink 刚摆的）"
时动手；落点固定取"被右键那个岛所在顶层块的边界之前"；延到下一个任务里落地。

逐条否掉的备选做法（都有实测支撑）：

- **只 preventDefault**：IR 够，WYSIWYG 与"原样 HTML 图片块 / 代码高亮岛 / 块公式节点"不够（抬手时会被再摆一次）。
- **`caretRangeFromPoint` 解一个自然落点**：会被归一化回 non-editable 的岛里，接着打字打到文档最前面。
- **`focus()` 后立刻补选区**：focus 的覆盖是异步的，microtask 里补也照样被盖掉 ⇒ 必须延一个任务。
- **一律把光标放到邻近正文**：形状多、规则脆（列表/引用/表格里各有边界），不如统一放块边界可预期。

修完的实测（`probe-caret-timeline.cjs`，开发树 + 素材副本）：

| 目标 | 按下 | 抬手 | 抬手 +1.2s |
|---|---|---|---|
| 素材上的图片 | 块 111 | 块 111 | 块 111（**稳定**） |
| 自造夹具：普通图片 / HTML 图片 / 块公式节点 / 块公式渲染 / 代码高亮岛 | 块 3 / — / — / — / — | 块 3 / 块 0（一帧内的过渡） | 块 3 / **4** / **6** / **6** / **8** |

过渡只在一帧内（release+0 那一采样），release+40ms 起全部落到正确位置且不再变化。

## 三 场景 76：用户要的"5 倍"边缘用例（三层结构）

新文件 `scripts/acceptance/scenarios/76-rightclick-and-caret-edges.cjs`，按用户给的方法分三层：

- **① 同源**（同一段代码路径）：21 类右键目标 × "没有光标"的三种来路；左键点同一批目标（同一条
  handler 的另一半）；WYSIWYG 模式下的同一批岛；以及"没有光标"时的菜单动作（复制）。
- **② 类比**（形状相同、代码不同）：编辑器之外（工具栏）右键不弹我们的菜单；右键菜单开着时按 Esc /
  滚轮；右键图片 → "图片设置…" → Esc 不改一个字节；`Ctrl+C` 的落点。
- **③ 新想到**（时序 / 数据形态 / 组合手势）：**打开后立刻右键**（预热队列还在跑，就是用户说的"马上"）；
  连续两次右键；右键 → 关菜单 → 再右键；右键后按方向键 + 回车；左键选图 → Ctrl+C；
  "文档第一块就是图片"（专门防"块下标 0"这种判据假阳性）；素材真机形态（滚轮找图 → 右键 → 打字 → 保存，
  用磁盘字节当证人）。

规模：**114 条断言 / 78 条独立证人**（每条断言都带读数、每步留截图）。旁证：上一轮同区域的场景 75 是
50 条断言。

写这个场景时踩到并修掉的"假红/假绿"（都留了注释，防止下一个人再踩）：

1. **坏图会污染"会话无 console 错误"这道闸门**：夹具里放一张不存在的图片必然产生一条 404 log，
   而闸门要求会话里不许出现新增 console 错误 ⇒ 用坏图测"图片没加载完"会把闸门本身弄脏。
2. **模式没切回来**：WYSIWYG 小节之后没切回 IR，后半场所有 IR 选择器全部点空（脚本里的 `mode` 一栏
   明确写着 `wysiwyg`）。
3. **`scrollTop` 读错了元素**：IR / WYSIWYG / 预览三处各有一份 `pre.vditor-reset`，
   `querySelector` 挑到的可能是隐藏那份（永远读到 0）。
4. **点不着会让整条场景崩**：`rightClick` 失败时返回的对象没有 `after` 字段，散落各处的
   `result.after.blockIndex` 直接抛异常 ⇒ 失败时也填上与"没点之前"相同的读数，另用 `result.ok` 断言。
5. **裸 `code` 会挑中行内公式的源码**（`code[data-type="math-inline"]` 折叠态是 0×0，鼠标点不到）。

## 四 已知边界与未覆盖（如实记账）

- **右键菜单开着时按 Esc 不关菜单**（现状记录在场景 76 的证人里，本轮**未改**）：产品只在"点到菜单外面"
  或"再开一次菜单"时关闭它。这条与用户报的 bug 无关，属于另一个 UX 小口子，留给你决定要不要修。
"- **光标本来就停在文档最开头**时（Ctrl+Home、或在文首点过一下），右键图片也会把光标挪到图片旁边——这两种情形在代码里长得完全一样（都是"折叠光标 / offset 0 / 在第一个块里"），无法区分。取舍：优先保证用户报的那条（Blink 刚摆出来的那个位置必须被改掉）。
- **编程式（既不发 keydown 也不发 beforeinput）的选区改写**不在守卫覆盖内——本产品的菜单里没有
  这类入口。
- **阅读模式（预览）**下右键图片走的是另一套 DOM（不是可编辑区），本轮没有改它的行为，也没有断言它的
  光标（那里没有光标可言）。
- 本轮**没有**触碰公式相关的任何逻辑，2.1.5 的空 `$$` 归位修复原样保留（场景 75 全绿）。

## 五 对用户那句"打开一段时间之后就不跳了"的解释

不是时间的问题，是**"文档里当前有没有光标"**：

- 病理只在"编辑区没有选区"时发生（刚打开就是这样）；
- 第一次右键之后（旧版本里）光标已经躺在文档开头了，于是**第二次右键时"已经有选区"**，
  Blink 不再重置 ⇒ 看起来"好了"；
- 中途只要你点过正文、打过字，光标存在，也就不会再跳。

探针里的对照读数（`probe-image-rightclick.cjs` 用例 B：紧接着再右键同一张图）就是"没动"——
与用户的观察一致。**修完之后这两种情形都正常**（场景 76 的"连续两次右键"用例）。

## 十一、日用巡检（模拟真人操作）：又找到三条真缺陷并修好

用户随后追加要求："继续找 bug，模拟日常操作，测试场景和前面的重复（不许重复）"，并要求凑够 10 条。
这一轮按"日用动作"另起一批探针（`probe-daily-ops*.cjs` / `probe-key-matrix.cjs` / `probe-file-fidelity.cjs` /
`probe-structures.cjs` / `probe-zoom-check.cjs` …），判据一律是磁盘字节、真实 DOM 标签、比例徽章这类
代码之外的东西。**先说结论：找到并修好 3 条真缺陷；另有 1 条定位到根因但没修（在解析层，另开一轮）；
没有凑够 10 条——下面如实列出所有量过的方向与它们为什么不是缺陷。**

### 修好的三条

| # | 缺陷 | 用户会怎么遇到 | 根因 | 修法 |
|---|---|---|---|---|
| 1 | 文件树的内联输入框（新建 Markdown / F2 重命名）**拿不到焦点** | 点完"新建"直接打字 → 字全丢；先点一下输入框再打 → 文件名被接成 `未命名.md我的笔记.md` | `renderTree()` 先在 DocumentFragment 拼好、最后才 append，而 focus() 排在 `queueMicrotask` 里，跑的时候输入框还在游离态（focus 静默失效） | `focusWhenAttached()`：挂到文档上再聚焦（最多约 160ms），新建/重命名复用 |
| 2 | **CRLF 文件保存后被整篇换成 LF**（实测 CRLF 6 → 0） | Windows 记事本打开变成一行；git 显示整篇改动 | 编辑区一律 `\n`，落盘时没有按原文行尾还原 | 打开时记 `eol`/`finalNewline`，`diskText()` 按它还原（CRLF→CRLF；原文无末尾换行就不补） |
| 3 | 桌面版**内容缩放快捷键全哑**（Ctrl+= / Ctrl+- / Ctrl+0） | 按了没反应，只有 Ctrl+滚轮能动 | 桌面 preload 故意提供 `acquireVsCodeApi` 兼容层 → `window.__vscodeHost` 在桌面版也是 true → zoom.js 不装桌面版快捷键 | preload 加 `markpilotDesktop` 标记；vscode.js 用 `!!vscode && !window.markpilotDesktop` |

三条都留了验证读数（探针）与回归断言（新场景 `scenarios/77-daily-ops-regressions.cjs`，25 条断言 / 13 条证人，dev 全绿）：

- 焦点：#1 修前 `focused: false`（activeElement 停在 `btn-new-md`），修后 `focused: true` 且真按键打字替换掉主名、扩展名保留；F2 同理（隔离环境实测 +120ms 起稳定聚焦）。
- 行尾：四种风格（CRLF/LF × 有/无末尾换行）+ BOM 全部逐字节保真；`diskText` 的转换另有 5 条单元级用例。
- 缩放：修前徽章恒 100%（键盘事件确实到了页面、`defaultPrevented=false`），修后 100→105→110→105→100，Ctrl+滚轮照旧。

### 定位到、本轮没修的一条（如实记账）

**带标题的链接引用定义会丢标题**：`[doc]: https://example.com/doc "示例标题"` 在**打开时**（Vditor/Lute 的 Md→IR 解析）标题就没了，改任何一个字再保存，磁盘上的定义行就永久变成没有标题的形态。
不是我们的保存路径丢的（打开瞬间读 `vditor.getValue()` 就已经没有标题）——修它要动"源码级块的保留策略"（incremental-ir 目前只缓存解析后的 DOM），风险与收益要单独评估。
场景 77 用"现状记录"断言把它钉住：将来谁修好了，那条断言会变红提醒更新文档。

### 量过、确认**不是**缺陷的方向（免得下一个人再跑一遍）

- 键盘 × 12 类块的 125 条组合（方向键/Enter/Shift+Enter/Tab/Esc/Backspace/Delete/Ctrl+B/I/K）：内容字符多重集零丢失（唯一的 9 条告警是 Ctrl+K 会插入 `https://` 造成的，属判据口径问题）。
- 表格：右键插入/删除行 + 一次撤销逐字节回退、单元格里 Tab、选中整行 Delete、base64 图片保存后逐字节不变、对齐属性落盘与撤销。
- 大纲点击跳转（长文档 scrollTop 0 → 4693）、查找替换"全部替换"+ 撤销、列表回车续项/退出、标题回车、任务清单勾选、撤销 12 步 + 重做。
- 文件保真：BOM 保留、末尾无换行不补、中文/空格/emoji/无扩展名文件名可开可存、只读文件保存失败时编辑内容不丢（该路径会弹原生模态，探针不点它）。
- 大文档打字：315,027 字节素材上 keydown→DOM 更新中位 3ms、最大 5ms。
- 同一文件开两次只开一个窗口；保存后 Ctrl+Z 能退回原样并可重新保存；front matter 内部编辑可落盘；脚注/`[toc]` 结构保存后仍在。
- 主题/快捷键/关于/调色盘弹窗开关不改文档；阅读模式来回不丢光标；源码模式来回 IR 值逐字节一致（IR 与 SV 的差异是 Lute 对表格分隔符与块间空行的既有归一化）。

### 探针自身的坑（这一轮踩掉并写进注释的）

1. CDP 拖拽的 mouseMoved 必须带 `button: 'left'`，否则 Blink 不认（"拖选不了文字"的第一版误报就是这么来的；同一条序列在**外壳页**上也选不出文字，才判定是探针问题）。
2. `Ctrl+Home` 是"文档开头"不是"行首"，行首用 `Home`。
3. 夹具里放"坏图"会必然产生一条 404，而验收闸门要求"会话无新增 console 错误"——用坏图测"图片没加载完"会把闸门本身弄脏。
4. WYSIWYG 小节之后必须切回 IR，否则后半场所有 IR 选择器全部点空。
5. IR/WYSIWYG/预览三处各有一份 `pre.vditor-reset`，滚动位置不能拿 `querySelector` 随便挑。
6. 只读文件的保存失败会弹**原生模态**（`showMessageBoxSync`），探针点不掉它、会卡住整轮。
7. 自己拼 `keyDown(text:...) + char` 会把一个字符插两次（要用 harness 的 `key()`）。
8. 素材里有 base64 图片，`getValue()` 是**掩码后**的短 URL（portable-images 的设计），逐字节比较必须用无图片的夹具。

## 十二、继续日用巡检：源码形态保真这一族（又 6 条，同版一起出）

用户的要求没有变（"不找到十个日常真人操作时候可能会遇到的 bug，不许停止"），于是换了一条线索继续：
**凡是 IR 里表达不了的源码写法，序列化时都可能被吃掉**。这条线索一口气产出 6 条真缺陷，
而且最后一条是**我自己修复里的缺口**——值得完整记下来。

### 这一族为什么危险

它们的共同症状是："我只改了一个字，保存后文件却少/变了别的东西"，而且**渲染结果跟着变**：
硬换行没了 → 本该换行的地方不换行；缩进代码块被拉平 → 代码变成散文；围栏信息串被截断 →
文档站的高亮范围失效；引用式标题丢 → 悬停提示没了。用户很难当场发现，往往在 git diff 里才看到。

### 六条清单（探针 + 磁盘字节判据）

| # | 缺陷 | 实测证据 | 修法 |
|---|---|---|---|
| 5 | 行尾两空格（硬换行）被剥掉 | `这一行末尾有两个空格  ` → 无空格 | 按"去掉行尾空白的那一行"记原文行，保存时还原 |
| 6 | 行尾反斜杠（另一种硬换行）同样被剥掉 | `…结尾\` → 反斜杠消失 | 并入上条：空格/制表符 ≥2 或**奇数个**反斜杠 |
| 7 | 四空格缩进代码块被拉平成正文 | 打开瞬间 `getValue()` 就没缩进；存盘后代码散成段落（DOM 里仍是 `code-block`） | 按 Markdown 定义认出缩进块，**整段顺序**匹配还原 |
| 8 | 围栏信息串被截断 | ```js {1,3-5} → ```js；`title="示例"` 丢 | 按文档顺序记围栏原文行，语言序列一致才还原 |
| 9 | 引用式定义标题丢失 | `[doc]: url "标题"` 打开时解析层就丢，保存后永久丢失 | 读原文记下带标题的定义行，按"同地址且未被改写"还原 |
| 10 | **上面五条在 CRLF 文件上全部失效** | CRLF 组合探针：五项保真 0/5（且缩进代码块会把后面的围栏并掉） | 所有行级收集器统一按 `/\r\n\|\r\|\n/` 切行 |

第 10 条是我自己在同一轮里引入的缺口：收集这些"原文行"时用的是**原始磁盘内容**（CRLF 行尾带 `\r`），
而保存前比较用的是**编辑区的 LF 值**，于是五类还原在 CRLF 文件上一个都不生效——正则以 `$` 结尾的
（硬换行、定义标题）连收集都收不到。这正是"每一类都要跨文件形态再验一遍"的价值。

### 回归

新场景 `scenarios/78-source-form-fidelity.cjs`：6 个用例 × 4 条断言（就绪 / 编辑落盘 / 形态逐字节保留 / 渲染形态），
24 条断言 / 6 条证人，dev 全绿；加上场景 77（输入框焦点、CRLF/BOM/末尾换行、缩放快捷键、定义标题）与场景 76（右键光标），
本轮一共 **10 条缺陷**全部有回归断言与磁盘证人。

### 量过但**不是**缺陷的（免得后人重跑）

- 表格里**未转义**的竖线（`` `c|d` ``）：按 GFM 本来就非法（表格按未转义 `|` 切格，代码跨度不豁免），
  Lute 解析时就把那一格切掉一截，且**打开瞬间 DOM 里就已经少了**（不是保存丢的）——只记账。
- 表格分隔符按列宽重排（`---` → `--`）、块间空行归一、嵌套引用多一个 `>` 空行、连续/末尾空行合并：
  都是**渲染等价**的归一化（Lute 的既有行为，仓库里早有记录），不是语义丢失。
- 混排归一化后仍然逐字节保真的：ZWJ emoji、国旗、组合重音符、RTL 混排、制表符、HTML 实体、反斜杠转义、
  超长单行（8000 字符）、十层嵌套列表、十二列宽表格、原样 HTML 块、U+2028、多反引号行内代码、
  空单元格/空 alt/[X] 任务框/未定义脚注与引用、紧贴的块边界（段落+围栏/表格/列表）、列表里的缩进围栏、引用里的围栏。

### 仍未覆盖（诚实记账）

- **导出（HTML/PDF/Word）**：链路必弹**原生保存对话框**（`dialog.showSaveDialog`），CDP 点不到；
  试过用 SendInput 敲回车绕过，但脚本的 `origin` 会把窗口强制置前、原生菜单/对话框拿不到注入按键，未能驱动。
  → 需要人工点一次，或后续做"OS 级对话框自动化"。
- **打印**：主进程里没有 print 分支（导出 PDF 走的是导出链路）→ 无独立可测路径。
- **AI 行内补全**：需要 API key，本机没有可用凭据 → 未做交互测试（产物级检查在既有场景里）。
- **快照的 5 分钟定时抓取**：定时器是 5 分钟，本轮用"保存时抓快照"验证了列表/预览/恢复为副本，未等定时器。
- **只读文件的保存失败**：会弹原生模态（`showMessageBoxSync`），探针点不掉；只验证了自动保存路径的冲突提示。

### 内存（同一天量过一次，记录下来）

305KB 素材（5634 处公式）会话里：基线 487MB → 150 次混合编辑后 ~613MB → **抽干撤销/重做历史后仍 ~601MB**；
同一时长只开着不动的那一组是 487 → 459MB。再跑 3 轮（每轮 15 次编辑 + 抽干历史 + 新编辑清重做栈）得到相邻增量
`[15.3, 65.8, 6.8]MB`：**先涨后趋平**（有界缓存，不是线性泄漏），故本轮不当作缺陷，只留数字。
