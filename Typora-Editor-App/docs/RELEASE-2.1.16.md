## 一 ① 口径改正：行末的点全都落到"逗号之后"

**你说的原话**：「点在 `$$ 1=\lim…=0, $$` 这一行的最后一个逗号及之后的任何本行元素处，光标都会被映射到逗号之后」。

上一版我按"停在逗号之前"实现（以为那是你要的），所以你看还是不对。现在按你的口径：

```
末尾三个字形： «=»@75 x 571..584   «0»@76 x 589..598   «,»@77 x 598..602
修后（probe-math9 的 1 像素网格，y=398 行）：
  x 587..593 → 76（`0` 之前）    x 594..597 → 77（`0` 之后）    x 598..608+ → 78（逗号之后 = 源码末尾）
```

规则：**公式最后一个字形**（左右半边都算）连同它**右侧的空白带**一律返回这条公式源码的末尾；它前面那些字形仍按半格走（左半→它之前、右半→它之后）；命令（`\sum`/`\int`/`\lim`）仍然落到反斜杠之后（那是你 ② 要的）。

A/B（把行末规则关掉）：点逗号的**左半边**给 77（你看到的"没修好"），断言红。

## 二 ④ 第二种机制：Vditor 自己那条"空历史"

上一版修的是"点选图片这个纯光标移动被我们记成一条空历史"。这次我在**你的原文档**（16.9 万字节、公式密布）里把图片插到「紧跟第 196 行那条块公式」的位置，一次 Delete 推了**两条**（`probe-img7.cjs`）：

```
栈 1→2  **推入** ← commitImageEdit（真正的删除补丁）
栈 2→3  **推入** ← index.min.js（setValue 之后 Vditor **自己的去抖 push**，前后 markdown 长度都是 15256）
```

第二条的 markdown 与第一条**完全相同**（但 Vditor 的历史快照是 HTML 层的，公式重排/reconcile 挪节点会让快照不同、补丁非空）。你按第一次 Ctrl+Z 撞上的就是它——所以"要两次"。

**修法**：在撤销/重做那一层**跳过空步**——走完一步之后如果 markdown 一个字都没变、栈里还有更早的补丁，就接着再走一步（最多 3 步）。这样：

- 你的体感变成"**第一次 Ctrl+Z 图片就回来了**"（场景 89 实测）；
- 历史记录一侧**不动**——我第一版是把空补丁拦在入栈那一侧，结果把两条合法断言弄红了（渲染层套件的 `ir math undo`、`wysiwyg list undo`：它们正是"markdown 相同但结构不同"的撤销步），所以改成只动手势、不碰记录。

## 三 ⑤ 拖拽抖动：这次抓到真凶是**块公式**的展开

`probe-jitter.cjs` 逐拍 40ms 采"块公式盒子 + class 翻转 + 顶层块布局 + 拖拽端点"：

| | 块盒高度序列 | `--expand` 翻转 | 结论 |
| --- | --- | --- | --- |
| 修前 向上拖 | `91,91,…,118,118,91,91,118,91,…` | **4 次** | 抖动（高度差 27px = 源码行那一条） |
| 修前 向下拖 | `91,…,118,118,…,91` | 2 次 | 位移压不到指针，症状轻 |
| 修后 两个方向 | `91,91,91,…` 全程不变 | **0 次** | 零布局变化 |

根因：2.1.11 修的是**行内**公式（`.typora-ir-pointer` 那套 CSS 只写了 `[data-type="inline-node"]`）；块公式一展开就把源码行插进版面，端点下面的文字整段位移 → 端点落到别处 → 再翻一次，反馈环。块公式用 CSS 压不住（折叠态那点间距来自 Vditor 画在 `::before/::after` 上的围栏，我把源码行藏掉反而从 118 掉到 27，位移更大——这条也量过并按"没有收益就撤"的规矩撤回了），所以改成：**按下期间不展开块公式**。

## 四 ③ 顺带修好的一条：面板不许顶着工具栏

给"避开预渲染框"那条规则加约束时，实测发现面板在"上方有空间、但空间被工具栏占着"的几何下会顶到屏幕最上面（横跨工具栏）。现在**工具栏下沿当天花板**：可用空间从它算起、落位也 clamp 到它下面，面板在这一侧变矮（可滚动）而不是顶上去。场景 86 因此断到 10/10（新增一条"面板也没有顶着工具栏"），既有 `desktop-completion` 套件全绿。
