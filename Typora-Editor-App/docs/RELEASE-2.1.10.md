## 1. 为什么 2.1.9 还是不行

上一版把"按下落在公式上"这条路修通了，但**反方向**的拖拽还有一层没拆掉：

- Chromium 的拖拽扩选交给 `SelectionController`，横向拖拽在"按下点在公式渲染结果里"时会给出
  空选区；我加了一层兜底（原生没做出来就自己按"按下点 + 最后落点"建选区），但兜底里用
  `Range.setStart/setEnd` 拼范围——**规范规定：终点在起点之前时，setEnd 会把整段收塌**。
  于是"从段尾往回拉"（起点在后、终点在前）永远被判成空选区，兜底等于没生效。
  改成 `selection.setBaseAndExtent(...)`（Selection API 自己处理方向）之后方向不再是问题。
- 你的第二条线索也解释得通：末尾补一个空行，落点就从"公式渲染结果"变成"段落空白"，
  原生拖拽那条路本来就能走通——所以看着像"文件末尾行的毛病"，其实是"落点压在公式上"。

## 2. 这一版改了什么

| 文件 | 改动 |
| --- | --- |
| `js/math-select-reveal.js` | 兜底选区改用 `setBaseAndExtent`（方向由 Selection 处理）；锚点在"按下于公式"时映射到源码对应字符，"按下于正文"时用落点解析（落进渲染结果则吸到该公式源码）；原生拖拽若被"关在这条公式内部"（按下在公式上、指针已走远、整条选区还在同一条公式里）也改用我们自己的选区 |
| `index.css` | **行内公式的渲染结果改为可选中**（`user-select:text`）——这是"按下能不能起选区"的前提：命中测试发生在监听器之前，落点若还是 `user-select:none`，Chromium 压根不把这次按下当成可以起选区。只发行内；块公式（`$$…$$`）的点击/退格语义仍走 Vditor 的 rawblock 路径，未改动 |
| `js/math-source-map.js` | 折叠公式按下不再 `preventDefault`；单击公式仍由 `click` 映射到源码（编辑器路径不回退） |

1. 鼠标点到**这一段最后一行**（"原命题的否定: …"）的末尾 → **按住往左上方拖**到本段第一个词
