## 一 ① 是真缺陷：清空整篇后光标落在公式源码里，接着打字变成公式

2.1.4 只观测到"剩一个空 `$$` 壳"，就把它归成"Vditor 删块的归一化 + 没有可靠判据"而没改。**这个处置错在两处**：一是没测"接着打字会怎样"，二是"没有可靠判据"这个判断本身不成立（判据是有的：**整篇被选中**这个前提）。

**现象（安装版 2.1.4、真按键）**：`Ctrl+A`（实测选区 221 字符、非折叠）→ 一次退格 → `value = "$$\n\n\n$$\n"`，光标 `inMathCode: true`、owner 已展开 → 接着打 `abc` → **`value = "$$\nabc\n$$"`**：字进了 TeX，屏幕上是渲染出来的公式，不是正文。

**四条归因实验**（探针 `scripts/acceptance/probe-empty-math-and-marker.cjs`，只观测，每步截图）：

1. **只选中最后一条块公式再退格** → 删 15 字符、其余 196 字符原样留着；全选那一下是 221 → 8。→ 我们的删除路径只摘一条节点，整篇不是我们删的。
2. **`execCommand('delete')`** → 事件流里**连 `beforeinput` 都没有**（只有一条 `input`），照样同一个壳 + 光标在源码里。→ 不是我们的键处理干的。
3. **换成"最后一块是围栏代码块"** → 清空后只剩空段落（`blocks: []`、`value: "\n"`），打字进正文。→ 公式特有的形状，不是通用删块。
4. **WYSIWYG 模式**（工具栏下拉切换，真实鼠标点击）→ 留下 `$$\na0+b0=1\n$$\n`、光标在编辑面（`inMathCode: false`）。→ 那一侧没有这个形状，一行没动。

**修法**：只在"整篇被选中"前提下、且删完只剩一个**空的块公式**时，把壳换成空段落（复用 `removeNode`）。"整篇被选中"由结构判据给出（选区端点落在首/末块内部，或直接落在编辑面元素上 offset 0/子节点数两种情况都认）。因此 `$$` 回车新建的空公式块不受影响。

**改后实测（开发树）**：`value: "\n"`、光标在空段落（`inMathCode: false`）、打字 → `"abc\n"`；**清空后一次 `Ctrl+Z` 逐字节回原文**（历史粒度专钉）；只选一条公式再退格仍是"15 字符 / 其余原样"。

## 二 ② 不是产品缺陷，是我自己的读数假阳性

2.1.4 那条"1/8 步光标落在标题 `##` 标记里、0 绘制矩形"两处都不成立：

- 那一步 `range.startContainer` 是 `<h2>` **元素**本身、`offset=2`，而该 `<h2>` 只有 2 个子节点 → 这是"**子节点边界**"，不是"字符偏移 2"；
- Blink 对"容器是元素、位置在子节点边界"的折叠 Range **一律给 0 个绘制矩形**：实测 `(h2,0)`、`(h2,1)`、`(h2,2)` 读数全是 0；而第 7 步落在同一个 `H2@2`（容器是文本节点）却报 1 —— 差异来自"容器是元素还是文本节点"，不是光标位置变了；
- **放大截图（6 倍，`caret-09b.png`）证实那一帧光标是画出来的**：`## 紧跟块公式的标题` 之后那根竖线。

**改法在测试侧**：`READ` 增 `caretStartKind`；场景 75 把"元素边界"单独归类、日志写"读数不适用"，并把"折叠 Range 在标题各子节点边界上全是 0"采成**证人**（`rectsAtBoundary`），免得下一轮再把它读成缺陷。公式那条不变量（不許停在**不可见的公式源码**里）判据不变。

## 四 这一版为什么不改别的东西

- **没有顺手"归一化所有空 `$$` 对"**：只认"整篇被选中 + 只剩这一个空块公式"。没有这个前提，空 `$$` 是**正常编辑状态**（`$$` 回车新建就是这个形状，实测 `mathCode: ["\n\n"]`、光标在源码里，用户正要开始写公式），一刀切会打坏它。
