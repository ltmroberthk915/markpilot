# v2.0.1 交付 Session 踩坑全记录（按流程顺序）

> 范围：本 session 从受理两个用户缺陷报告（补全弹窗卡工具栏、IDE 大纲在 Trae 不渲染且验收误报）起，经修复迭代、验收门升级、版本规范、全量验收、打包交付，到会话崩溃恢复并完成交付为止。每条按「现象 → 根因 → 对策/沉淀规则」记录。

---

## 一、问题受理与定位阶段

### 1. 大纲功能验收误报（最严重的坑）
- **现象**：用户截图证明 Trae 里大纲面板根本没生成，而此前验收结论是"成功"。
- **根因**：冒烟断言只走命令/状态桥（executeCommand + webview 状态查询），从头到尾没有断言真实 workbench DOM——命令能执行 ≠ 面板真的渲染了。
- **对策**：验收门升级为「真实 DOM 断言 + 真实输入事件」：直接断言侧栏 `.monaco-list-row` 的真实行文本，再对行的真实坐标派发 CDP 鼠标点击并断言 webview 收到 reveal。
- **沉淀**：*任何 UI 验收，断言必须触达用户眼睛能看到的那层 DOM；只验证内部命令通路的验收不算验收。*

### 2. Trae 不渲染挂在内置 explorer 容器的树视图
- **现象**：同一份 VSIX，VS Code 里大纲出现，Trae 里完全没有。
- **根因**：Trae（字节 VS Code 分叉）不渲染 `views.explorer` 下的树视图贡献——分叉行为差异，无任何报错。
- **对策**：改为自定义活动栏容器 `viewsContainers.activitybar`（`marcopilot-outline`）+ 容器内树视图，两个 IDE 均正常。
- **沉淀**：*分叉 IDE 的兼容性必须用目标 IDE 本体验证，不能拿 VS Code 行为外推。*

### 3. 清单键名拼写静默失败
- **现象**：第一次改容器时写成 `viewContainers`，VS Code 静默回退到 Explorer（只在扩展宿主日志里有警告），差点再次误判。
- **根因**：正确键名是 `viewsContainers`（带 s）；错拼不报错、直接忽略。
- **沉淀**：*清单/配置里"拼错不报错"的字段，验收时必须断言其效果落在预期容器，而不是落在兜底位置。*

### 4. 弹窗卡工具栏的根因定位
- **现象**：补全锚点光标滚到可视区上方时弹窗停在工具栏，滚到下方反而正常。
- **根因**：v10 `position()` 的顶部钳位 `Math.max(8,…)` 只防"太靠上"，没有区分"光标已离屏"与"光标在视口内但靠上"。
- **对策**：离屏（上/下对称）时弹窗随光标离开屏幕；在视口内时保留 v10 翻转语义；工具栏 z-index 提到 1001 做硬防线。

### 5. 滚动容器认知错误（桌面测试侧）
- **现象**：CDP wheel 事件滚不动编辑器；`document.querySelector('.vditor-reset')` 拿到的元素 scrollTop 永远是 0。
- **根因**：DOM 里有多个 `.vditor-reset`（隐藏的 wysiwyg/sv 副本），querySelector 命中隐藏副本；IR 模式根 `editor.ir.element` 本身就是 `pre.vditor-reset`——它既是滚动器又是 contenteditable，`.vditor-ir` 下没有 `.vditor-reset` 后代。
- **对策**：`setScroll` 改为"模式根优先"选择，并**断言 scrollTop 真的变化**（st===1200）后才继续用例。
- **沉淀**：*驱动 UI 的测试步骤必须自证生效（动作后断言状态真的变了），否则后续断言全是在验证噪声。*

## 二、修复方案迭代阶段

### 6. 三个"更彻底"的重写方案全部打破嵌套公式测试
- **现象**：画布∩视口全面夹取、rAF 合帧滚动重定位、"视口内钉住不跟随"三个方案，各自让嵌套公式套件失败。
- **根因**：360px 高的弹窗在滚动后于新位置展开，盖住了公式 1 的点击点 (576,411)，弹窗内按钮把点击吞掉（诊断证据：`popupAtClick` 矩形覆盖点击点、`popupAfter:null`）。几何/时机一变，就撞上这类用例。
- **对策**：二分法（2.0.1 + v10 completion.js）先证明 completion.js 因果，再收敛为最小语义改动：历史翻转语义逐字节保留 + 画布夹取只做硬边界 + 离屏随行 + CSS 工具栏压层。嵌套公式/表格套件全绿后交付。
- **沉淀**：*改动敏感区域时，"最小 diff + 一层硬保险（z-index）"比"重写得更漂亮"更容易通过全量回归。*

### 7. webview 内 console.log 打不到扩展日志
- **现象**：想在 webview 里插桩看 position() 的实时值，日志完全不可见。
- **根因**：webview 的 console 不进扩展宿主输出通道。
- **对策**：改为测试侧插桩——`nestedPoint` 返回点击瞬间的弹窗矩形（`popupAtClick`），配合逐步 `console.log` 模式/索引/坐标，一次跑完拿到因果链。

### 8. 用户架构建议的落地翻译
- **现象**：用户建议"弹窗放文本同图层、工具栏放上一图层"——字面执行做不到。
- **根因**：滚动器就是 contenteditable 本身（`pre.vditor-reset`），把弹窗节点插进文本层会进 Vditor 的 DOM→Markdown 序列化，内容必损坏。
- **对策**：翻译为语义等价方案：弹窗仍 fixed 定位但严格夹在画布内 + 离屏随行；"工具栏上一图层"用 z-index 1001 > 1000 实现。
- **沉淀**：*用户的架构直觉往往指向真问题（分层），落地时要找宿主框架约束下的等价实现，而不是字面照搬或直接说"做不到"。*

## 三、验收测试编写阶段

### 9. 大纲树行的"单击/双击"语义
- **现象**：单击行只产生选中态（aria-selected:true），reveal 不触发；普通两次 clickPair 也不生效。
- **根因**：树条目命令绑定在激活（open/双击）上；CDP 合成双击必须在第二对 mousePressed/Released 上带 `clickCount:2`。
- **对策**：按 `mouseMoved → click(1) → click(2 with clickCount:2)` 序列派发，成功触发命令。

### 10. CDP 调试上下文掩蔽（假阴性陷阱）
- **现象**：扩展侧命令日志明明打了 `[reveal-cmd]`，测试读 webview 的 `__outlineReveal` 却一直是 null。
- **根因**：`inWebviewTagged` 辅助函数返回"第一个不抛异常的上下文"——那是旁观上下文，它当然没有标记；真正的编辑器 webview 被掩蔽。
- **对策**：`anyReveal()` 扫描**全部**调试上下文取 `max(at)` 作为基线，判定只认"时间戳增长"。
- **沉淀**：*多上下文调试里"取第一个成功"的辅助函数是经典坑，应遍历全部候选并断言来源。*

### 11. 产品侧 reveal 守卫被防抖刷新打破
- **现象**：偶发点击无效。根因是守卫用对象同一性 `flat[node.index] === node`，而 250ms 防抖刷新会在渲染与点击之间替换节点对象。
- **对策**：放宽为语义匹配（文档行 + 文本），保持防抖语义不变。

## 四、版本管理与打包阶段

### 12. 版本号无递增、多处漂移
- **现象**：用户指出版本管理混乱。
- **对策**：确立"第三位递增"政策（本轮 2.0.1，后续 2.0.2…）；版本号贯穿 package.json（两仓）、VSIX 清单、产物文件名、dist 目录、验收断言。
- **沉淀**：*verify 脚本从 package.json 动态读版本，任何硬编码版本号的断言迟早咬人（本轮就实际发生了：硬编码 2.0.0 直接断言失败）。*

### 13. VSIX 清单与字节级一致性
- **现象**：`<Identity Version>` 手工同步会漏；写回后 CRLF→LF 改变字节，VSIX 内字节与清单文件对不上。
- **对策**：pack.py 自动同步版本并以 `newline=""` 写回保持 CRLF；verify 用「桌面源码 = app.asar = VSIX」三方逐文件哈希断言。

### 14. Trae 命令行装扩展会转发给真实实例
- **现象/风险**：`Trae.exe --install-extension` 在 Trae 运行中会转发给用户正在用的实例——等于动用户环境。
- **对策**：永不使用；测试用 `--extensionDevelopmentPath` + 隔离 profile 副本；交付时指导用户从命令面板"从 VSIX 安装"。

## 五、全量验收执行阶段

### 15. 并行负载毁掉 GUI 验收
- **现象**：GUI 驱动跑着的同时并行跑后台 Node 套件，出现 CDP 打字丢字（`null !== '事件🙂集合'`）。
- **根因**：CPU 争抢使合成输入时序漂移。
- **对策**：串行复跑即过；确立"GUI 验收期间零并行负载"铁律（含本次崩溃恢复后的复核，也是先跑完所有无 GUI 校验再碰窗口）。

### 16. 三类已知抖动，复跑即过但必须披露
- profile UI 2.5s 等待超时（时序敏感）；Trae 遥测噪声（volo/icube 超时日志）叠加一次 `visible:[]`；workflow-gaps 的 SV undo 时序（历史已知）。
- **沉淀**：*抖动类失败"复跑通过"可接受，但必须写进报告披露，不能静默吞掉。*

### 17. 孤立测试实例留在用户屏幕上引起误会
- **现象**：用户看到屏幕上出现大纲面板，以为是新功能已就绪——其实是我遗留的测试实例窗口。
- **对策**：澄清来源；用完的测试实例及时关闭（本轮收尾即以 CloseMainWindow 干净退出，无强杀）。

## 六、会话崩溃与恢复阶段

### 18. 远程图片分析链路是单点故障（直接导致崩溃）
- **现象**：截图分析依赖"上传 CDN → 远程模型读 URL"两跳。路径带反斜杠被拼坏时返回 400「图片输入格式/解析错误」；最终一次 DNS 解析失败（temporary DNS server 8.8.8.8 exceeded retries）把整个会话卡死崩溃。
- **对策**：崩溃后不再依赖远程分析：curl 直接下载截图到本地（CDN 当时可达，说明只是 DNS 瞬态）；OCR/UIA/像素分析走全本地路径。
- **沉淀**：*图像验证先备好本地退路（下载/OCR/像素统计），远程分析当加速器而不是必经之路。*

### 19. 恢复时不信叙述、只信哈希
- **现象**：恢复后读盘发现 completion.js 的"最终版本"与会话摘要的描述不一致（摘要说最小 diff，磁盘是混合版）。
- **根因**：叙述性总结天然滞后于最后几次编辑。
- **对策**：以字节为准——extension-src、App 仓源码、VSIX 提取物三处哈希完全一致（`5093e9a2…`），再由 verify 脚本把 app.asar 拉进三方断言，闭环确认"源码=产物=被验收的版本"。
- **沉淀**：*崩溃/交接恢复的第一件事是重建"源码↔产物↔已跑验收"的哈希链，而不是继续做摘要里说的下一步。*

### 20. 本环境的"本地看图"并不存在
- **现象**：以为用 Read 打开本地截图就能亲眼看像素——结果图片同样被上传 CDN 只回 URL。
- **对策**：接受现实，改走程序化本地方案；顺带发现网络恢复后 analyze_image 可用（用于判断截屏内容，不再用于坐标）。

### 21. Windows 本地 OCR/UIA 的连环坑
- PowerShell 调 WinRT OCR：`[Windows.Storage.StorageFile]::GetFileAsync` 报 MethodNotFound（WinRT 静态方法投影失败）；改走 `IStorageFileStatics` 接口类型又"找不到类型"——Windows PowerShell 5.1 的 WinRT 静态成员这条路在本机不通。
- UIAutomation 遍历 Trae 窗口：Chromium 无障碍未开启，树近乎全空。
- 尝试 `SPI_SETSCREENREADER` 唤醒 Chromium 无障碍：无效；**系统级标志用完必须恢复**（已当场恢复为 off）。
- **沉淀**：*改系统全局状态（SPI 标志等）必须成对出现"设置→恢复"，且恢复失败要有兜底记录。*

### 22. Git Bash ↔ PowerShell 引用坑（再次踩中）
- PowerShell 单行命令里的 `$_` 被 Git Bash 展开，必须写 `\$_`；本轮多处命令因此需转义重试。
- `/tmp` 路径是 MSYS 虚拟路径，交给 Windows 程序（OCR、Read）前要 `cygpath -w` 换成真实路径。

### 23. 脚本默认参数指向旧版本
- **现象**：恢复后复跑 verify，只传了 release 目录，第三参默认指向 `marcopilot-1.0.0.vsix`，断言 `'1.0.0' !== '2.0.1'` 失败。
- **对策**：显式传全三参（release 目录、VSIX、输出目录）复跑通过。
- **沉淀**：*带版本号默认值的脚本，调用时永远显式传参；或把默认值改成从 package.json 推导。*

### 24. 证据文件的路径与 schema 要先摸清
- live-AI 结果在 `.perf/release100-live-ai-201/`（不是无后缀目录）；后台套件 results.json 没有 pass/total 汇总字段，判定要看 `testExitCode` 和 `tests[].path/sha256`。
- `node -e` 直接 require 一个含 GBK 错误文本的"json"只会报 SyntaxError——先看原始文件内容再解析。

### 25. 截屏捕获到用户前台（隐私 + 安全 + 打扰三重坑）
- **现象**：为做最终手动抽查截屏，发现前台是用户正在使用的窗口——测试 Trae 窗口被完全盖住。
- **风险**：此刻继续按坐标点击会打中用户窗口；截图本身含用户隐私内容。
- **对策**：立即中止手动抽查（CDP 真实 DOM+真实输入验收已覆盖同等路径，用户本人也确认过功能），删除含用户桌面的截图，优雅关闭测试实例，并在报告里如实披露"手动抽查未执行及原因"。
- **沉淀**：*GUI 自动化动手前先确认前台归属；用户正在用机器时，宁可少一步人工复验，不抢用户的前台。截到用户内容的图一律即删、不入档。*

## 沉淀为长期规则（本 session 教训浓缩）

1. **验收断言必须触达真实渲染 DOM 与真实输入事件**；只验证命令通路的验收是误报之源。
2. **分叉 IDE（Trae vs VS Code）差异必须用目标 IDE 实测**；清单键名等"静默失败"点要有显式效果断言。
3. **测试动作要自证生效**（滚动后断言 scrollTop 变了），否则后续断言全是噪声。
4. **敏感区域改动优先最小 diff + 一层硬保险**；每轮必须过全量回归（嵌套公式是弹窗几何的守门用例）。
5. **GUI 验收零并行负载**；抖动复跑通过可接受，但必须披露。
6. **崩溃/交接恢复先重建哈希链**（源码=产物=已验收版本），叙述摘要只当线索。
7. **图像验证备好本地退路**（下载/OCR/像素分析），远程分析是瞬态故障单点。
8. **改系统全局状态必须成对恢复**；测试实例用完即关，不留窗口在用户屏幕上。
9. **版本号单一来源**（package.json），脚本动态读取，调用显式传参。
10. **用户前台被占用时中止 GUI 自动化**；截到用户内容的图即删；密钥只走环境变量、产物零泄漏自检。
