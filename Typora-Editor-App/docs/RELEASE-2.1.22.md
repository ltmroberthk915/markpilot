# MarkPilot 2.1.22 发布说明（私版）

你把两个问题一起报来了：① 上一版刚接上的行内公式浮框"点一下闪一下"；② 源码跨行时浮框被挤到右边。
两个都复现到了、都量出了根因，也都修了。你点的方向是对的——① 和第 12 轮块公式那次**是同一类问题**。

## 一 ① 点一下闪一下：按下期间正在编辑的那条公式被"从视觉上"折了起来

取证脚本 `scripts/acceptance/probe-inline-wrap-and-press.cjs`（新）。它逐帧记录的不是 `--expand` 类，
而是**真正决定画面的 computed style**——这次闪烁恰恰是"类一次都没变、画面变了"：

```
按住 250ms（43 帧）：
  foldedFrames     0      ← --expand 一次都没被摘
  KaTeX 重建       0      ← 预渲染子树逐字节不变
  srcHiddenFrames 16      ← 但源码 display:none 的有 16 帧
  boxStaticFrames 16      ← 浮框 position:static（摊回行内）的也是那 16 帧
  caretInCode     43      ← 光标一直在源码里（上一版那条修好着）
```

真凶是 v2.1.11 那组 CSS（第 7 轮治拖拽抖动用的）：`.typora-ir-pointer` 存在期间，所有**展开态的
行内节点**被"只从视觉上"压回渲染态——源码藏起来、浮框摊回行内、`position` 归位。拖拽**经过**别的
公式时这是对的；可用户主动**按住的那一条**不是"经过"，它正是正在编辑的那条：

```
按下 → 源码消失、浮框摊平、段落重排（后面的文字整体左移）
松开 → 全部弹回来
```

**一次点击 = 闪一下**，而且只会发生在"已经展开的那条公式上"——正是上一版把"点浮框＝落光标"
接上之后用户开始大量点击的那个位置。

## 二 ② 浮框被挤到右边：落位基准取了"第一个行盒片段"

同一支探针量了两套几何（跨行的公式，owner 的行盒被折成两个片段）：

| 基准候选 | 左边界 |
| --- | --- |
| owner 的**第一个行盒片段** | **591** ← 浮框实际就落在这里（上一行行尾那个 `$`） |
| owner 的联合盒子 | 28 |
| **源码 code** | **28** ← 应有的位置 |

行内公式的源码太长、一行装不下时，源码折到下一行，而绝对定位的包含块是最近的定位祖先（owner，
`position: relative`）——对**跨行**的行内包含块，Chromium 用的是它**第一个片段**的盒子：也就是
上一行行尾那个 `$`。于是浮框跑到右边、还挂在上一行下面（你截图里 `f^*\in[f^{\inf},f^{\sup}]` 的形状）。

## 三 修法

**① 冻结"按下那一刻已经展开的那条"**（与第 12 轮块公式同一条思路）：

- `render/js/math-select-reveal.js`：按下时，若落点所在的节点**已经展开**（源码或它的浮框上都算），
  给它挂 `.typora-ir-pressed`；松手 / 按键介入 / 失焦时摘掉（跟 `.typora-ir-pointer` 同生命周期）。
- `render/index.css`：那组"按下期间压回渲染态"的规则全部加 `:not(.typora-ir-pressed)`。
- 折叠态的公式按下去**照旧**被压住（第 7 轮的拖拽手感一字未动）——只放行"按下时已经展开"的那条。

**② 浮框的落位基准换成源码**（CSS 锚点定位，Chromium 125+，本应用 Electron 44 支持）：

```css
.vditor-ir .vditor-ir__node--expand[data-type="inline-node"] > code[data-type="math-inline"] {
  anchor-name: --typora-math-source;
}
.vditor-ir .vditor-ir__node--expand[data-type="inline-node"] > .vditor-ir__preview {
  top: 100%; left: 0;                                        /* 不支持锚点定位时的回退（单片段本来就对） */
  position-anchor: --typora-math-source;
  top: anchor(--typora-math-source bottom);                  /* 改用源码的下沿 */
  left: anchor(--typora-math-source left);                   /* 改用源码的左边界 */
}
```

源码在展开态是 `inline-block`，**永远只有一个片段**，所以锚点没有歧义；不写一行 JS、不强制重排、
打字换行时也自动跟着走。不支持锚点定位的构建会忽略这两条声明，退回原来的 `left:0 / top:100%`。

## 四 回归门（场景 92 从 34 条扩到 44 条）

新增两组（都在 `scripts/acceptance/scenarios/92-inline-preview-box-click-caret-2.1.21.cjs`）：

- **G 组（跨行落位）**：前提自证（owner 片段数 > 1），然后断言浮框左边界贴着**源码**左边界（±2px）、
  浮框挂在**源码**下沿 +4px；证人里同时留了"首片段左边界"以便一眼看出修前的落点。
- **H 组（按下不折）**：在浮框里、在源码上各按住 250ms，逐帧断言**源码被藏起来的帧 = 0、
  浮框被摊回行内的帧 = 0、非展开帧 = 0**，并记录帧内 computed style 的取值集合（恒为
  `inline-block` / `absolute`）；自证至少采到 8 帧。

A/B（只改构建产物，源码不动）：

| A/B | 结果 |
| --- | --- |
| 不挂 `.typora-ir-pressed` | **44/44 帧**源码被藏、**44/44 帧**浮框被摊回行内（H1 红），H2 前提也被带红 |
| 去掉两条 `anchor()` 声明 | 浮框 left = **591**（首片段）而源码 left = **28**（G 组两条红） |
| 两处都恢复 | 44/44 断言通过 |

## 七 请你手验

1. 点开一条行内公式（浮框浮出来），在**浮框里连点几下**、再在**源码上连点几下**——不应该再有闪动
   （源码不消失、浮框不摊平、后面文字不位移）；
2. 找一条**长到会折行**的行内公式（比如你截图里那条 `f^*\in[f^{\inf},f^{\sup}]` 那种位置）——
   浮框应贴在这条源码自己的左边界、挂在源码下方，而不是跑到上一行行尾；
3. 顺手确认拖拽选中经过公式的手感没变（那是第 7 轮的效果，这次特意没碰）。
