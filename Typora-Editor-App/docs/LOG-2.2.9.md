# LOG-2.2.9：合成光标的"幽灵线"（点空白区出现两个光标）+ doc B 横向"跳过标题行"

两条都是用户可见的光标问题。第一条是**我们自己画的合成光标**画错地方且不收；第二条是**我们自己的
←/→ 事后校正**把光标跳过了整整一行标题。另外把遗留 #3（跨块 shift+→ 偶发重置）追到了机制层，如实记录。

## 一 点空白区出现两个光标：合成线按"跨行并集盒"定位 + DOM 变了不重算

**用户截图现象**：点块公式那一行右下方一点（先按过 Enter 建了下一行）→ 正文里出现**两根竖线**。

**定性**（`scripts/acceptance/probe-repro-twocaret*.cjs` 系列）：两根线不是一类东西。原图逐像素扫描：

```
x=23..25  y=93..129  颜色 (212,212,212)  ← #d4d4d4，正是我们合成线的默认色；2px 宽（CSS 2px）
x=60      y=280..309 颜色 (46,66,101)    ← 1px 宽、偏蓝 = 浏览器原生 caret
```

⇒ 上面那根是**我们的合成光标**，它没被收掉/画错了地方；下面那根是原生 caret。

**根因 1：合成线只在"选区变化"时重算。** Vditor 每次输入都会重渲染块——选区没动、几何全变，
我们的线就按**旧几何**留在原地。A/B（同一串手势，`probe-repro-twocaret-fixed.cjs`）：

```
旧版（已安装 2.2.8）：点完 0.7s 线=[88,452] ，3s 后仍然 线=[88,452]   ← 一直留着
修复版（dev）      ：点完 0.7s 线=null      ，3s 后     线=null        ← 已收起
```

截图对照：`.perf/repro-twocaret-fixed/other/①段落末行右侧-3秒后.png`（"整数解"后面挂着灰线）
vs `.perf/repro-twocaret-fixed/dev/①段落末行右侧-3秒后.png`（干净）。

**根因 2：几何用"前/后**兄弟元素**的矩形"定位，三个洞**（都有实测读数）：

| 洞 | 实测 |
| --- | --- |
| 行内公式是**跨行元素**，`getBoundingClientRect()` 是**多行并集** | 那条折行公式 = `{x:46,y:432,w:837,h:41}`，它的 `right/top` 属于**上一行** → 竖线画到上一行行尾（探针读数 `位=[882,432,25]`，光标其实在下一行） |
| `closest('pre')` 从块公式里往上爬会匹配到**编辑面根** `PRE.vditor-reset` | 块框 = `{0,0,922,713}`＝整面 → 竖线出现在面的右缘（点块公式下方空白带时读数 `位=[883,520,25]`） |
| 零宽哨兵文本节点自己没矩形 | 退化成"兄弟盒 + 整行行高"的长竖线 |

**改法**：

1. 几何改成**区间行盒**：光标之前的内容（块首 → 光标）取最后一个 `height > 0` 的矩形、之后的内容取第一个；
   两者都必须落在**块框**里才算数（折叠态公式源码那种"宽 0、高 999"的容器会被这条挡掉）；
   块里一条内容都没有（空段落、整块只有公式）才用块框内缘兜底。跨行公式自动按行算，不用管它内部是什么节点。
2. 偏移先**夹到容器合法范围**：Vditor 重渲染后选区里的偏移可能是旧的（实测 `P@11` 而 `P` 只有 9 个子节点），
   照原样丢给 `Range` 会抛 `IndexSizeError`；浏览器自己画 caret 时也是夹过的。
3. 加 `MutationObserver`（rAF 合并）+ `input`：DOM 一变就重算——几何变了、或原生能画了就立刻收线。
4. `window.__caretProxyLog`（环形缓冲，最近 20 条）常驻：记"谁画的、按什么几何画的、为什么收起"，
   下次这类报告直接取证。

**修完读数**（dev）：

```
点段落末行右侧  → 线=null（原生 caret 能画出来，我们不该插一脚）
点块公式下空白带 → 线只在预览行出现 70ms（[784,559,2,20]，那是光标真所在的行），随后自动收起
块公式源码行底   → 线=null（光标在隐藏源码里，块框 0×0 → 不画）
```

## 二 doc B 横向"→ 跳过标题行"：是**我们自己的校正**跳的，不是 Chromium

**取证**：`node scripts/acceptance/probe-real-ops.cjs --app=dev --doc=b --section=horizontal --rounds=8 --presses=6 --trace`，
H4 失败样例：上一行 y=298（段落）→ 现在 y=386（下一段），**中间夹着 y=348 的 `### 1.3.3 Def 勒贝格积分`**。
`--trace` 的选区写入口把改写者连栈打了出来：

```
{"m":"removeAllRanges","stack":"… 落 (typora-patches.js:1445) | 邻行 (typora-patches.js:1491)"}
{"m":"addRange",       "stack":"… 落 (typora-patches.js:1445) | 邻行 (typora-patches.js:1491)"}
```

⇒ 是 `patchHomeEndCaret` 里那条 **`校正横向`**（←/→ 的事后校正）干的：它的触发条件包含"落在**非公式**标记里"
（`###` 这类），而兜底 `邻行()` 找不到同行落点时会**往下逐 6px 找**——标题行上正好找不到，于是把光标
从上一段末尾跳过了整行标题。

**改法**：`校正横向` 只纠"落在**预览浮层**里"这一种（预览是隐藏内容，落进去光标看不见）；
同行找不到可用落点就**什么都不做**（绝不跨行兜底）。理由：对 ←/→ 来说标题标记 `###` 是**合法落点**
（"围栏当普通字符"契约，与 `$` 同类），本就不该纠；隐形位置更不碰（场景 101 钉着的公式源码落点）。

**修完**（dev，doc B）：H1 72/72、H2 72/72、**H3 6/6**、**H4 6/6**（此前 H3/H4 各一处红）。
doc A 复核：H1 96/96、H2 96/96、H3 8/8、H4 8/8、F 1/1。

## 三 遗留 #3（跨块 shift+→ 偶发重置）：追到机制，**没修**，如实记

**新增长跑**：`probe-real-ops --doc=b --section=select --rounds=20 --presses=10 --trace`（20 轮 × 20 键）。

- 30 键连走（`probe-repro-selreset.cjs`）：长度 1→29 单调增长、回程单调收缩，**不复现**。
- 20 轮里稳定出现**同 4 处** S2 红，全部在**收缩相位反而变长**（轮 18 步 5/6/8/9，长度 3→6）：
  即向左收缩时高亮**反向增长** = 选区的锚点/焦点被翻转。
- **这一拍没有任何 JS 写入**（`--trace` 时间线为空、acts 为空）⇒ 不是我们、也不是 Vditor 的 JS，
  而是原生选区在**公式密集的行边界**上重新锚定。
- **A/B**：把同一轮同种子跑在**已安装的 2.2.8** 上 → 同样 4 处、同样轮次、同样步号，逐字相同 ⇒ **既有行为**，
  与本次改动无关；F（文档未被子测试改写）为绿 ⇒ 不损坏文档。
- 结论：要"修"就得接管 Chromium 的原生选区模型（风险远大于收益），**本轮不动**。埋点（`--trace`）常驻，
  S2 失败现在会连**端点坐标 + 写入口栈**一起记下来，下次有更明确的用户现场可直接复跑。
