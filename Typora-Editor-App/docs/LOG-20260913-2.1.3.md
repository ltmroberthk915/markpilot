## 一、取证：三个真实机制，都在**已安装的 2.1.2** 上量到

### 1.1 `(2)` "之前"那一下，光标其实落在**隐藏的公式源码**里

`probe-math-user6/7/8`（真鼠标点击 + 真键盘 + 逐字节前后对比）。素材里 `blockquote` 的结构：

```
blockquote A: p(受限量词…) / p(1) / div[math-block](¬∃x∈A…) / p(2) / div[math-block](¬∀x∈A…)
                  ↑ 两处 `<=>` 由 blockquote 的 padding 表现，DOM 里没有"空行"节点
```

在 `(2)` 上方那片留白（块公式的**下内边距**）点击，Chromium 解析出的光标容器随横向位置变化：

| 点击位置 | 2.1.2 落到的容器 | 一次退格之后 |
|---|---|---|
| 留白中间 | `TEXT"\neg\,\exist"@0`（源码开头） | 文档不变（2.1.2 的源码 0 处拦截起了作用） |
| 留白靠左 | `TEXT"\neg\,\exist"@70`（源码末尾） | **`x+y=1` → `x+y=`：删掉公式里一个字符** |
| 更靠外 | `pre@27`（渲染**预览**子树里的元素级位置） | 文档结构被改（`(2)` 那一行被并掉/前缀被削） |

几何原因（`probe-math-user9` 量的）：折叠态下块公式的源码 `pre` 是 `display:inline-block; height:0; width:0` 的壳，里头的 `code` 是 9px 宽、1228px 高的竖条——它**在布局树里**，所以 Chromium 会把落在这一带的点击翻译成源码文本里的位置；而屏幕上是看不见的。

### 1.2 跨 blockquote 的段落贴边没有保护

素材另一处 `(2)`（证明段的第一条）上一行是**不带 `>` 的空行**，于是它与上一条公式分处两个 blockquote。`probe-math-user7` 的转储：

```
[2] (2) tag=P prev=null parentPrev=blockquote="$$\neg\,\exists x\" parent=blockquote="(2)$$\neg\,\forall"
```

`prev=null` —— `(2)` 是它所在 blockquote 的第一个子节点，2.1.2 的段落贴边只看**同级兄弟**，于是 no-op 放行；Vditor 接手后把整段引用块的 `>` 前缀削掉。产物级复现（场景 74）：`> (2)` → `(2)`、`> 证:` → `> 证:(1)`。

### 1.3 点 `$$` 被塞进源码里（所见非所得）

2.1.2 的约定是"点前 `$$` = 源码开头，点后 `$$` = 源码末尾"。用户要的是**光标站在 `$$` 上**；而且这个落点紧接着按退格就是删源码——正好又是同一句抱怨。

### 1.4 用户要的"删掉一个 `$`"能不能做（三条实测，`probe-math-user9/10/11`）

1. **围栏不是文档里的字符**：把块公式的 open/close 围栏 span 文本从 `$$` 改成 `$` 或 `$$$$`，`getValue()` **逐字节不变**（`probe-math-user9`）。
2. **真去改 markdown 会毁邻居**：用 `setValue` 把闭合围栏写成单个 `$` 之后，Lute **重新配对围栏**——`code.textContent` 末尾出现 `\n$\n\n(2)`，也就是**紧随其后的 `> (2)` 那一行被吞进公式源码**；开场围栏少一个 `$` 则把**下一条公式的开场 `$$` 拉上来**当自己的闭合围栏（`probe-math-user11`）。
3. **改 markdown 只能整篇重排**：2 万字素材 `setValue` **24ms**；49 万字（348K 字符 / 5634 条公式）**2.0–2.2s**，且前后**不是逐字节相同**（`sameAfter:false`，Lute 顺带规范化别处内容）（`probe-math-user10`）。

结论：**不能给"删一个 `$`"**。本版改成：围栏成为真实可站位置 + 围栏上退格不改文档 + 当场说明原因与正路。

## 二、改了什么（源码唯一真相：`Typora-Editor/extension-src/render/js/math-edit.js`，只改了这一个文件）

与 2.1.2 的渲染层逐文件 diff：**只有 `math-edit.js` 不同**（`diff -rq app/renderer .perf/renderer-2.1.2`）。

1. `markerEdge(node, owner)`：围栏标记（块 `$$` / 行内 `$`）上的位置按 **owner 是否展开**区分——展开态返回新的 `layer:'fence'`（真实可站位置），折叠态仍是 `'outer'`（零宽标记，挪出去）。文本级与元素级光标都走这一支。
2. `formulaEdge` 新增"元素级位置落在 owner 里但不是源码里"的归类：预览子树 → `layer:'preview'`（拦删除、**不挪光标**，因为 WYSIWYG 靠这个状态显示源码）；其余 → `'outer'`。
3. `fenceClick`（mousedown 捕获）按几何落点：点渲染结果 → 放过（Vditor 展开并进源码）；点围栏（展开态）→ 光标按横向比例落进 `$$` 文本；点折叠态的留白 → 光标落到公式块**之前/之后**（按上下半），并 `preventDefault` 掉 Chromium 那套"落进隐藏源码"的解析。带修饰键或 `detail>1` 不接管。
4. `boundaryNode` 改成返回 `{owner,hop,hint}`：`hop` 只对"看不见的位置"为真（挪光标），看得见的位置原地不动；新增 `nearBlockOf`（沿祖先链找相邻块公式）与 `layer:'fence'`/`'preview'` 两个分支。
5. `fenceCaret()` + `beforeinput`/`paste`/`compositionstart`：围栏上的文字输入一律先进源码的对应一端（`execCommand('insertText')`），围栏与 markdown 都不会被写坏。
6. `recoverMarkerInput` 扩到块公式（`$$` 标记绝不持有游离字符）。
7. `enforce`（MutationObserver）：光标站在围栏上时也算"正在编辑这条公式"，不收回展开类。
8. 新增 `mathHint()`（复用既有 `.typora-context-toast` 样式，2.6s）：围栏上退格 → `FENCE_HINT`；紧贴公式块退格 → `BOUNDARY_HINT`。
